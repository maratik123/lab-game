# Project context — lab-game

## Purpose

A **Telegram bot game** (working title «Лабиринты»): adding the bot to a group chat gives that chat a *home* in a shared, infinite, procedurally generated hex maze. Players issue commands in DM with the bot; the group chat receives only rare, status-worthy notifications. The chat is a collective entity — shared buildings, shared reputation, shared map knowledge.

The canonical, finalized specification is **[`docs/DESIGN.md`](../docs/DESIGN.md)** (Russian) — read it for anything non-obvious about the world, raids, combat, economy, PvP, seasons, or infrastructure. Its idea backlog is **[`docs/IDEAS.md`](../docs/IDEAS.md)**, which is *not* a source of implementable behaviour (`AGENTS.md` § Project carries the AXIOM). This file is the short orientation; the design document is the source of truth.

## The positioning that decides ties

> **The unit of acquisition is a chat, not a player.** When two designs compete, the one that strengthens *chat-as-an-entity* wins (shared map, doors as infrastructure, walking newcomers in, chat legends in notifications) over the one that strengthens an individual.

The mechanics are deliberately conventional (stamina, auto-combat, seasons, an extraction loop) so players understand the rules immediately. What is novel is the combination, not the bricks.

## Load-bearing invariants worth knowing before touching a block

- **The maze is a pure function of its seed.** Cell content and its edges are `f(world_seed, coord)`; a cell materialises in the database on first visit; connectivity is guaranteed *by construction* (per-chunk spanning structure + 1–2 generated portals per chunk border), never repaired after the fact. Rotation of a season = a new `world_seed` (`docs/DESIGN.md` §2.2.2).
- **Edges are not stored.** Passages and walls are derived from `f()`; the canonical face representation makes both sides of a border agree by construction (§2.2.4).
- **Danger is a property of space, not of the observer.** Depth = distance to the nearest *chat entrance* (crafted doors do not count). PvP tier, monster budget, wave multiplier and newcomer XP all hang off that one axis (§2.2).
- **A raid session is a row, not a process.** An explicit FSM in Postgres: player actions and timers are edges of the same kind, every transition is a guarded transaction plus a basis document, and timer edges are one-shot scheduler tasks that die on a stale guard. Bot restarts are invisible to sessions (§3.5).
- **Combat is a pure function** `combat(seed, party, monsters) → outcome + log`. Nothing outside sees its internals; the combat-system version is part of every stored log and PvP-trail snapshot, which is what buys the freedom to rewrite it wholesale (§4).
- **Every balance change is a ledger posting.** Double-entry with a global "World" account, zero-sum per kind inside each transaction, checked at write time in `store.Post`; instance-carrying items live in a second machine with an unbroken chain of holders. All game logistics — death, looting, contributions, corpse evaporation — are one "move under a document" operation over those machines (§11, and [`domain-invariants.md`](domain-invariants.md)).
- **Lazy ticks, no cron.** Stamina, corpse evaporation and respawn are computed from timestamps at read time; the single exception is the Postgres-backed scheduler that drives raid-session timer edges, notifications and day-close (§11).

## Architecture

The design document defines the blocks; the Go package layout lands one implementation spec at a time, never by assumption. **Layout so far:** `internal/store` — the ledger's write path (owner/scope/account catalog, forward migrations under `internal/store/migrations`, `store.Post`) and the product event log (the `event` table, its §13.4 type registry, the write API, and the `metric_*` SQL views a product dashboard reads); `internal/testdb` — PostgreSQL provisioning for the whole suite (a `postgres:18` container or `LAB_GAME_TEST_DSN`, one schema per test), exported as an API that `cmd/testpg` imports as well as the `_test.go` files that call `Main` and `Schema`: `make test`, `make test-race` and the coverage ratchet each run their test invocation through that wrapper, so one run shares **one** server instead of starting a container per database-backed test binary, and the per-binary path survives as the fallback a bare `go test ./...` still takes; `internal/repotest` — the module's one repository-root resolver for tests (`Root`, `RootPath`), into which every per-package copy was folded and then deleted; `internal/config` — the start-up configuration layer (the `LAB_GAME_` environment set, the tracked balance YAML, the world-set path), which `cmd/bot` loads and validates before any other work; `internal/tg` — the Bot API transport over `telego`'s low-level layer (the caller with retries and exact `retry_after`, the window-schedule rate limiter, the `Gate` seam `internal/ingest` installs its allowlist into (#22), the observation point `internal/health` reads), with `internal/tgtest` as its in-process fake Bot API server; `internal/scheduler` — the Postgres-backed task scheduler over the `scheduled_task` table (the handler registry with its one-shot and recurrent declarations, the worker's claim/execute/settle cycle and its per-task deadline, the start-up reconciler that seeds and corrects recurrences, the `process_liveness` singleton whose start-up shift absorbs an outage and whose heartbeat keeps the instant fresh, the `Stop` seam that ends a cycle without aborting the work inside it, and the observation seam `internal/health` reads), which ships no production handler; `internal/backoff` — the one exponential ramp (`Exponential`, `EqualJitter`) that `internal/tg`, `internal/scheduler` and `internal/ingest` all call, both private copies deleted rather than left standing beside it, its growth factor read from each adopter's own configuration over the shared `DefaultFactor` / `ValidFactor` pair rather than compiled into the arithmetic; `internal/ingest` — update ingestion over the transport (the long-polling loop with its always-transmitted `allowed_updates`, the 26-row update-kind table and the router, the `ingest_offset` row whose guarded advance rides the handler's own transaction, one transaction per attempt with retries and the `ingest_dead_update` give-up row, the unexported `operation_id` grammar a handler cannot forge, the `ALLOWED_CHAT_IDS`-plus-player outbound gate, and the observation seam `internal/health` reads), which registers no route — a production handler and a route alike arrive with their own mechanic; `internal/health` — the health surface (an explicitly-constructed Prometheus registry with no global default registerer, one adapter per consumer-declared observation seam, the pgx pool collector read at scrape time rather than from a cached snapshot, the `/metrics` server with the `/readyz` path beside it, the process-identity collector carrying the build version, the start instant, readiness and the restart gauges, and the two-leg `getMe` canary whose legs each carry their own client and limiter so a probe draws on no production budget), whose alert shapes are fixed in [`alert-contract.md`](alert-contract.md) and whose numbers are not; `internal/srcguard` — the shared source-walk support every structural guard in the module parses its own package's files through, taking the repository root as an argument rather than ascending to it; `internal/leaktest` — the goroutine-leak check every test binary ends with (`Main`, wrapping whatever owned the entry point, and the `Ignore` entry with its stated reason), over `go.uber.org/goleak`, together with the guard that fails the suite when a package with tests does not run it. Under `cmd/`: `cmd/bot` is the composition root — it assembles every block above in one written, all-fatal, unwinding order, serves `/metrics` and `/readyz`, applies the migration policy, and drains on a signal ([`process-lifecycle.md`](process-lifecycle.md)) — beside `cmd/testpg`, `cmd/commentrefs` and `cmd/importguard`, the gate that keeps the bot's non-test dependency graph free of the container runtime. The blocks the layout has to house:

| Block | Responsibility | Design ref |
|---|---|---|
| Transport | Bot API client over a self-hosted `telegram-bot-api`, retries, 429/`retry_after`, rate limits, idempotency of updates | §11, §12.2 |
| World | Deterministic chunked generation, prefabs, materialisation, discovery/knowledge | §2.2 |
| Raid | Session FSM, leader screen (one edited message), stamina, standing-timer escalation | §3, §5 |
| Combat | Pure simulator + narrative rendering from the world's vocabulary | §4 |
| Economy | Double-entry ledger (`internal/store`), item machine, logistics addresses, shop/craft | §6, §11 |
| Scheduler | `scheduled_task` worker (`FOR NO KEY UPDATE SKIP LOCKED`), one transaction per task with its effects | §11 |
| Notifications | Outbound queue with a rate limiter; the notification budget is a design obligation | §1, §13.3 |
| Observability | `event` log (product) + Prometheus metrics and canaries (health) | §13 |

the product event log — `internal/store`'s append-only `event` table, the `event_type_definition` registry seeded from §13.4 with each type's volume class, `Event` as a posting basis alongside `AppendEvent` for the no-posting path, and the `metric_*` views (activation funnel, retention, deaths by depth, faucet/sink, notifications per chat per day), which nothing emits into yet — each mechanic declares and emits its own events in its own PR (§13.4); update ingestion — `internal/ingest` (the long-polling loop over `internal/tg`, the 26-row update-kind table and the router, the `ingest_offset` / `ingest_dead_update` migration, the guarded offset advance inside the handler's own transaction, one transaction per attempt with retries and give-up, the `operation_id` grammar, the `ALLOWED_CHAT_IDS`-plus-player outbound gate and the observation seam) with its `LAB_GAME_INGEST_*` tuning keys, over the new shared `internal/backoff` ramp that `internal/tg` and `internal/scheduler` now call in place of their own deleted copies; the health surface — `internal/health` (the explicit Prometheus registry, the transport / scheduler / ingest observation adapters, the pgx pool collector, the `/metrics` server, and the two-leg `getMe` canary on its own in-process ticker, independent of Postgres and of the scheduler) with its `LAB_GAME_HEALTH_*` tuning keys and the alert shapes recorded in [`alert-contract.md`](alert-contract.md), alongside `internal/repotest`, into which the module's per-package repository-root resolvers were folded. And the composition root itself — `cmd/bot` now assembles every one of them: a fourteen-step, all-fatal, unwinding start-up order (signals first, then configuration, the pool, readiness, the registry, the listener, migrations under a database-wide advisory lock, restart hygiene, the scheduler, the client with its gate, the loop, the canary, the runners), `/readyz` beside `/metrics`, a `migrate` subcommand that applies and exits, a link-time build version, and a signal-driven drain bounded by one budget — with its `LAB_GAME_PROCESS_*` tuning keys and its contract written down in [`process-lifecycle.md`](process-lifecycle.md). What is still empty is deliberate: the ingest router registers no route and the scheduler registry declares no task, so the assembled process polls, claims and heartbeats but runs no gameplay — a production handler and a route arrive with their own mechanic (the raid timer edges (#36), corpse evaporation (#40), the day close (#45)), and the outbound queue is still #43's. MVP scope is `docs/DESIGN.md` §14.
- **Gates:** one entry point — `make verify` runs the whole gate list, and CI invokes the same sub-targets, so hook, CI and a local run cannot disagree. Format gate is `golangci-lint fmt -d` (gofumpt included); file size is gated at 1000 / 1500 lines; `make comment-refs` refuses a comment that points outside itself, over `*.go`, `*.sh`, `*.sql`, `*.yml`, `*.yaml`, `.gitignore`, `.env.example`, `Makefile` and `.githooks/**`. `make import-guard` refuses a forbidden module in the non-test dependency graph of a package the rule table names — today, the container runtime in the bot's. Every test binary ends with a goroutine-leak check (`internal/leaktest` over goleak), wired into each package's `TestMain`, and a guard fails the suite when a package with tests does not run it — so every route that runs the tests runs the check. The pre-commit hook is a symbolic link to a dispatcher that runs the reference gate over the staged set and then the coverage ratchet. In CI each test gate — the suite, the race gate, the coverage ratchet, the fallback path — runs as its own job rather than as a step of one shared job, so a run costs the slowest of them instead of their sum, and a red gate no longer stops the others from reporting. Per-task detail: [`context-status.md`](context-status.md).
- **Harness:** being ported from the `graphite-gp` project (which in turn evolved it from `quartzite`), adapted to Go and to this domain.
- **Repository:** `maratik123/lab-game`, private, default branch `main`. No server-side branch protection — see `AGENTS.md` § Permissions.
