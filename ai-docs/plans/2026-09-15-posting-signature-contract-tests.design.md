# Design: Posting-signature contract tests

**Issue:** #26
**Date:** 2026-09-15

## Approach

A new package, `internal/contract`, holds three things: the vocabulary a signature is declared in, the declared set as one Go table literal, and the contract check. Only tests import it, so the bot binary does not carry it `[derived → subtask 6 verification: go list -deps ./cmd/bot lists no internal/contract]`. A balance-moving mechanic adds its type's row to the declared set, and calls the check from its own contract test, in its own pull request (spec Out of scope, first row). The migrated-schema pool the tests stand on comes from a second new test-support package, `internal/storetest` (D13). On the owner's word, the scheduler, ingest and bot test suites take their pool from it too (D14).

**Round 3: what the amended spec removed.** The owner narrowed the task (spec Key decisions row 2, answer 3.2). There is no completeness gate over every existing type, no explicitly empty signature, and no player-operation signature. The following go with them:
- the catalog audit;
- the `cmd/bot` task-type list;
- the scheduler accessor;
- the assembly-test rewrite.

D9 is withdrawn. Every other decision drops the parts that served the gate, and the acceptance criteria are renumbered to the amended spec.

**Round 5: the owner's answer on the pool helper copies.** The owner chose to move the scheduler, ingest and bot suites onto `storetest.Pool`. D14 records the move with the owner's words. The move is the new subtask 2, so the former subtasks 2–6 are now 3–7. The spec is unchanged.

A type with no row now meets the check itself: a write under it fails (spec Scope 3, AC6). The check does not ask whether a balance-moving mechanic declared a signature and ships a contract test at all. The review checklists do:

**What exists to build on.**
- **Basis tables.** A journal entry references exactly one basis document. Its arc columns:
  - `player_operation_id` and `manual_correction_id` `[measured f87c044:internal/store/migrations/00001_ledger_core.sql:67-73 · sed -n 15,90p → CONSTRAINT journal_entry_exactly_one_basis CHECK (num_nonnulls(player_operation_id, manual_correction_id) = 1)]`;
  - `deferred_task_id` and `recurrent_task_id` `[measured f87c044:internal/store/migrations/00002_scheduler.sql:38-44 · sed -n 21,46p → ADD COLUMN deferred_task_id … ADD COLUMN recurrent_task_id]`;
  - `event_id` `[measured f87c044:internal/store/migrations/00003_event_log.sql:71-76 · sed -n 60,80p → num_nonnulls(player_operation_id, manual_correction_id, deferred_task_id, recurrent_task_id, event_id) = 1]`.
- **Types within those tables.**
  - An event's type is a row of `event_type_definition` `[measured f87c044:internal/store/migrations/00003_event_log.sql:14-36 · sed -n 14,40p → CREATE TABLE event_type_definition … ('bot_added_to_chat' … 'bot_kicked')]`. The store mirrors each row as a constant `[measured f87c044:internal/store/catalog.go:73-74 · grep -n 'EventType = "' → EventShopSale EventType = "shop_sale", EventShopPurchase EventType = "shop_purchase"]`.
  - A task type is text in each task basis table `[measured f87c044:internal/store/migrations/00002_scheduler.sql:21-36 · sed -n 21,46p → CREATE TABLE deferred_task (… task_type text NOT NULL …), CREATE TABLE recurrent_task (… task_type text NOT NULL …)]`. The store's task bases carry it as a string `[measured f87c044:internal/store/basis.go:104-109,140-145 · Read → type DeferredTask struct { TaskID int64; TaskType string; … } / type RecurrentTask struct { TaskID int64; TaskType string; … }]`.
  - The player operation has no type column `[measured f87c044:internal/store/migrations/00001_ledger_core.sql:53-59 · sed -n 53,59p → CREATE TABLE player_operation (id …, source operation_source NOT NULL, operation_id text NOT NULL, created_at …)]`.
- **Postings.** A posting row carries its journal entry, its account and a non-zero amount `[measured f87c044:internal/store/migrations/00001_ledger_core.sql:78-84 · sed -n 15,90p → posting (journal_entry_id, account_id, amount) … CHECK (amount <> 0)]`. An account definition is unique per scope definition and code, and it carries the kind `[measured f87c044:internal/store/migrations/00001_ledger_core.sql:20-27 · sed -n 15,90p → account_definition (scope_definition_id, code, kind, controlled) … UNIQUE (scope_definition_id, code)]`.
- **Item movements.** A movement references its journal entry and two holder scopes `[measured f87c044:internal/store/migrations/00007_item_machine.sql:107-120 · grep -n -A 16 'CREATE TABLE item_movement' → item_movement (item_id, prev_movement_id, from_holder_id REFERENCES scope, to_holder_id REFERENCES scope, journal_entry_id)]`.
- **Every write path leaves at least one posting.**
  - `store.Post` refuses an empty batch `[measured f87c044:internal/store/post.go:102 · grep -n ErrEmptyBatch → return ErrEmptyBatch]`.
  - `store.Move` refuses an empty movement list `[measured f87c044:internal/store/move.go:88-89 · sed -n 86,130p → if len(movements) == 0 { return nil, ErrNoMovements }]`, and it posts capacity legs for every movement `[measured f87c044:internal/store/move.go:204-214 · sed -n 200,220p → from.free +1, from.used −1, to.free −1, to.used +1]`.
- **Nothing in production writes under any basis today.**
  - The write-call grep finds only the definitions `[measured f87c044:internal/store/post.go:77, internal/store/move.go:86, internal/store/event.go:88 · git grep -n -E '(Post|Move|AppendEvent)\(ctx' -- '*.go' ':!*_test.go' → func Post / func Move / func AppendEvent only]`. - **The design corpus.** §11 gives signature examples (`craft_succeeded`, `shop_sale`, the manual correction) and calls the structural comparison the economy's contract test `[measured ~/lab-private@48f7c2e:DESIGN.md:331 · grep -n 'Проводочные сигнатуры по типу документа' → «у каждого типа основания — ожидаемый набор проводок (craft_succeeded: списания ресурсов + зачисление предмета; shop_sale: ресурс↔деньги; ручная коррекция: любая сбалансированная пачка). ### Key decisions

| # | Decision | Why / rejected alternatives |
|---|---|---|
| D1 | **A new package, `internal/contract`, imported only by tests.** Exported surface: <br>• `DocumentType`, with the constructors `ManualCorrection`, `Event`, `DeferredTask` and `RecurrentTask`; <br>• the `Signature` forms `AnyBalanced` and `Expect`; <br>• the `Leg` constructors `PostingLeg` and `MovementLeg`; <br>• `Sign` (`Positive`, `Negative`); <br>• `Cardinality` (`Exactly`, `AtLeast`); <br>• `Declaration`, `Registry`, `NewRegistry` and `Declared`; <br>• `Queryer`, `Mark`, `NewMark` and `(Registry).Check`; <br>• the sentinels `ErrInvalidDeclaration`, `ErrNonconforming`, `ErrNoDocument` and `ErrNoSignature`. <br>The sentinels use the `"contract: …"` form the store's sentinels use `[measured b4b1240:internal/store/errors.go:11 · sed -n 1,20p → ErrNoBasis = errors.New("store: posting basis is nil")]`. | **The name.** The design corpus's own word is «контрактный тест», and `contract.Signature` does not stutter. `internal/signature` would force `signature.Signature` `[measured f87c044:ai-docs/go-api-naming.md:21 · sed -n 19,23p → "No stutter. … The package name is part of the identifier at the call site."]`. <br><br>**Not `internal/store`.** Every mechanic's pull request would edit the ledger package to declare its signature, and the binary would carry the read-back path, which is test support. <br><br>**Not a `_test.go` helper in each package.** The mechanic issues that depend on #26 each call the check from their own package, which makes it a shared package by the ≥3-site rule. In the MVP roadmap's dependency table, the rows of #31, #36, #40, #41 and #45 list #26 (https://github.com/maratik123/lab-game/issues/47, read this turn: `gh issue view 47 --json body --jq .body \| grep -n '#26'`). <br><br>**Import gate.** The gate's only rule forbids the container runtime under `cmd/bot` `[measured f87c044:cmd/importguard/run.go:37-44 · sed -n 36,46p → Package: ".../cmd/bot", ForbiddenPrefixes: testcontainers-go]`. A test-only import never enters that graph `[derived → subtask 6 verification: go list -deps ./cmd/bot lists no internal/contract]`. |
| D2 | **A basis-document type is an opaque, comparable `DocumentType`**, with an unexported basis and code. <br><br>The bases are `manual_correction`, `event`, `deferred_task`, `recurrent_task` and `player_operation`. <br><br>The constructors mirror the store's basis types: `ManualCorrection()`, `Event(store.EventType)`, `DeferredTask(code string)` and `RecurrentTask(code string)`. The manual correction is a whole-table type with an empty code. <br><br>**The player operation has no constructor.** `Check` gives a player-operation entry the type `player_operation`, and `NewRegistry` refuses a declaration under that basis. <br><br>`String()` renders `event/shop_sale`, `deferred_task/<code>`, `manual_correction` or `player_operation`. | **Signature carriers are the types spec Scope 4 names:** each event type, each task type, and the manual correction. The player operation has no type within its table (measured above), and a whole-table signature for it is out of scope (spec Out of scope, third row). A write under a player operation therefore always fails the check with `ErrNoSignature`, which is AC6 for that basis. The first mechanic that writes under a player operation introduces a type within that table, and adds the constructor in its own pull request. <br><br>**Unexported fields**, so the only declarable types are the ones the constructors make. The zero `DocumentType` is refused as an unknown basis. <br><br>**Task codes are strings**, because the store's task bases carry them as strings (measured above). `contract` does not import `scheduler`. <br><br>**The two task tables stay separate keys.** The check reads an entry's type from the table the entry references, with no merge rule. A mechanic's test reads `contract.DeferredTask("x")` beside the `&store.DeferredTask{TaskType: "x"}` it wrote. A declaration under the other table leaves `want` with no entry, so the mechanic's own test fails with `ErrNoDocument` rather than passing. |
| D3 | **A signature takes one of two forms, `AnyBalanced` or `Expect`, and the zero `Signature` is neither.** <br>• `AnyBalanced()` admits any postings that sum to zero per kind, and any movements. <br>• `Expect(legs ...Leg)` admits exactly the declared legs. <br><br>`NewRegistry` refuses: <br>• the zero `Signature`; <br>• `Expect` with no legs; <br>• `AnyBalanced` on any type other than `ManualCorrection()`. <br><br>`Registry`'s fields are unexported and `NewRegistry` is its only constructor, so no one can build a registry that loosens another type. | **There is no empty form.** Every write path leaves at least one posting (measured above), so an empty signature could only ever fail. The one use it had was a type no mechanic writes under, and the owner struck that (spec Key decisions row 2). A type therefore has an `Expect` row, an `AnyBalanced` row, or no row, and a forgotten row cannot pass for a declared one. <br><br>**The permissive form is confined when the registry is built**, which makes AC7 structural. The check never meets `AnyBalanced` under another basis, so it carries no second guard. Such a guard would be dead code, and an uncovered branch against the ratchet. |
| D4 | **Legs and matching.** <br><br>A posting leg is `(scope definition code, account definition code, kind, sign, cardinality)`. An actual posting's key `(scope code, account code, kind, sign)` is read along posting → account → account definition → scope definition, with the sign of its amount. <br><br>A movement leg is `(from scope definition code, to scope definition code, cardinality)`. An actual movement's key comes from its two holder scopes. <br><br>A document conforms to `Expect` when both hold: <br>• for every declared leg, the count of actual rows with its key satisfies its cardinality; <br>• no actual row has a key that no leg declares. <br><br>Leg keys are unique within one signature; `NewRegistry` refuses a duplicate. | **Amounts are not in a signature.** They are balance numbers, and the corpus asks for a *structural* comparison. <br><br>**Owner identity is not in a leg.** Two players' `attributes/money` postings match one leg, and the cardinality counts them. <br><br>**Kind is declared even though the account definition determines it**, because spec Scope 1 lists it. `contract` reads no catalog. A leg whose codes or kind disagree with the migrated catalog never matches, so the mechanic's own contract test fails on it with the mismatch pair D11 defines. The check is its own drift detector. <br><br>**The capacity legs `store.Move` derives are ordinary postings, declared explicitly** (measured above). The check derives nothing from movements: a checker that re-derived Move's legs would pass a Move defect by construction. |
| D5 | **Cardinality is `Exactly(n)` or `AtLeast(n)`, with `n ≥ 1`.** `NewRegistry` refuses `n < 1`. A leg that may be absent is simply not declared. | `AtLeast` exists because the corpus's first example, «списания ресурсов», debits as many resources as a recipe names (§11, measured above). An upper-bounded range has no example, so it is not built. |
| D6 | **"The transaction" is every journal entry past a mark.** `NewMark(ctx, q)` reads the greatest `journal_entry.id` visible to `q`, and gives **the zero mark when no entry is visible**. `(Registry).Check(ctx, q, mark, want)` then judges every journal entry visible to `q` with a greater id: <br>• if `want` has no row, it fails with `ErrNoSignature` before reading anything; <br>• if none of the entries has type `want`, it fails with `ErrNoDocument`, so a mechanic that wrote nothing cannot pass vacuously; <br>• it judges each entry, of `want` or of any other type, by the signature of **its own** type, read from the document (AC5): `event.type`, `deferred_task.task_type` or `recurrent_task.task_type`, and the table alone for `manual_correction` and `player_operation`; <br>• it fails with `ErrNoSignature` for an entry whose type has no row (AC6), including every player-operation entry, and an entry that references none of the basis tables `contract` knows, which is what a later migration's new arc column produces; <br>• it fails with `ErrNonconforming` for any mismatch. <br><br>**The returned error joins one wrap per class present** (`errors.Join`). `errors.Is` then matches every class the window holds, and each wrap names its entries by id and type, together with their mismatches. <br><br>`Check`'s doc comment states two things. The precondition: no other writer adds journal entries to the schema between `NewMark` and `Check`. And that `ErrNonconforming` also covers a document whose postings do not sum to zero per kind (D7), which only a write that bypasses the write path, such as raw SQL, can produce. | **The zero mark on an empty journal.** An empty journal is reachable by a mechanic test that needs no funding: the migrations seed no journal entry or posting `[measured b4b1240:internal/store/migrations/ · rg -n -i 'INSERT INTO (journal_entry\|posting)' → no output, exit 1; control line 'INSERT INTO journal_entry (x) VALUES (1);' → 1]`, and creating a player writes none `[measured b4b1240:internal/store/owner.go · grep -n -i -E 'journal_entry\|Post\(\|INSERT INTO' → INSERT INTO owner / scope / account / account_balance only]`. A mark read as NULL would fail loudly, because pgx refuses NULL into an integer `[measured github.com/jackc/pgx/v5@v5.10.0:pgtype/int.go:303 · grep -n 'cannot scan NULL' → return fmt.Errorf("cannot scan NULL into %T", dst)]`. The zero mark admits every entry, because every id is ≥ 1. The column is an identity with no sequence options `[measured b4b1240:internal/store/migrations/00001_ledger_core.sql:68 · sed -n 66,70p → id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY]`, and an ascending sequence starts at its minimum, which defaults to 1 (https://www.postgresql.org/docs/18/sql-createsequence.html, read this turn: «The default for an ascending sequence is 1.» and «The default starting value is minvalue for ascending sequences»). `[derived → TestNewMark_emptyJournal]` <br><br>**Rejected (a): returning the journal-entry id from the write paths.** Neither returns one today `[measured f87c044:internal/store/post.go:77 · grep -n '^func Post(' → func Post(…) error]` `[measured f87c044:internal/store/move.go:86 · grep -n '^func Move(' → func Move(…) ([]ItemID, error)]`. Changing both for a test's benefit would still leave a scheduler-run handler's entry out of its test's reach. <br><br>**Rejected (b): filtering on `xmin` equal to the current transaction id.** A handler runs under a savepoint `[measured f87c044:internal/scheduler/execute.go:342 · grep -n SAVEPOINT → tx.Exec(ctx, "SAVEPOINT handler")]`, and a subtransaction that writes gets an id of its own (https://www.postgresql.org/docs/18/subxacts.html, read this turn: «Read-only subtransactions are not assigned subxids, but once they attempt to write, they will be assigned one.»). Which id a row's `xmin` then carries is row-header behaviour this design would have to prove before any task mechanic could rely on it. The mark needs no such proof. <br><br>**Rejected (c): judging every entry in the schema.** A test's fixture funding would be judged as the code under test `[measured f87c044:internal/store/post_test.go:57-77 · sed -n 55,80p → "fund posts a ManualCorrection crediting accountID …"]`. <br><br>**The precondition is met by construction**, because each test takes its own schema `[measured f87c044:internal/testdb/testdb.go:76-80 · grep -n 'func Schema' → "Schema creates a uniquely named schema on the provisioned server …" func Schema(tb testing.TB) *pgxpool.Config]`. <br><br>**Gaps in identity values are harmless**, because the mark is the greatest *visible* id, not a sequence position. `journal_entry.id` is an identity column (measured above). An identity column draws from a sequence (https://www.postgresql.org/docs/18/sql-createtable.html, read this turn: «It will have an implicit sequence attached to it and in newly-inserted rows the column will automatically have values from the sequence assigned to it.»), and a sequence has gaps by design (https://www.postgresql.org/docs/18/functions-sequence.html, read this turn: «This means that transaction aborts or database crashes can result in gaps in the sequence of assigned values.»). <br><br>**Later entries carry larger ids** within one schema that has no concurrent writer `[derived → TestCheck_ignoresEntriesBeforeMark]`. <br><br>**A joined error rather than a first-found one**, so a test can assert that a class did *not* fire. An `ErrNoSignature` entry cannot mask an `ErrNonconforming` one in the same window `[derived → TestCheck_joinsEveryClass]`. |
| D7 | **Every document past the mark is also checked for a zero sum per kind**, the same predicate the write path enforces. A failure reports as an `unbalanced` mismatch (D11). | This is what makes `AnyBalanced` mean *balanced* rather than *anything* (spec Scope 5, 6). For `Expect` the check is redundant, and it costs one pass over rows already read. |
| D8 | **The declared set is one slice literal in `internal/contract/declared.go`**, and `Declared()` returns `NewRegistry(declarations...)`. The literal follows these rules: <br>• one element per declared type; <br>• every leg is spelled with catalog codes, a named sign and a named cardinality; <br>• **each leg on its own line**, never two legs on one line; <br>• no loop, helper or computed leg; <br>• the order is the manual correction, then event types in the event-log migration's declaration order, then deferred-task and recurrent-task types by code. <br><br>A signature change is therefore a changed line of its own that names the account, kind, sign or cardinality that changed (AC9). | **One leg per line** is what makes a one-leg change a one-line diff. A signature written as a single `Expect(PostingLeg(…), PostingLeg(…))` line would show the whole signature changed when one sign moved `[derived → Step 9 AC9 measurement, step 3]`. <br><br>**One registry, not one per mechanic package.** `Check` judges every entry past the mark by its own type, so the registry a mechanic's test passes must hold every type the operation writes under, not only the mechanic's own. The manual correction's row (spec Scope 5) then exists once, instead of being copied into every mechanic's test. <br><br>**Rejected: a YAML or JSON file.** It needs a loader and a parser this project would own. Its values are type-checked only at load, and its diff is no more readable than a gofumpt'd literal. <br><br>**Rejected: a SQL table seeded by migration.** A signature is a test contract, not live data. A forward-only migration would turn every signature edit into an INSERT/DELETE delta rather than the signature itself, and would put a test-only fact into the production schema. |
| D9 | **Withdrawn in round 3.** The completeness audit served only the gate the owner removed (spec Out of scope, third row; Key decisions row 2). That covers the catalog read, the task-type list in `cmd/bot`, `scheduler.Registry.Declarations` and the `TestAssemble_HappyPath` rewrite. The row number is kept so that earlier review notes citing D10–D12 still resolve. | The amended spec does not ask whether every type has a row, and AC6 is met by the check at the moment of the write. No non-test path in `internal/scheduler` or `cmd/bot` is touched; their test files change only for the pool move D14 records `[derived → subtask 6 verification: git diff --name-only main... lists no internal/scheduler or cmd/bot path that is not a _test.go file]`. |
| D10 | **The declared set on the merged tree** is `ManualCorrection()` → `AnyBalanced()` alone (spec Scope 5). | No event-type or task-type row exists, for two reasons. No production code writes under any type (the grep in § Approach). And the row a mechanic needs ships with that mechanic (spec Out of scope, first row). |
| D11 | **The matcher is an unexported pure function, and `Check` is a thin read around it.** `conform(sig, doc)` returns sorted mismatches. `Check` loads the documents, the postings and the movements past the mark with one query each, and **runs every read before it judges any entry**. <br><br>A mismatch carries a class and a key: <br>• `cardinality`: a declared leg's key, with the count wanted and the count found; <br>• `unexpected`: an actual row's key that no leg declares, with its count; <br>• `unbalanced`: a kind whose postings do not sum to zero (D7). <br><br>A row that differs from a declared leg in one key dimension (account definition, kind or sign) therefore reports a pair: `cardinality` on the declared key and `unexpected` on the actual key. The dimension is the one field in which the two keys differ, and the rendered `ErrNonconforming` message prints both keys whole. | **Every AC2 dimension is testable without a database**, the kind-only one included. A kind-only difference cannot occur in a real row, because `(scope_definition_id, code)` determines the kind (`00001_ledger_core.sql:20-27`, measured above). The database-error branches stay few, which the coverage ratchet needs. <br><br>**Reads before judgement** make every read's failure reachable while the reads before it return no rows, which is what lets a fake `Queryer` drive each read's error returns `[derived → TestReads_returnEveryError]`. The cost is the reads a window with no document of type `want` would not otherwise need. <br><br>**Classes make each check separately observable.** A test asserts which check fired, so a broken cardinality comparison, or a skipped unexpected-row pass, cannot hide behind an `unbalanced` entry the same document also produces. |
| D12 | **Totality without panics.** <br><br>Every switch over the basis and over the signature form names every member and returns an error from its default arm. `NewRegistry`'s `player_operation` arm refuses with `ErrInvalidDeclaration`. <br><br>`NewRegistry` and `Declared` return errors, and no `Must…` exists. | **The explicit cases are this design's choice, not the linter's.** `exhaustive` runs with `default-signifies-exhaustive: true` `[measured f87c044:.golangci.yml:44-45 · grep -n -A2 'exhaustive:' → exhaustive: default-signifies-exhaustive: true]`, so the linter alone would accept a default arm that hides a missing member. <br><br>**No panics.** The project holds zero production panics `[measured f87c044:ai-docs/panic-index.md:5 · sed -n 1,8p → "The project targets zero production panics and currently holds it"]`. <br><br>**The precedent is `scheduler.NewRegistry`**, which returns errors `[measured f87c044:internal/scheduler/registry.go:45-69 · grep -n -E 'func NewRegistry\|ErrInvalidDeclaration' → "Every refusal wraps ErrInvalidDeclaration and names the offending type."]`. |

## Risks

- **A shared schema breaks `Check`'s precondition and can yield a false pass.** If another writer commits a conforming document of type `want` between `NewMark` and `Check`, a mechanic that wrote nothing passes. Mitigation: the precondition is in `Check`'s doc comment, and every test takes its own schema (D6, measured). The failure mode is named so that a mechanic's concurrency test does not reach for `Check` — `[derived → Check doc comment; TestCheck_noDocumentOfWantedType]`.
