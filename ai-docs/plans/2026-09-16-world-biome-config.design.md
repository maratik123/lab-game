# Design: World and biome config: generation inputs, lexicon, bestiary

**Issue:** #28
**Date:** 2026-09-16

## Approach

The world set stops being a path the loader only probes and becomes a decoded source. `internal/config` already owns a YAML **node-tree** loader, and the reason it owns one binds this task harder than it bound the balance file: no key may have a compiled-in fallback, and a struct binder cannot separate "the key was absent" from "the operator wrote 0" `[measured f5a5963:ai-docs/key-decisions.md:61 · Read → KD-22 "any binder that decodes straight into a Go value cannot separate …"]`. In a world file `k: 0` and `seed: 0` are both *authored* values — k = 0 is the concentric-ring packing the corpus names `[measured ~/lab-private@48f7c2e:DESIGN.md § 2.2 · `git -C ~/lab-private show 48f7c2e:DESIGN.md | grep -n 'k = 0'` → «k = 0 — концентрические кольца от центра»]` — so an absent key that decodes to zero would be a silently valid world. The world set therefore rides the same walker, in the same package, into the same `*KeyError` vocabulary, and reaches the process as a new field on `Config`.

Everything the generation half needs already exists and is already reachable from this package. `maze.Params` carries exactly the inputs the spec enumerates and says so: "It carries no seed — the seed is New's own argument — and fixes no configuration key name; mapping a biome file onto Params is the composition root's concern" `[measured f5a5963:internal/maze/params.go:18-32 · Read → Params{Radius, Weights, IslandShare, ExtraPassageShare, GrowingTreeBias, PortalShareLower, PortalShareUpper}]`. `maze.MinRadius` is the radius bound `[measured f5a5963:internal/maze/params.go:12-16 · Read → "const MinRadius = 6"; "There is no upper bound"]`, `maze.AlgorithmWeights` is the weight set indexed by `Algorithm` `[measured f5a5963:internal/maze/algorithm.go:44-50 · Read → "AlgorithmWeights is the per-algorithm weight set … indexed by Algorithm's own value"]`, and `internal/config` already imports `internal/maze` `[measured f5a5963:internal/config/balance_load.go:13 · Read → import "github.com/maratik123/lab-game/internal/maze"]`. `gate.Next` takes k as an `int` and refuses a negative one `[measured f5a5963:internal/gate/next.go:8,16-19 · Read → doc "k < 0 returns ErrNegativeK"; func Next(created, gates []hexgrid.Chunk, k int)]`.

The balance side gives the chunk radius up, the ledger gains the MVP biome's resource kinds by a forward migration, and the corpus records the promotion of the sketch the MVP world is authored from.

**On AC4's placement clause.** AC4 says the world set "reaches the process through the configuration layer". That is read here as a scope statement rather than a prescribed mechanism, and it is the issue's own wording, not the spec's origination `[measured f5a5963:ai-docs/plans/2026-09-16-world-biome-config.spec.md:34 · Read → `[task: "Tracked files, loaded through #18."]`]`. AC3's citation of the Propagation Rule is read the same way: it defines the membership of a class, which is the spec's job, and names no mechanism for reaching it. Neither is flagged.

### Key decisions

| # | Decision | Why / rejected alternatives |
|---|---|---|
| D1 | **The world format lives in `internal/config`.** The world set decodes into a new `Config` field beside `Config.Balance`; the package gains world value types, a world schema and a world-set loader. | One loader, one error vocabulary (`*KeyError` plus `ErrMissing` / `ErrUnknownKey` / `ErrInvalidValue` / `ErrUnreadable`) `[measured f5a5963:internal/config/errors.go:11-27 · Read → the sentinel declarations]`, and one start-up refusal path: `Load` already validates every source independently and joins the failures so one call reports every problem `[measured f5a5963:internal/config/config.go:85-104 · Read → "All three sources are validated independently … their failures are joined (errors.Join)"]`. **Rejected: a new `internal/world` package.** It cannot import `config`'s `KeyError` (`config` would import it), so it would mint a second error vocabulary for the same failure classes, and it would carry a second copy of the node walker. *Trigger to revisit:* when #34 and #35 need the lexicon and bestiary **types** without the loader — the types move then, and `config` keeps the file reading. **Rejected: `internal/config` importing `internal/store`** to type a resource kind — the configuration layer's own design refused pgx in this package for exactly that reason `[measured f5a5963:ai-docs/plans/done/2026-09-04-config-layer-balance-files.design.md:363 · Read → "not parsed here — store.NewPool already owns DSN parsing, and importing pgx into config would couple configuration to storage"]`. *Consequence:* KD-23's "the world set owns world content and is **not decoded by the loader at all**" is falsified and amended `[measured f5a5963:ai-docs/key-decisions.md:63 · Read → that clause]`. |
| D2 | **`LAB_GAME_WORLD_PATH` names a directory; each `*.yaml` file directly in it is one world.** `resolveWorldPath` grows from an open/close probe into the world-set loader's entry, and its regular-file branch goes. The loader fixes the decode order by sorting the file names itself, so the joined error's order is stable. A directory holding no world file is a refusal naming the variable; a subdirectory and any non-`.yaml` entry are ignored. | The shipped contract delegated this choice to this task in as many words `[measured f5a5963:config/world/.gitkeep · Read → "Issue #28 fills this directory (or repoints the variable at a single file; the loader accepts either)"]`. A world **set** is a set, and one file per world means authoring a world is adding a file rather than re-indenting a shared one. Sorting in the loader rather than relying on the directory read's own order keeps the error order a property of this code `[derived → the stable-error-order test § Test Design]`. **Rejected: keeping "a file or a directory"** — two code paths for one contract, when the single-file case is a directory holding one file. **Rejected: refusing an unknown file** — a later content layer (AC9) or a `README` would then be a start-up failure; the empty-set refusal is what catches the whole-set-missing case, and the tracked set is held by a test that loads it (D9). |
| D3 | **A world carries an explicit `id`; the file name is not the identity.** A lower_snake_case token, unique across the set — a duplicate is a refusal naming both files. | The spec puts the world identifier in telemetry as an event dimension `[measured f5a5963:ai-docs/plans/2026-09-16-world-biome-config.spec.md:65-66 · Read → "The world identifier reaches telemetry as a dimension of events #29 and the raid issues emit"]`, and #29 persists a maze's biome and seed `[measured 2026-09-16 · gh issue view 29 → "`mazes`: id, biome, world_seed, season"]`. An identifier a later migration persists is a data contract, and deriving it from a path lets a file rename silently re-key stored rows (`AGENTS.md` § API Stability carve-out). **Rejected: the file's base name** for that reason. |
| D4 | **The generation inputs decode into `maze.Params`, and `maze.New` is the single source of every cross-field refusal.** Per-key predicates in the schema name their own dotted key: the radius against `maze.MinRadius` (the constant, never a literal), each share and the bias in `[0,1]`, each weight non-negative with at least one positive, k non-negative, the seed any `int64`. The loader then calls `maze.New(seed, params)` once and discards the generator, wrapping its error into a `*KeyError` on the world's generation subtree. | The cross-field rules — a lower portal share above the upper, a lower share rounding to no portal, an upper share rounding past what a border path holds, an island target above a gate chunk's capacity — live in `Params.validate`, which is **unexported and reachable only through `New`** `[measured f5a5963:internal/maze/params.go:44-91 · Read → func (p Params) validate() error, called from New]`. **Rejected: restating those predicates in the schema** — two copies of one rule, drifting silently past `go build ./...`. **Rejected: exporting `maze.Params.Validate`** — `New` already returns exactly that error over a struct build, and `maze` carries a guard against growing entry points `[measured f5a5963:ai-docs/key-decisions.md:103 · Read → KD-38 "One guard fails the package on an exported interface type, or on an exported function or method that takes a function- or interface-typed parameter"]`. *Consequence:* a world file that loads is a world a generator can be built from, which is stronger than AC6's "the file loads" `[derived → AC6]`. |
| D5 | **Each algorithm weight is its own fixed-path schema leaf, bound beside the constant it writes.** The path's last segment is that algorithm's lower_snake_case name; the destination is the weight array's entry for `maze.AlgorithmBacktracker`, `AlgorithmKruskal`, `AlgorithmPrim`, `AlgorithmGrowingTree` or `AlgorithmWilson`. An unrecognised weight key falls out as `ErrUnknownKey` from the walker, free. | The dependency already puts name decoding on this side of the boundary: "an unknown algorithm name in a biome file is the decoder's error, on the side of the boundary that knows names", and `Algorithm.String()` renders "the same spelling a biome file's weight-set keys use" `[measured f5a5963:internal/maze/algorithm.go:19-20,44-49 · Read → both sentences]`. A fixed-path entry needs no parse function and no lookup table to drift. A test holds each entry's last segment equal to that `Algorithm`'s own `String()` `[derived → the weight-key agreement test § Test Design]`. **Rejected: exporting `maze.ParseAlgorithm`** — a second place the names live. |
| D6 | **The YAML schema machinery is lifted into a file of its own, unchanged, and gains a non-scalar leaf kind.** `schemaEntry`, `buildSchemaTree`, `walkNode`, `walkInterior`, `walkLeaf`, `pathKey`, `nodeKindName` and `checkDuplicateKeys` move out of the balance-loading file byte-for-byte; the world loader builds its own entry list over the same walk. The extension: an entry declares which YAML node kinds its binder accepts. Scalar entries keep today's refusal text, so every existing balance test passes unmodified; a sequence entry (the bestiary, a phrase list, the resource profile) and an open-map entry (the lexicon, the naming style's parts) are bound by binders of their own. | Reuse rather than a second decoder, because the absent-versus-zero property (§ Approach) is the whole reason this machinery exists. Leaving the scalar path's behaviour identical is what makes "the balance file still loads exactly as before" checkable rather than asserted: the balance suite is not touched by this subtask `[measured f5a5963:internal/config/balance_load.go:222-238 · Read → walkLeaf refuses a mapping or sequence with "must be a scalar, got %s"]`. The lift also keeps the balance-loading file from growing the world schema on top of the walker and the balance schema, against the soft file-size band the style rule names `[measured f5a5963:ai-docs/code-style.md:150-159 · Read → the four-band table; 800 "Soft: plan the split now"]`. |
| D7 | **Every mapping in a world document is closed, with two authored-key exceptions.** An unknown key is `ErrUnknownKey` naming its dotted path — except inside the lexicon's slot map and the naming style's parts map, whose keys are authored content. Both validate their keys as lower_snake_case tokens and refuse an empty phrase list. | Strictness is what turns a typo into a named refusal instead of a silently defaulted world, and it is what AC9 needs rather than what AC9 forbids: a later layer (prefab placements, the entrance prefab, boss areas, ruins, NPC outposts) **adds** its own section and its own entries and redefines nothing already stated `[derived → AC9]`. ## Handoff plan

Change-type classification, the one the configuration layer's own design fixed for exactly this file set: **code** covers the program and the build/runtime artefacts its gates read — `*.go`, `*.sql`, the tracked `config/**` data files and `.env.example`; **instructions/harness** covers the agent-facing prose rule (e) enumerates — `*.md`, `.claude/**`, `AGENTS.md`, `ai-docs/**`, and with it the design corpus' two markdown files under `~/lab-private/` `[measured f5a5963:ai-docs/plans/done/2026-09-04-config-layer-balance-files.design.md:487-491 · Read → that classification]`.

- **Entry into Group A:** spawn `/context-reset` per `.claude/skills/context-reset/SKILL.md` § Compaction recovery (re-entry).
- **Group A** — model `sonnet`, effort `medium` (pinned) via the `code-writer` subagent, 1M-token window — subtasks 1–8 (code change-type). Every code subtask is clustered into this one group, in dependency order; 1 and 2 open it with no dependency of their own, and 8 closes it because it gates what 1, 5 and 7 leave. 8 subtasks, within the size cap of 10.
- **Handoff after Group A:** spawn `/context-reset` per `.claude/skills/context-reset/SKILL.md` § Compaction recovery (re-entry). Parent `/task` resumes in Group B with fresh context.
- **Group B** — model `inherit` (the orchestrator's), effort inherited from the orchestrator (typically xHigh), via the `general-purpose` subagent, 1M-token window — subtasks 9, 10, 11 (instructions/harness change-type). Terminal group (3 subtasks; within the `1..=10` range). It follows Group A because each of its three subtasks describes what Group A leaves. It edits no code file: a code-surface finding here is a Group A defect, which Group B reports instead of editing.

Two groups: the minimum for two change-types, within the default maximum of four.

## Risks

- **A ledger enum member is permanent after merge.** A resource kind named wrongly cannot be withdrawn — each arrives by its own `ADD VALUE` migration and never leaves `[measured f5a5963:ai-docs/deferred/_inbox.jsonl:25 · `cat -n ai-docs/deferred/_inbox.jsonl` → "each its own `ADD VALUE` migration; members are permanent"]`. Mitigation: D8 names the tokens in the design so review meets them before the migration exists, and § Open questions asks the owner to confirm them before subtask 1 lands.
- **A new enum member cannot be used in the transaction that adds it.** Mitigation: subtask 1 adds no `account_definition` row, so nothing consumes the members in that transaction and no follow-on migration is owed (D8) — `[measured f5a5963:internal/store/migrations/00006_capacity_kinds.sql · Read → the same restriction, and the reason its consumers waited for the next migration]`.
- **The world file is gated as YAML by the comment-reference gate, and a document marker makes the gate refuse the whole file.** A leading `---`, a trailing `...` or a `%` directive at column zero returns an instrument failure rather than a finding `[measured f5a5963:internal/commentref/yaml_extract.go:17-21,104-107 · Read → ErrYAMLUnsupportedStream; the "---", "...", "%" tokens]`. Mitigation: the authored file is one plain document with no marker, and its comments obey D12 — `[derived → subtask 7's `make comment-refs` gate]`.
- **A radius that passes configuration can still exhaust memory at generation time.** `maze` states no upper bound, and this design adds none beyond what the field type holds `[measured f5a5963:internal/maze/params.go:12-16 · Read → "There is no upper bound — a radius this package makes no promise for exhausts memory long before any coordinate arithmetic would overflow"]`. Mitigation: the refusal that does exist names its key; bounding the radius for play is a balance decision §16.5 leaves open, and inventing one here would be unapproved scope.
- **The lexicon and bestiary shapes could pre-empt #34 and #35.** Mitigation: D10 carries no stats, no vulnerabilities, no loot and no fixed lexicon slot names; the only cross-check is internal to the naming style — `[derived → AC9; the naming-style cross-check tests]`.
- **The balance and world files are one contract across two files.** An operator who updates the binary and one file gets a start-up refusal naming the key, never a defaulted value (D11) — `[derived → AC2, AC5 tests]`.
- **Coverage.** The loader is mostly refusal paths, and the ratchet only ever rises `[measured 3feab5d:ai-docs/coverage-ratchet.txt:1 · Read → 91.90]`. Mitigation: every refusal D4, D7 and D10 name gets its own table row in § Test Design.
- **Panic surface.** None is designed: every refusal is a `*KeyError`, and the loader returns errors rather than exiting. The panic index is empty and stays so `[measured f5a5963:ai-docs/panic-index.md:9 · Read → "| — | — | — |"]`.
- **The `exhaustive` linter is not excluded for test files.** Its exclusions there are `goconst`, `gosec`, `unparam` and `forbidigo` `[measured f5a5963:.golangci.yml:72-78 · Read → that list]`, so a `switch` over a ledger `Kind` without a `default` anywhere in the tree would turn red on the new members. Mitigation: D8 measured that every such switch carries one; a new switch written by this task carries one too.
- **A mistyped file extension silently drops a world.** D2 ignores non-`.yaml` entries, so `cotton_candy.yml` would load nothing. Mitigation: the empty-set refusal catches the whole-set case, and the tracked set is held by a test that loads it and reads its content — `[derived → the tracked-set test § Test Design]`.

## Test Design

All config tests are in `package config`, the package the existing tests use `[measured f5a5963:internal/config/world_test.go:1 · Read → "package config"]`, so the unexported loader is reachable directly. Fixtures follow the balance suite's shape: one known-good world YAML constant every negative case mutates by one documented line, and `t.TempDir()` world directories `[measured f5a5963:internal/config/balance_load_test.go:15-18 · Read → "validBalanceYAML is the known-good baseline every negative test case mutates: one documented change per case"]`. The tracked set is reached through `repotest.RootPath` `[measured f5a5963:internal/config/balance_file_test.go:22 · Read → repotest.RootPath(t, "config/balance.yaml")]`. Refusals are asserted through the existing `assertKeyError` helper, which pins both the sentinel and the key. Every claim below is about a test that does not exist yet.

**`internal/config/schema_test.go`** — entry points: the lifted walker and the new non-scalar leaf kind (D6).
- The scalar leaf still refuses a mapping and a sequence with today's wording, so the lift changed no behaviour `[derived → the lift's own test; the untouched balance suite passing is the second half]`.
- A sequence leaf binds a sequence and refuses a scalar and a mapping, each naming its key `[derived → AC1]`.
- An open-map leaf binds a mapping, refuses a scalar and a sequence, and refuses a key that is not a lower_snake_case token `[derived → AC1, D7]`.

**`internal/config/world_test.go`** — entry point: the world document's scalar schema (D3, D4, D5).
- Happy path: the known-good world decodes to the expected id, seed, `maze.Params` and gate spacing `[derived → AC1]`.
- Refusal table, one row per key, each asserting `ErrInvalidValue` and the key's own dotted path: a radius below `maze.MinRadius`, stating the bound rather than "positive" — the balance suite's own reasoning, since a radius of five is itself positive `[derived → AC5]`; each of the island, extra-passage and portal shares outside `[0,1]`; the growing-tree bias outside `[0,1]`; a negative gate spacing `[derived → AC5]`; a weight set whose entries are all zero; a non-integer seed; a float where an integer is required.
- `ErrMissing` for each absent key, including `k` and `seed` — the absent-versus-zero case that is the reason for the node tree `[derived → AC5]`.
- `ErrUnknownKey` for an unrecognised key at each level, including an unrecognised algorithm weight (D5), and a duplicated key anywhere in the document.
- The weight-key agreement: each weight entry's last path segment equals that `maze.Algorithm`'s `String()`, over every exported `Algorithm` constant `[derived → D5]`.

**`internal/config/world_content_test.go`** — entry points: the profile, naming-style, lexicon and bestiary binders (D7, D10).
- The resource profile: a happy path; an empty profile; a negative weight; a duplicated kind — each naming its key `[derived → AC11]`.
- The naming style: a template naming a slot the parts map does not define, and a parts slot no template names, each naming its key. **Mutant that must be seen red:** the cross-check removed — both rows must fail before the check exists and pass after `[derived → D10]`.
- The lexicon: an empty phrase list and a slot key that is not a lower_snake_case token.
- The bestiary: a duplicated entry id, an unknown role, an empty name.

**`internal/config/world_load_test.go`** — entry points: the world-set loader and `Load` (D1, D2, D4).
- A directory holding one world loads; a directory holding two worlds loads both, each with its own values for every part of AC1 — the AC8 case, built as a **fixture**, since the content of worlds beyond the MVP one is out of scope `[derived → AC8]`.
- Duplicate ids across two files: a refusal naming both files `[derived → AC8, D3]`.
- An empty directory, a path that is a regular file, and a path that does not exist: each a refusal naming the variable `[derived → AC4, AC5]`.
- Non-`.yaml` entries and a subdirectory are ignored beside a world file that loads `[derived → D2]`.
- The cross-field fold: a lower portal share above the upper share is refused naming the generation subtree, with the message carrying `maze`'s own wording. **Mutant that must be seen red:** the `maze.New` call removed — this row must fail `[derived → D4, AC5]`.
- Two malformed worlds in one directory produce both failures, in the file order the loader fixes, so the order is a property of this code `[derived → D2]`.
- `Load` with a valid environment populates the new `Config` field, and a world failure reaches the caller joined with every other source's failures `[derived → AC4]`.

**`internal/config/world_file_test.go`** — the tracked set (D9).
- The tracked world set loads through the same loader every other test uses; a single successful load is the proof that no schema key is absent from it and no key in it is unknown to the schema — the balance file's own agreement argument `[derived → AC6]`.
- Every resource kind the tracked set names is a member of the ledger's kind list, read from `internal/store` in this test file only `[derived → AC11]`.
- The tracked set holds one world with one biome `[derived → AC7]`.

**`internal/config/balance_load_test.go`** — the removal (D11).
- The radius cases go; a leftover `world:` block in a balance file is `ErrUnknownKey` naming it `[derived → AC2]`.

**`internal/store/enums_test.go`** — the enum half of AC11.
- The existing mirror test is unchanged in shape and now carries the new members; it fails if the migration and the Go mirror disagree in either direction `[derived → AC11]`.

No golden is specified by this design, and no new database-backed test binary is added: the config suite stays database-free, and the enum mirror rides `internal/store`'s existing one.
