## Approach

Four deliverables, one mechanism each, plus the propagation the two rule changes force.

### 2. Format gate — `golangci-lint fmt -d`

`-d/--diff` is a real flag of this binary and exits non-zero when any enabled formatter would rewrite a file
`[measured: golangci-lint fmt --help → "-d, --diff   Display diffs instead of rewriting files"; on a gofmt-clean/gofumpt-dirty two-file scratch module: gofmt -l . → no output, exit 0, while golangci-lint fmt -d → exit=1 printing the blank-line-removal diff for both files]`.

`golangci-lint fmt` also accepts **path arguments** and confines itself to them, despite a `Usage: golangci-lint fmt [flags]` line that does not advertise it
`[measured: golangci-lint fmt -d sub/sub.go → exit=1 with only sub/sub.go in the diff; golangci-lint fmt sub/sub.go → exit 0, rewrote sub/sub.go only, main.go left dirty; same with an absolute path; 0.05–0.07 s wall each (time)]`.

That measurement is what makes KD-8 cheap: the `PostToolUse` hook keeps its per-file shape and simply swaps the tool.

### 3. Two-tier file limit — one POSIX `awk` step in the Makefile

**Chosen:** a single `file-limits` target running one `awk` program over `find`-selected `*.go` files, applying 1500 to a base name ending `_test.go` and 1000 to everything else, counting raw records (KD-3).

```
find . -path ./.git -prune -o -name '*.go' -exec awk \
  '{n[FILENAME]++} END{rc=0; for (k in n) {lim=(k ~ /_test\.go$$/)?$(GO_MAX_TEST_LINES):$(GO_MAX_LINES); if (n[k]>lim) {printf "%s: %d lines exceeds hard limit %d\n", k, n[k], lim; rc=1}} exit rc}' {} +
```

(`$$` is the Makefile escape for a literal `$`; the limits are `?=` variables so the two numbers appear once each.)

Verified behaviour, exactly the AC6 matrix, against generated fixtures
`[measured: fixtures a1000.go=1000, a1001.go=1001, b1500_test.go=1500, b1501_test.go=1501, c1001_test.go=1001 (wc -l confirms each) → find … -exec awk … {} + printed "./pkg/a1001.go: 1001 lines exceeds hard limit 1000" and "./pkg/b1501_test.go: 1501 lines exceeds hard limit 1500" and exited 1; a1000.go, b1500_test.go and c1001_test.go were silent; after deleting the two offenders → exit 0; on a tree with no .go file → exit 0]`.

Three sub-decisions, each measured rather than assumed:

- **Exit status propagates through `find -exec … +`** — the gate is not piped, so nothing masks it `[measured: the run above returned exit=1 from find itself; with the offenders removed, exit=0; the `-path ./.git -prune -o` form propagates identically, tested with an offender present → exit=1]`. POSIX additionally specifies that `find` returns non-zero if *any* `-exec … +` invocation does, which covers a future ARG_MAX split.
- **The program is POSIX awk, so `mawk` on `ubuntu-latest` runs it** — no gawk extension is used `[measured: gawk --posix and gawk --traditional both reproduce the exit-1/exit-0 results above; mawk is not installed on this machine (command -v mawk → empty), so the runner itself is discharged by the first CI Lint job]`.
- **Records vs `\n` bytes.** `awk` counts a final newline-less line as a record; alduna counts `\n` bytes. The two can differ by one only for a file with no trailing newline, and no such file can pass the format gate `[measured: printf 'package main\n\nfunc main() {}' > nl.go → 28 bytes; gofmt -w nl.go → 29 bytes, last byte \n]`. The divergence is therefore unreachable for a tree that is green, and `awk`'s reading is the stricter one.

**Rejected — `revive` alone:** spec § C probe 4 shows two `file-length-limit` entries silently collapse to one. Unimplementable as specified.

**Rejected — `revive` at 1000 with a `_test.go` exclusion plus `awk` at 1500:** it works, but splits one gate across two mechanisms with two message shapes and two config sites, makes AC4's single "file-limit check" into two, and puts half the gate behind `golangci-lint run` where the Makefile cannot name it. It also forfeits KD-3's raw counting only if the skip flags are passed — a footgun the config would carry forever. No compensating benefit: the `//nolint:revive` exemption channel it would buy is not one we want (see § *Exemptions* below).

**Rejected — a Go tool** (`cmd/`, an `internal/` package, importing `projectlint`): forbidden by AC7.

### 4. `Makefile` — ten sub-targets and one aggregate

Header comment states the contract and names AC14's two deliberate exceptions (`reviewdog/action-actionlint@v1`; the Harness-guards job's inline `shellcheck` over `.claude/**`). Then:

```
SHELL := /bin/bash
.SHELLFLAGS := -eu -o pipefail -c
.NOTPARALLEL:
```

`pipefail` in force for every recipe answers spec § D and AC5 structurally rather than per-recipe; `.NOTPARALLEL` keeps `make -j verify` from interleaving `go mod tidy` with the build. Targets, all `.PHONY`:

| Target | Command | AC |
|---|---|---|
| `build` | `go build ./...` | AC4 |
| `vet` | `go vet ./...` | AC4 |
| `test` | `go test ./...` | AC4 |
| `test-race` | `go test -race ./...` | AC4 |
| `lint` | `golangci-lint run` | AC4 |
| `fmt-check` | `golangci-lint fmt -d` | AC3, AC4 |
| `tidy-check` | `go mod tidy`, then fail if `git status --porcelain -- go.mod go.sum` is non-empty | AC4 |
| `file-limits` | the `awk` gate above | AC4, AC6 |
| `actionlint` | `actionlint .github/workflows/*.yml` | AC4 |
| `shellcheck` | `find . -path ./.git -prune -o -name '*.sh' -exec shellcheck -s bash {} +` | AC4 |
| `verify` | those ten as prerequisites, in the order `fmt-check build vet lint file-limits test test-race tidy-check actionlint shellcheck` | AC4, AC13, AC14 |

`tidy-check` keeps the `git status --porcelain` form and the reason CI already carries for it (`git diff -- go.sum` exits 128 while the file does not exist); it loses the `::error::` annotation prefix, which is a GitHub-only nicety and would be noise locally — a deliberate, stated trade-off.

No `fmt` (apply) target: `golangci-lint fmt` is the apply command, it is already in `AGENTS.md` § *Build & Test*, and an eleventh target that `verify` does not run is drift bait (YAGNI).

Longest recipe is 4 code lines (`tidy-check`); the `awk` gate is one logical line. KD-7's 10-code-line cap holds with room. No python, no third language (AC12).

A prototype of exactly this file was run against the real repository from the scratchpad, so the tree stayed clean
`[measured: make -f $S/Makefile.proto verify → VERIFY-GREEN, every target executed in order; git status --porcelain afterwards unchanged (only the pre-existing INDEX.md/spec entries); make -f $S/Makefile.proto actionlint shellcheck file-limits with no PATH prefix → green, so actionlint (/home/syt/go/bin) and shellcheck (/usr/bin) resolve on the default PATH]`.

**CI never runs `make verify`.** It runs sub-targets per job; `verify` is the local aggregate. That is what keeps AC14's "cannot disagree" true while `actionlint` is absent from the runner (spec § E).

### 6. Hook (KD-8) and one permission

Body delta is one call: `gofmt -w "$f"` → `golangci-lint fmt "$f"`. Structure, `|| true` tail, matcher, timeout and `statusMessage` are untouched, so the shellcheck-clean shape is preserved and a missing binary still cannot break a session. The scoped-path measurement in § 2 is what makes this safe: it rewrites only `$f`, in 0.05–0.07 s, and does **not** reformat siblings.

`.claude/settings.json` `permissions.allow` gains `Bash(make *)` — **KD-13 / Scope item 7 / AC19**, an owner decision since the amendment, no longer a design proposal. Without it, `make verify` is an ASK for every agent and AC13 cannot be discharged in an unattended run. The granularity matches the file's existing entries (`Bash(go *)`, `Bash(git *)`), and no other `permissions` entry is added, removed or broadened (AC19's second half). Entry count today is 17 `[measured: jq -r '.permissions.allow[]?' .claude/settings.json | wc -l → 17]`, so the file carries 18 after this change.

### 8. Exemptions — the spec's first open question, answered

The `awk` gate has no per-file escape and will not get one: the exemption channel is **a path prune added to the `file-limits` recipe in a reviewed diff**, recorded in `ai-docs/code-style.md` § *File size*. Rationale: `//nolint:revive` would only exist under the rejected mechanism; an inline escape hatch on a *hard* limit is the thing that turns a hard limit soft; and `ai-docs/code-style.md` already states the equivalent posture for lint ("A rule that keeps firing on correct code is a config bug: change `.golangci.yml` in a reviewed diff"). No prune is added now — no `testdata/`, `vendor/` or generated directory exists `[measured: find /home/syt/lab-game -name '*.go' -not -path '*/.git/*' → cmd/bot/main.go only]` — and adding one pre-emptively is YAGNI.

### 9. The piped-gate guard and its regression suite (Scope items 8–9)

**Why it is in this PR at all (KD-15).** Deliverables 2 and 3 would silently narrow an existing enforcement: the `PreToolUse` guard's alternation names `golangci-lint[[:space:]]+run` and `gofmt`, so the moment the format gate becomes `golangci-lint fmt -d` the guard stops covering it, and it never covered `make`. `AGENTS.md:76` (`:75` before the leg-1 insert) advertises that hook as the enforcement for the whole piped-gate class, so shipping without this would make a live instruction-file claim false — while KD-11 records that nothing this repo enforces today gets narrower.

**The edit is one alternation group, and nothing else.** `(go[[:space:]]+(build|test|vet)|golangci-lint[[:space:]]+run|gofmt)\b` becomes `(go[[:space:]]+(build|test|vet)|golangci-lint[[:space:]]+(run|fmt)|gofmt|make)\b`. Both carve-outs — `--help`/`-h` and `set -o pipefail` — are untouched, which AC23 checks byte-for-byte. **Nothing is removed from the alternation either**, `gofmt` included: it stops being this project's gate, but it stays a command agents reach for by habit, and AC21 keeps `gofmt -l .` piped into `tail` in the must-block set precisely as regression cover. A rewrite that drops the branch while adding the new ones would read as tidying and fail AC21.

**`make` matches as a class (KD-16), and this design does not re-open that.** What it does add is the verification: I ran the full 26-row matrix myself, against the **real hook body extracted from `.claude/settings.json`** rather than a retyped regex, feeding each fixture as a `tool_input.command` payload and reading the exit status (2 = blocked)
`[measured: $S/guard/probe.sh — extracts the live body with jq, derives the class body by substituting only the alternation, runs all 26 fixtures through both → every AC21 must-block case BLOCKED under CLASS (the ten `make`/`golangci-lint fmt` rows were ALLOWED under LIVE, which is the leak); every AC22 must-allow case ALLOWED under both; `make -n verify | head` BLOCKED under CLASS; both carve-out strings present verbatim in the derived body; PROBE-GREEN, and the script itself is shellcheck-clean]`.
That run reproduces § I's table row for row, including the one disagreement it records: `make -n verify | head` is **blocked**, so it belongs in AC23 as a documented false positive and not in AC22.

**The suite (Scope item 9, AC24) runs the hook body, not a copy of its regex.** This is the design's answer to AC24's anti-drift clause, and it is the stronger of the two the AC allows: there is no copied regex to drift, because the fixture runner extracts the body with `jq` and executes it. A later edit that breaks a must-allow case fails CI; a revert of the `make` extension fails the must-block cases.

- **Path:** `.claude/skills/ai-audit/scripts/test-piped-gate-guard.sh`, beside `check-citations.sh` and its test. `/ai-audit` is the skill that audits the harness surface and already owns the only checklist item that lints hook bodies (`ai-docs/hook-verification.md` § 1), so the guard's regression suite is its neighbour, not a new home. The spec's *Out of scope* carve-out fixes the directory (`.claude/skills/**/scripts/`); this adds no `SKILL.md`, no `allowed-tools`, no hook entry, and no slash command.
- **Shape:** a `fixtures` heredoc of `verdict<TAB>command` rows, a `verdict()` helper (~5 code lines), a `check()` assertion (~6), the loop (~6), and a carve-out assertion (~4) — **every unit ≤ 10 code lines**, the restrictive reading of AC12's "no shell unit longer than 10 code lines". A whole *file* is not a unit: its two siblings are 121 and 877 lines `[measured: wc -l on both]`, and KD-7's own binding sentence names "the Makefile recipes and any CI step this change writes".
- **CI:** one line appended to the existing `guard regression suites` step — at `.github/workflows/ci.yml:155-161` **as the implementor found it pre-change**, `144-151` on the shipped tree `[measured: grep -n "guard regression suites" → 144, with the three `bash …` lines at 149-151]` — beside the two suites already there. ### Fixture protocol (AC3, AC5, AC6)

All fixtures live in a throwaway package directory `flfixture/` at the repository root, are generated **with `Bash`** (`printf` / a shell loop / a quoted heredoc) and **never** with `Write`/`Edit` (see § *Risks*), and are removed by `rm -rf flfixture` inside the same `Bash` invocation that ran the gate. After the last fixture run, `git status --porcelain` must equal the baseline captured before the first one.

- **AC3 —** `flfixture/dirty.go`: `package flfixture`, blank line, `func f() {`, **blank line**, `\tprintln("x")`, `}`. This exact shape is gofmt-clean and gofumpt-dirty `[measured: on the scratch module, gofmt -l . → silent while golangci-lint fmt -d → exit=1 removing that blank line]`.
**Which fixtures must be format-clean, and which must not.** The two families have opposite requirements, and conflating them is what broke the round-3 plan:

  - **AC5's fixture traverses the whole of `verify`**, whose order is `fmt-check build vet lint file-limits …`. It must therefore be clean through all four earlier targets — plain-`gofmt` clean, gofumpt clean, buildable, vet-clean and lint-clean — or the red it produces is not the red AC5 asks for.
  - **AC3's fixture is deliberately dirty** — being `gofmt`-clean and gofumpt-dirty is the entire point — and it is never fed to `verify`; only to `gofmt -l .` and `make fmt-check`.

**The corrected fixture shape** (the round-3 shape omitted the blank line and was rejected by plain `gofmt` — see § *Risks*). A **blank line follows the `package` clause**, and the filler is **reduced by one** so the total is unchanged; that offset is the load-bearing detail, because adding the blank line without it turns `a1000.go` into 1001 lines and `b1500_test.go` into 1501, inverting the two boundary cases AC6 exists to prove.

  - non-test: line 1 `// Package flfixture is a temporary gate fixture.` · line 2 `package flfixture` · line 3 **blank** · lines 4…N `// filler`
  - `_test.go`: line 1 `package flfixture` · line 2 **blank** · lines 3…N `// filler` (no second package comment — `revive`'s `package-comments` rule allows only one per package, and the non-test file carries it)

- **AC6 —** one fixture at a time, so each gate message is unambiguous. All five verified under the corrected shape `[measured: per fixture — `wc -l` exact; `gofmt -l .` names none of them; `golangci-lint fmt -d` exits 0 for each; `file-limits` exits as listed]`:
  - `flfixture/a1000.go` — 1000 lines → **pass**
  - `flfixture/a1001.go` — 1001 lines → **fail**, message naming the file, `1001`, `1000`
  - `flfixture/b1500_test.go` — 1500 lines → **pass**
  - `flfixture/b1501_test.go` — 1501 lines → **fail**, naming `1501`, `1500`
  - `flfixture/c1001_test.go` — 1001 lines → **pass** (a test file is never governed by 1000)
  - A `_test.go` fixture needs the non-test package file beside it to hold the package comment; keep that companion small (5 lines) so it never approaches a limit.
  - Confirm each fixture's own count with `wc -l` before running the gate; the generator writes a trailing newline, so `wc -l` and the gate's record count agree (§ *Approach* 3).
- **AC5 — assert BOTH halves; only the pair is evidence.**
  1. **With `flfixture/a1001.go` present** (corrected shape, package comment included): `make verify > verify.gate.log 2>&1 && echo GATE-GREEN || echo GATE-RED` → `GATE-RED`, **and the failing target is `file-limits`**, with `fmt-check`, `build`, `vet` and `lint` all having passed above it in the log. Verified for that fixture `[measured: the corrected 1001-line file is `gofmt -l`-silent, `golangci-lint fmt -d` exit 0, `golangci-lint run` "0 issues.", `go build` and `go vet` clean, and `file-limits` exits 1 naming it]`.
  2. **With the fixture removed:** the same command → `GATE-GREEN`.

**What each half proves, and why one alone proves nothing.** The red alone is satisfied by *any* red — including a fixture that trips `fmt-check` at target 1, which is exactly how the round-3 plan failed and would have recorded a pass. The green alone shows only that the tree is clean. Together they show `verify`'s verdict actually *depends on* `file-limits`: it is the only thing that changed between the two runs. If the red arrives at any target other than `file-limits`, the fixture is malformed — fix the fixture, never accept the red.
