# Design: Spiral gate placement and nearest-gate depth

**Issue:** #120
**Date:** 2026-09-14

## Approach

Three pure functions over the chunk super-lattice `internal/hexgrid` already provides, in a new package `internal/gate` that imports `hexgrid` and the standard library and nothing else. The spiral order is a ring walk with a closed-form index. The next gate scans that order over a bounded prefix and falls back to a chunk it proves valid. The nearest-gate distance is a ring search around the cell's chunk over a hash set of gate chunks. Its stop rule is a lower bound on the cell distance from the cell to any chunk centre in a ring, and that bound is what makes the search both exact however sparse the gates are and blind to gates beyond it.

Everything this builds on exists: the axial `Chunk` with the same six direction deltas as a cell, `ChunkDistance`, and the `Lattice` with `Center`, `Locate`, `CellCount` and the cell `Distance` `[measured fc73d3b:internal/hexgrid/chunk.go:14-27 · Read → Chunk.Neighbor uses directionDeltas; ChunkDistance (|dq|+|dr|+|dq+dr|)/2] [measured fc73d3b:internal/hexgrid/lattice.go:15-28,39,139 · Read → CellCount 3R²+3R+1; Center i·(2R+1,−R)+j·(R,R+1); Locate; Distance]`. The six directions have a numeric canonical order the package fixes and documents as load-bearing `[measured fc73d3b:internal/hexgrid/coord.go:11-24 · Read → "the six values are in the canonical order this package fixes"; DirE, DirNE, DirNW, DirW, DirSW, DirSE]`.

| D4 | **`Next`: a bounded scan with a proven fallback.** `k < 0` returns `ErrNegativeK`. Return the first chunk that is not in `created` (a map built from the slice) and whose `ChunkDistance` to every entry of `gates` is at least `k+1`. If none qualifies, return the first chunk of ring `M+k+1`, `(M+k+1, −⌊(M+k+1)/2⌋)`. | D5 | **`Set` and `Depth`: a ring search with a lower-bound stop rule.** `NewSet` refuses an empty `gates` (`ErrNoGates`) and a negative radius (`ErrNegativeRadius`), and it copies the gate chunks into a `map[hexgrid.Chunk]struct{}`, the only form in which `Set` holds them. `Depth(cell)`: `c0, _ := lattice.Locate(cell)`. For `s = 0, 1, 2, …`: if a gate has been found and `best ≤ L(s)`, stop. Otherwise look up every chunk at `ChunkDistance` `s` from `c0` (the ring walk, translated) in the set, and set `best = min(best, Distance(cell, lattice.Center(g)))` for each hit. Here `L(s) = ⌈s·C / (2R+1)⌉ − R` with `C = 3R²+3R+1`. The result is `best`, a hex-formula cell distance to a gate chunk's centre cell. | **Why `L` is a lower bound.** Super-lattice vectors map to cell vectors by `Φ(i, j) = i·(2R+1, −R) + j·(R, R+1)` `[measured fc73d3b:internal/hexgrid/lattice.go:21-28 · Read → q = i*(2r+1) + j*r; rr = -i*r + j*(r+1)]`. The second basis vector is the first rotated by 60°, so `Φ` commutes with rotation, and the hex norm's minimum over the super-lattice's unit hexagon is the same on all six edges. On the edge from `(1, 0)` to `(1, −1)` it is `C/(2R+1)`, reached at `t = (R+1)/(2R+1)`. So two chunk centres at super distance `s` are at least `⌈s·C/(2R+1)⌉` cells apart. A cell lies within `R` of its chunk's centre, so a gate centre in ring `s` is at least `L(s)` from the cell. A scratch probe checked this for every cell of a chunk against every chunk out to ring 12, for radii 0–12. At R = 9 the centre bound is attained at rings 2 and 4 (29 and 58), so it is not loose `[measured fc73d3b:tmp/spiralprobe/main.go · go run ./tmp/spiralprobe → "lower bound ok"; "R=9 s=2 minCentreDist=29 bound=29"; "R=9 s=4 minCentreDist=58 bound=58"]`. **Exact however sparse (AC8).** `L` never decreases, so once `best ≤ L(s)` no gate in ring `s` or beyond can be nearer. Before any hit the search does not stop, and a non-empty set guarantees one. The probe matched the search against brute force over random worlds, cells up to 60 chunks from the origin included `[measured fc73d3b:tmp/spiralprobe/main.go · go run ./tmp/spiralprobe → "depth search ok"]`. **The stated search bound (AC9).** `S(cell) = ⌊(depth(cell) + R)·(2R+1) / C⌋`, the largest `s` with `L(s) ≤ depth`. The search never looks at a chunk beyond super distance `S` from `c0`. `L` is strictly increasing because `C ≥ 2R+1` with equality only at R = 0, where `L(s) = s`. So the nearest gate's ring is at most `S`, and the loop stops before ring `S+1` at the latest. The probe checked that no search visited a ring beyond `S` `[measured fc73d3b:tmp/spiralprobe/main.go · go run ./tmp/spiralprobe → "depth search ok" (asserts maxRing ≤ S)]`. A gate beyond `S` is never looked up, and holding gates only as a map means reaching them any other way is a map range, which `detguard` refuses. That makes the bound structural, not a convention `[derived → AC9 tests; guards_test.go]`. **The negative-radius refusal.** With `2R+1 < 0`, `L` decreases, and the loop would never stop. Rejected: a linear scan over all gates, whose work grows with far gates (AC9). Rejected: a precomputed distance field, since the world is unbounded (DESIGN §2.2). |

## Risks

- **A wrong lower bound gives a silently wrong depth.** A cell whose nearest gate lies in a farther ring than an already-found gate would be mis-answered, and depth feeds every danger formula. Mitigation: D5's proof; the probe over every cell to ring 12 for radii 0–12; a rapid brute-force oracle; and an explicit table case in which the nearer gate lies in the later ring, whose mutant ("stop at the first ring with a hit") must be seen red — `[measured fc73d3b:tmp/spiralprobe/main.go · go run ./tmp/spiralprobe → "lower bound ok", "depth search ok"]` `[derived → AC7, AC8 tests]`.
- **The spiral orientation becomes world identity.** Once #29 stores gate chunks and spiral indices, changing D2 re-places every later gate and renumbers stored indices, which is a data migration, not a refactor (`AGENTS.md` § API Stability carve-out). Mitigation: KD-41 records it, and the ring 1–3 table test makes any change visible in the diff — `[derived → AC2 table test; subtask 5]`.
- **Pathological `k` or far chunks.** `Next` costs up to rings `0..M+k` times the gate count, and `Depth` costs chunk lookups over the hexagon of radius `S(cell)`, which grows with distance from the nearest gate, not with the gate count. Neither is bounded in code (D9). Mitigation: the benchmark reports both on a fixed world (D7). Bounding `k` is #28's config call, and whether depth is cached is #29's — `[derived → bench_test.go]`.
- **Directions indexed arithmetically.** `(d+2) mod 6` relies on the canonical numeric order `[measured fc73d3b:internal/hexgrid/coord.go:11-24 · Read → canonical order documented as relied on]`. Any `switch` over `Direction` written here must be total, because `exhaustive` is enabled with `default-signifies-exhaustive` `[measured fc73d3b:.golangci.yml:20,44-45 · Read → exhaustive enabled; default-signifies-exhaustive: true]`.
- **Panic surface.** None is designed. Every refusal is a sentinel error, and `Depth` is total over a validated `Set`. The panic index is empty and stays so `[measured fc73d3b:ai-docs/panic-index.md:9 · Read → "| — | — | — |"]`.
- **Coverage.** `Next`'s fallback return is a real statement, and one table row must reach it, e.g. every chunk of rings 0–2 created with `k = 0`, giving `(3, −1)` — `[derived → TestNext_Table fallback row]`.
- **The leak-check guard.** A new package with tests must carry the `leaktest.Main` `TestMain`, and the guard finds package directories itself `[measured fc73d3b:internal/leaktest/guard_test.go:204,232 · Read → ImportDir walk; TestGuard_EveryPackageWithTestsRunsTheDetection]`.

## Test Design

All in `internal/gate`. External tests are in package `gate_test`, and the AC9 test is in package `gate`. Property tests use `pgregory.net/rapid`, already a direct requirement and the form `hexgrid`'s tests use `[measured fc73d3b:go.mod:22 · Read → pgregory.net/rapid v1.3.0]` `[measured fc73d3b:internal/hexgrid/chunk_test.go:13 · Read → rapid.Check]`. Every statement below about a test is `[derived → the test it names]`.

**`spiral_test.go`** — entry points `Spiral`, `SpiralIndex`.
- `TestSpiral_ListsEveryChunkOnceRingByRing` (AC1): take the prefix of `Spiral()` through ring `N` (a small constant). The first chunk is `(0,0)`. Ring distances never decrease, and ring `n` contributes exactly its chunks before any of ring `n+1`. There are no duplicates. Every chunk with `ChunkDistance ≤ N` in an enclosing box appears.
- `TestSpiralIndex_AgreesWithSpiral` (AC1): `SpiralIndex` of the `i`-th chunk of the prefix is `i`, so the two independent derivations must agree.
- `TestSpiralIndex_RingRange` (AC1, rapid): for a chunk drawn within ±1000, `SpiralIndex` lies in `[1+3n(n−1), 1+3n(n+1))` for its ring `n ≥ 1`, and is 0 for the centre.
- `TestSpiral_RingWalkTable` (AC2): hand tables of rings 1, 2 and 3 as full chunk lists. Mutants that must go red: `⌈n/2⌉` start (differs at ring 3), corner start (differs at ring 2), reversed turn.
- `TestSpiral_RingStartAndTurn` (AC2): for every `n ∈ 1..N`, the ring's first chunk is `(n, −⌊n/2⌋)`. Consecutive chunks, and the last with the first, are at distance 1. The corner `n·δ(d)` sits at ring position `(d·n − ⌊n/2⌋) mod 6n` for each canonical `d`.
- `TestGuard_DeterminismPredicates` (`guards_test.go`): `detguard.Check` on `internal/gate` is empty.

**`next_test.go`** — entry point `Next`.
- `TestNext_FirstGateIsCentre` (AC3): table over `k ∈ {0, 1, 5}`, with `created` nil or holding non-centre chunks, and no gates. The result is `(0,0)`.
- `TestNext_Table` (AC4): centre created, `k = 0` → `(1,0)`. Gate at the centre, `k = 1` → `(2,−1)`. Rings 0–2 all created, `k = 0` → `(3,−1)` (the fallback). And a sequential fill: with `k = 0`, repeatedly calling `Next` and adding the result to both `gates` and `created` reproduces `Spiral()`'s prefix, which is how k = 0 fills concentric rings.
- `TestNext_MatchesSpiralScan` (AC4, rapid): draw `created` and `gates` from a box around the centre and `k ∈ [0, 4]`. The oracle scans `Spiral()` for the first chunk not in `created` and at distance `≥ k+1` from every gate, failing the test past a generous iteration cap. `Next` equals the oracle.
- `TestNext_AlwaysReturns` (AC5, rapid): for finite drawn sets and `k ∈ [0, 20]`, `err` is nil, the result is not in `created`, and it is at distance `≥ k+1` from every gate.
- `TestNext_RefusesNegativeK` (AC6): `k ∈ {−1, math.MinInt}` gives `errors.Is(err, ErrNegativeK)`. The test file may import `math`; `detguard` checks non-test source only `[measured fc73d3b:internal/detguard/detguard.go:39 · Read → "Check parses every non-test Go source file"]`.

**`depth_test.go`** — entry points `NewSet`, `Set.Depth`.
- `TestNewSet_Refusals`: an empty gate slice gives `ErrNoGates`, and radius −1 gives `ErrNegativeRadius`.
- `TestSetDepth_MatchesBruteForce` (AC7, rapid): radius drawn from `[6, 12]`, plus radius 0. Gates are drawn within ±15 chunks, and the cell within ±60 chunks' worth of cells. `Depth` equals `min Distance(cell, lattice.Center(g))` over the gate slice.
- `TestSetDepth_Table` (AC7): a cell at a gate's centre gives 0. A hand-computed cell two chunks out gives its formula distance. The later-ring case: a gate in ring 1 of the cell's chunk that is farther in cells than a gate in ring 2, with the expected value from brute force.
