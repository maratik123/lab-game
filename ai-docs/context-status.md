## Mechanical code-style gates from a donor project — one `make verify` every runner shares (PR #6, 2026-08-30)

- **What landed:** `asciicheck` + `gofumpt` in `.golangci.yml`; a tracked `Makefile` whose `.PHONY` sub-targets carry every gate, under a `verify` aggregate; CI rewired so every Go job invokes a `make` sub-target, with the job matrix and `paths-filter` otherwise unchanged; a two-tier file-size gate (1000 non-test / 1500 `_test.go`) as one POSIX `awk` step; the `PostToolUse` formatting hook and the `PreToolUse` piped-gate guard both updated; a committed guard regression suite run by CI; and the two rule changes propagated to every site the sweep found.

- **Decisions worth keeping:**
  - **The format gate is `golangci-lint fmt -d`**, not `gofmt -l .`. It exits 1 when any enabled formatter would rewrite a file, so it works as a check without post-processing its output. `gofumpt` needs no separate binary — it is a golangci-lint v2 built-in formatter.
  - **`make` matches as a CLASS in the piped-gate guard**, not by target enumeration. Enumeration leaks on six shapes that all run gates: five carry a flag between `make` and the target (`-s`, `-B`, `-C .`, `-j4`, `-f Makefile`), which breaks the `make[[:space:]]+<target>` anchor; the sixth is bare `make`, which leaks because it names no target for the anchor to bind to at all. The class form's only false positive is a dry run, which executes nothing — loud over-blocking beats silent under-blocking.
  - **No dry-run carve-out in that guard.** `tail -n 5` is the canonical spelling of `tail -5`, so exempting that flag would switch the guard off through the exact idiom it exists to catch. The carve-outs are whole-command greps, so any such exemption is a bypass, not a narrowing.
  - **The `gofmt` branch stays in the guard regex** even though `gofmt -l .` is no longer this project's gate — agents still reach for it by habit, so it remains must-block regression cover.
  - **File-size bands: 500 and 800 are prose, 1000 and 1500 are gated.** The source contradicts itself — the donor's `projectlint` flags mechanically at 500 (`internal/projectlint/projectlint.go`, `MaxLines = 500`) while the donor's prose (`docs/code-style.md`) calls 1000 the hard threshold. Resolved in favour of the prose by owner decision.
  - **Neither of the donor's `errcheck` loosenings crossed over.** Both would have weakened this repo's existing "never discard an error" rule (`code-style.md`). `asciicheck` was the whole linter delta; the donor's other linters are already active here via `linters.default: standard`.
  - **Every Makefile target is a gate**, which is what makes class-matching `make` semantically exact. An eleventh non-gate target was refused as drift bait — `go` stays enumerated in the guard precisely because `go list` and `go doc` are legitimately piped.

- **Traps found:**
  - **A pure-`revive` two-tier limit is impossible.** Two `file-length-limit` entries in one config silently collapse to the last one, and `exclusions` can disable a linter per path but not re-parameterise it. Hence one `awk` step owning both tiers.
  - **A fixture proving the file-limit gate must itself be gofmt-clean, or it proves nothing.** `verify` runs `fmt-check` first, so a dirty fixture reds at target 1 of 10 instead of at the gate under test. The naive fix — inserting a blank line — shifts the boundary fixtures by one, flipping 1000 to 1001 at exactly the boundary being proven. Reduce the filler by one to compensate.
  - **Proving a gate is load-bearing needs both halves:** red *at that gate* with the fixture present, and green with it removed. A red alone is satisfied by any red.
  - **`golangci-lint fmt` confines itself to path arguments**, despite a usage line that suggests otherwise. That is what makes the formatting-hook swap a one-call delta rather than a whole-module reformat.
  - **`golangci-lint-action@v9` needs `install-only: true`** when a job's `run:` is a `make` target — the action otherwise runs the linter itself. Its `core.addPath` precedes the early return, so the pinned binary is still on PATH.
  - **A guard regression suite must execute the hook body, not a copy of its regex.** Extracting the body with `jq` removes the drift class instead of documenting it. The suite was also run against the *pre-edit* body, where it fails on exactly 11 rows — proving it discriminates rather than passing anything put in front of it.
  - **The piped-gate guard matches command TEXT, not shell semantics.** It fires on any command merely quoting a gate piped into `tail`/`head`, including documentation of its own fixtures. Use the Write tool for such content.

- **Invariants this now relies on:**
  - `AGENTS.md` sits at **34 984 bytes** against its own 34 986 ceiling. Any edit to lines 47, 48, 77, 102 or 108 needs its byte arithmetic re-run *before* the edit lands — the five-line set balances only as a set, and two of the five grow while three pay for them.
  - `.claude/skills/task/SKILL.md` is **39 539 bytes** against a 40 000 hard cap.
  - `harness` is the only CI job whose `paths-filter` matches `.claude/**`, so a guard added there has nowhere else to live.
  - `Makefile` is present in the `go` paths-filter; without that entry a Makefile-only change silently skips every Go job.
  - The file-limit gate has no per-file escape hatch. The exemption channel is a reviewed path prune in the `file-limits` recipe, recorded in `code-style.md` — an inline escape on a hard limit is what turns a hard limit soft.

## Ledger core — `store.Post`, the owner/scope/account model and container-backed tests (PR #14, 2026-09-02)

- **What landed:** `internal/store` (`Migrate`, `NewPool` with the shopspring codec, `CreateOwner`, `Post`, enum and catalog mirrors, the `Err…` sentinels) and `internal/testdb` (testcontainers provisioning, `LAB_GAME_TEST_DSN` override, schema per test, never a skip). One forward-only goose migration creating the enums and tables — `owner`, `scope_definition`, `account_definition`, `scope`, `account`, `account_balance`, `player_operation`, `manual_correction`, `journal_entry`, `posting` — with World and the player `attributes` catalog seeded. The whole suite runs against a real `postgres:18` container: the rapid property for the zero invariant, the `QueryTracer` phase/capture-order test, the `-race` anti-deadlock stress, FK-coverage and balance-row invariant checks, the catalog-mirror equality test. CI's `go` filter now matches `**/*.sql`.
- **Decisions worth keeping:** `kind` and `controlled` are catalog data (`account_definition`), never caller input — a posting is `(account, amount)` and "wrong kind on wrong account" is unrepresentable; accounts and zero balance rows are created with their owner, so every overdraft is refused by `CHECK (balance >= 0)` and `Post` needs one plain `UPDATE` per controlled account in ascending `account_id` (no upsert, no sign split); the exclusive arc and `ts` live on `journal_entry`, 1:1 with its basis document; singular table names; identity columns (`BY DEFAULT` where seeded, `ALWAYS` where only `Post` writes); every FK is index-covered, partial `IS NOT NULL` allowed, enforced by a migration test with a planted positive control; enums are add-only, one `ALTER TYPE` per migration file; images pinned to the major tag (`postgres:18`); `pgregory.net/rapid` for properties.
- **Traps found:** `INSERT … ON CONFLICT DO UPDATE` evaluates the `CHECK` on the *proposed* row, so an upsert refuses a covered debit with `23514` — the round-1 design had "measured" it on credits only; `pg_index.indkey` is zero-based (take the prefix `WITH ORDINALITY`); rootless podman's healthcheck never leaves `starting` (gate on `pg_isready`); the shell's `grep` is ugrep and `\|` inside `-E` is a literal pipe under GNU grep too — a grep-shaped AC needs a positive control, and its command cannot live in a markdown table cell (the cell escaping recreates the defect); `go mod tidy` prunes a `require` no package imports, so a dependencies-only subtask cannot commit on its own; a `.gitignore` pattern with an inner slash is root-anchored (`**/testdata/rapid/`); `decimal.New` takes an `int64` coefficient — 25-digit amounts are built from `New(r, 18)` plus a scale-5 fraction; `pgxdecimal.Register` prepends on every call (register once, in `AfterConnect`).
- **Invariants this now relies on:** every controlled account has exactly one `account_balance` row from creation (owner-creation code + the AC18 test) — `Post` treats zero rows affected as a broken invariant, never as overdraft; the Go mirrors of the three enums and two catalogs equal the database rows (test); no non-test statement in `store` targets `posting`/`journal_entry` with `UPDATE`/`DELETE` (grep with a planted control); `cmd/bot` never links testcontainers (`go list -deps` count 0); the test suite fails rather than skips when no database is reachable.

## Configuration layer — typed access, fail-loud start-up validation, and the tracked balance file (PR #50, 2026-09-04)

- **What landed:** `internal/config` — the `Balance` schema with a node walker that reports every failure by dotted key path, the environment layer (`Lookup`, `EnvKeys`, the `LAB_GAME_` name constants), the world-set path probe, and `Load` joining all three into one error; the tracked `config/balance.yaml` and `config/world/`; `.env.example`; `cmd/bot` rewired so `main` delegates to a testable `run` that loads and validates before any other work; the `go` paths-filter in `ci.yml` extended to the tracked config artefacts. Riding in the same PR by the owner's decision: the `AGENTS.md` axiom making established packages the default over hand-rolling, the `.claude/settings.json` deny narrowing that made `.env.example` authorable, and the `claude-tools-hierarchy.md` propagation of that narrowing.

- **Decisions worth keeping:**
  - **The parser is `go.yaml.in/yaml/v3`, not `gopkg.in/yaml.v3`.** The incumbent's upstream (`go-yaml/yaml`) is archived and has no release past `v3.0.1`; the YAML org's fork is maintained and has zero non-stdlib requires. `gopkg.in/yaml.v3` stays as a test-only indirect via testify — do not tidy it away. The fork's `retract [v3.0.0, v3.0.1]` directive is **not** an argument for the move: it retracts those version strings under the new module path and says nothing about the incumbent release.
  - **The three sources are disjoint by domain, so there is no override chain to resolve.** The environment owns secrets, runtime settings and file paths; the balance file owns balance values; the world set owns world content and is not decoded here. This is excluded by decision, not merely unimplemented — no key-path override machinery and no env-vs-file merge step exist, and none should be added without revisiting the decision.
  - **Reload is start-up only.** Moving balance without a deploy is deferred out of MVP with the seasons work; the closing clause of `domain-invariants.md` § 8 binds nothing here, while the rest of § 8 — balance is configuration, never a Go literal — is why the layer exists.
  - **`.env.example` is the loader's manifest, and the equality is enforced.** Its keys equal the set the loader consults, checked in both directions by name. Test-suite variables such as `LAB_GAME_TEST_DSN` are documented elsewhere; adding one here breaks the suite, which is why the file opens with a header comment saying so.

- **Traps found:**
  - **A YAML `null` decodes into `int`, `time.Duration` and `decimal.Decimal` with no error and a zero value** — the silently-defaulted balance number this layer exists to prevent. So does `!!float` into `int` (`3.25` → `3`). Both are why the walker inspects node tags rather than binding straight into a struct.
  - **Duplicate keys are reported when decoding into a map but not into a `yaml.Node`**, at any depth — hence the separate duplicate-key pre-pass.
  - **`reflect.DeepEqual` on `decimal.Decimal` is true for two parses of the same text** and false only for a respelling (`1.50` vs `1.5`). It passes today and breaks the day someone reformats a placeholder; compare field-wise with `decimal.Decimal.Equal`.
  - **In ripgrep, a later `--glob` overrides an earlier one**, so `--glob '!*_test.go' --glob '*.go'` silently includes the very files the negation dropped. The AC11 gate now takes its file set from `go list` instead, which has no ordering footgun.
  - **The permission deny rules reach `Bash` by command text, not only the file tools.** A command naming both `.env` and `.env.example` is refused outright while either alone runs — and a refusal reads nothing like a failed criterion.
  - **`revive`'s `package-comments` fires per package, so the package comment must land in the first subtask**, or every earlier per-subtask commit red-gates on it. A second package comment is gated by nothing: two of them pass lint and vet and simply concatenate, so `doc-convention.md` DOC-2's "exactly one" is honour-system here.

- **Invariants this now relies on:** no balance value has a compiled-in fallback, so an empty-but-valid balance file fails rather than yielding a usable configuration; every failure names its dotted key path or variable; `main` may exit non-zero but nothing on the loader path panics; and a textual gate's hit is evidence to inspect, never a reason to reword the matched text.

## Bot API transport over telego — retries, exact `retry_after`, a window-schedule rate limiter, the base-URL axis (PR #53, 2026-09-04)

- **What landed:** `internal/tg` — the client over `telego`'s low-level generated API with `net/http` and `encoding/json` substituted for its `fasthttp`/`go-json` defaults, the method classifier, the `Gate` seam #22 installs its allowlist into, the window-schedule rate limiter, the caller with its retry loop and typed error, and the `Observation` the §13.2 health surface reads; `internal/tgtest`, an in-process fake Bot API server over `net.Pipe` with scripted 429/5xx/delay/dial-failure behaviours; the optional-with-default `LAB_GAME_TG_*` key class in `internal/config` with `.env.example` extended; `github.com/mymmrac/telego` pinned as a direct requirement; and `key-decisions.md` rewritten for KD-2 plus KD-25/KD-26/KD-27. `cmd/bot` is deliberately untouched — constructing a client nothing feeds would be dead code and an untested wiring path at once.

- **Decisions worth keeping:**
  - **The seam is `telegoapi.Caller`, not a wrapper around the generated methods.** telego's stock caller discards the HTTP status code and reports any 5xx as an untyped error, so the per-method status and 429 counts §13.2 asks for cannot be observed from above it. Replacing the caller is the only layer where those facts exist, and it makes the generated API safe to hand out unwrapped.
  - **One schedule per key holding a *set* of `(count, per)` windows — not composed limiter legs.** "At most one per second" and "at most twenty per minute" are the same kind of constraint. Acquire computes `t = max(now, global.earliest(), chat.earliest())` under one mutex, refuses on deadline **before any mutation**, then commits to every window at that same `t`. Three review rounds of composed legs produced four defects of one shape, each individually defensible per leg; the composition was what broke.
  - **A chat key is ordered, the class-global key is unordered.** A per-chat key owes arrival order (AC30); a ceiling owes none, and imposing one let a backlogged chat hold every other chat behind it.
  - **Never retry on doubt.** A Bot API call has no idempotency key, so a request that went out with no response back is ambiguous and is *not* re-sent; the typed error carries the ambiguity flag for #43 to branch on.
  - **The limiters are charged per attempt and are unconditional across all three base-URL values.** A self-hosted instance does not relax message rate limits (KD-9), so there is no relaxed mode and no branch on base URL in the limiter path.
  - **Tuning values are environment keys carrying compiled-in defaults** — a new class for `internal/config`, bounded to operational tuning only: secrets, the base URL, the allowlist and the two file paths stay required with no default, and no balance number gains a fallback.

- **Traps found:**
  - **`url.Error.Error()` prints the full URL, and the Bot API URL contains the bot token.** `stripPassword` redacts only userinfo. Store `url.Error.Unwrap()` rather than the wrapper — `Unwrap` returns exactly the cause, so `errors.Is` still reaches `context.DeadlineExceeded` — and run rendered strings through a token replacer.
  - **`net/http` retries a POST internally only when an `Idempotency-Key` header is present.** Never set one, or "never retry on doubt" is silently defeated inside the transport.
  - **`MultipartRequest` returns `BodyStream` (an `io.Pipe`) with `BodyRaw` nil**, so a file upload's `chat_id` is unreachable at the caller seam. Hence the three-state target: `ChatNone` (no destination — `getMe`) and `ChatUnknown` (destination unreadable) need *opposite* answers from #22's allowlist gate, and one boolean cannot carry both.
  - **A token bucket sized `burst = count` admits `count + rate·W` per window** — double the configured figure at the shipped default. A bucket is a rate, never a window bound.
  - **`rate.Reservation.Cancel` reclaims nothing whenever a later reservation exists**, so a cancelled call leaves a permanent hole rather than releasing its slot.
  - **Count-based retention is unsound once inserts are no longer appends** — a sorted-insert schedule that keeps "the newest `max(c)`" silently forgets live grants and over-emits. Retention is time-based.
  - **Eviction must be relative to real `now`, never to the instant just granted**, or a far-future grant makes the schedule forget an early member of a simultaneous burst.
  - **The transport keys must not join the unexported `envKeys()`** — two existing suites iterate it and assert every member is required. Append in `EnvKeys()` only, mirroring the file-path keys. `.env.example` must land in the *same* commit as the loader, because the disjointness test asserts the two key sets are equal.
  - **A red-first variant that cannot go red is worse than none.** One shipped here: a truncated pacing interval could never admit an extra emission, because the quota window already forbade it. A variant is only evidence when it has been seen to fail.

- **Invariants this now relies on:** no chat is exempt from the per-chat limiter by construction, including private chats and calls whose body cannot be decoded; every submitted call ends in an emission or a returned typed error, never in silence, and nothing is discarded to relieve pressure; the bot token appears in no rendered error, observation or fixture; limiter state is in-process only — no database, no disk, no migration, with #43 owning anything that must survive a restart; and each rate-limit default traces to a figure with a published source, with classes whose figure has none left unbounded rather than throttled against an invented number.

## Postgres task scheduler — `scheduled_task`, the `SKIP LOCKED` worker, one-shot and recurrent tasks (PR #54, 2026-09-05)

- **What landed:** migration `00002_scheduler.sql` — `scheduled_task` with its live-scoped identity index, the `deferred_task` / `recurrent_task` basis tables, and `journal_entry`'s arc widened to four columns; `store.DeferredTask` / `store.RecurrentTask`, which make `PostingBasis` a four-implementation sum type; `internal/scheduler` — the handler registry with its one-shot and recurrent declarations, `Schedule`, the worker's discovery / per-id re-claim / execute / settle cycle, the failure policy, the per-task execution deadline with its deferred settlement, `Reconcile`, and the observation seam #23 reads; the second optional-with-default environment class, `LAB_GAME_SCHEDULER_*`. No production handler ships — the raid timer edges (#36), corpse evaporation (#40) and the day close (#45) each bring their own. `cmd/bot` is untouched: #24 owns the composition root.

- **Decisions worth keeping:**
  - **Discovery is one statement; each task then gets its own transaction.** A batch transaction with a savepoint per task was designed, reviewed, and **withdrawn** — under it a late task's deadline breach discarded an early task's already-committed effects, which is exactly the durability `~/lab-private/DESIGN.md` §11 buys with "одна транзакция со своими эффектами". The derived documents that spell that cardinality out were the signal, not the target: the shape changed rather than their wording.
  - **Savepoints are raw SQL on the worker's own `pgx.Tx`.** `pgx.Tx.Begin`'s pseudo-nested transaction sets `sp.closed = true` unconditionally after its `release savepoint`, so a failed release leaves `sp.Rollback` returning `ErrTxClosed` without ever issuing `ROLLBACK TO SAVEPOINT` — the recovery the design prescribed was unreachable through the API it named.
  - **`FOR NO KEY UPDATE`, and it is not a throughput decision.** It is the weakest lock that expresses what a claim does; a one-shot's `DELETE` takes `FOR UPDATE` strength at the moment it needs it. The equivalence of the two modes rests on *no foreign key anywhere referencing `scheduled_task`* — a condition wider than AC27 enforces, which covers basis-document tables only. An FK from any other table would pass every criterion here and silently start minting multixacts.
  - **Every future `run_at` comes from a settlement instant, never the claim instant.** The execution instant keeps one job: the lag the health dashboard reads.
  - **A deadline breach settles.** It counts an attempt through a guarded, non-blocking deferred settlement drained before the next discovery — the alternative left the row due with no attempt counted, which retries for ever with neither backoff nor cap.
  - **No liveness protocol.** No `picked` column, no heartbeat, no revival: a worker that dies mid-execution aborts its transaction and the row is simply still due. The residual case a transaction cannot heal is a handler that *hangs*, and that is answered by a bounded deadline, not a lease.

- **Traps found:**
  - **`~/lab-private/DESIGN.md` carries `FOR UPDATE` twice.** Line 310 is the scheduler's claim query; **line 147 is §3.5's `SELECT session FOR UPDATE`, the raid-session FSM guard.** A document-wide substitution silently changes the documented lock mode of a different machine. Line 311's bare `SKIP LOCKED` is a third sweep hit that names no table.
  - **CI's relative-link gate is a raw regex over markdown text and does not honour code spans** — a correctly backticked example of a link still fails it. Its own escape is a target containing `<`.
  - **`internal/store/migrate_test.go` goes red on the table list and the migration count, but not on the index list or the CHECK map** — the first is a presence loop, the second matches `num_nonnulls` by substring. Both must be extended by hand, and no gate will remind you.
  - **A resolution table is read more carefully than the section it points into.** Two descriptions of mechanisms that a later round had replaced survived four review rounds and a full implementation pass, because the tables truthfully said the change had happened.
  - **`pgx` does carry a `time.Duration` → `interval` codec** — `now() + $1` works. What genuinely fails is `SET LOCAL statement_timeout = $1`; use `set_config(name, $1, true)`.

- **Invariants this now relies on:** a stale task dying on its guard is a third outcome class, distinguished from failure everywhere it is observed; a recurrence is one row moved forward in place and never reaches a terminal state, while a one-shot is deleted on completion and does reach give-up; scheduling twice is refused by the database rather than by a code path that checks first; the scheduler moves no balance and writes no posting of its own — it ships the basis documents that mechanics post under; and `AC30`'s guarantee is conditional on handlers propagating the context they are handed, which is stated in `Handler`'s doc comment and driven as a negative test case.

## Event log — the `event` table, the §13.4 dictionary, and the MVP SQL views (PR #60, 2026-09-06)

- **What landed:** migration `00003_event_log.sql` — the `event_volume_class` enum, the seeded `event_type_definition` registry carrying §13.4's dictionary in declaration order, the append-only `event` table whose four §13.4 dimensions are columns over a JSONB payload, `journal_entry`'s arc widened to five columns, and the five MVP §13.3 views (`metric_activation_funnel`, `metric_retention_daily`, `metric_death_by_depth`, `metric_faucet_sink`, `metric_notification_per_chat_day`); `store.Event` as a fifth `PostingBasis` implementation plus `store.AppendEvent` for the no-posting majority, and `ErrUnknownEventType`; the Go registry mirrors and their ordered element-for-element database comparison; `~/lab-private/DESIGN.md` reconciled with its own §11 — the log table named `event` and the game event registered as a basis type. Nothing emits an event: each mechanic brings its own, in its own PR.

- **Decisions worth keeping:**
  - **The activation funnel attributes a player through their own `player_started`, not through the raid's chat.** The owner's call, and it removes an obligation rather than recording one: no future PR owes `chat_id` on `raid_started` for §13.3's headline number to work. The earlier construction read the raid's chat, which would have returned a zero funnel with every gate green if #36 shipped without that column — and this task's own fixture would have passed regardless. Validated on a fixture where every `raid_started` carries a null chat, so the raid's chat is provably unread. Accepted cost: a player active in several chats is credited to the chat they started from; §16.7 and #30 own membership.
  - **The registry is a seeded catalog table, not a Postgres enum — and the volume class is an enum.** The asymmetry is the point: `TestMigrate_hygiene` forbids an `ADD VALUE` file from doing anything else, so an enum registry would cost every future mechanic two migrations with a window where its type has no class. A new type is routine; a third volume class is a rare policy change that wants its own migration anyway.
  - **`event.type` is a `text` foreign key to `event_type_definition (code)`, not a smallint id.** The stated consumer is a Grafana Postgres datasource writing ad-hoc SQL: `WHERE type = 'death'` beats a join. `event_type_definition.id` exists solely to carry §13.4's declaration order so the mirror comparison is ordered rather than set-wise, and is referenced by nothing.
  - **A view's column set is as durable as a table's.** `CREATE OR REPLACE VIEW` can only append; dropping, renaming, reordering and retyping each fail with `42P16`. The design therefore fixes every view's column names, order, types **and row set** — the row set being precisely the half Postgres does not police.
  - **The event basis carries no idempotency key.** Unlike `player_operation`'s `ON CONFLICT (source, operation_id)` → `ErrAlreadyPosted`, two `Post` calls under the "same" event write two event rows and two journal entries. Stated for mechanic authors rather than left to discovery, alongside the 1:1 arc: one event backs at most one `journal_entry`, so a mechanic moving balances twice needs two events.

- **Traps found:**
  - **`information_schema.tables` reports views alongside base tables**, so the existing exact-table-set assertion breaks on the first `CREATE VIEW` in a way that reads like a spurious failure. It needs a base-table filter, and the views need their own exact-set assertion.
  - **`count(…) / count(…)` is integer division**, so an uncast ratio renders `0` for every value below 1 — a plausible wrong answer rather than an error, which is worse than the division-by-zero and empty-`FILTER` traps beside it. Found by probing, not by review.
  - **A wrong-but-existing issue number clears the citation guard**, which checks that `#N` resolves and not that it is the right `N`. An emitter attribution naming the wrong issue passed every gate; the repair was to attribute emitters only where an issue title actually names one.
  - **Most of the store suite stays green on the new schema.** Only the table list and the `goose_db_version` count go red; the enum map is a hard-coded literal ranged over, the index list is a membership loop, and `journal_entry_exactly_one_basis` is matched on the substring `num_nonnulls`, which the four-column form already contains. "Suite green" is not "requirement discharged".
  - **`TestFailurePolicy_oneShotAttemptsGrowAndGiveUp` in `internal/scheduler` is a pre-existing flake** that fails roughly one full `-race` run in three, and **isolation is not a valid probe for it** — 25 of 25 isolated runs were green while the same assertion fails under parallel load. Reproduced on the base commit in a clean worktree; filed as #59.

## Update ingestion — long polling, dispatch, operation idempotency, the chat allowlist (PR #66, 2026-09-07)

- **What landed:** `internal/ingest` — the poll/dispatch/retry loop (`Options`/`New`, `PollOnce`, `Run`), the `Kind` table over `telego.Update`'s payload fields with its date and chat extractors, `IDSpace` and the unexported `operation_id` builder, `Handler`/`Update`/`Route`/`Router`, the guarded-monotone offset and the payload-free give-up store, the observation seam (`Outcome`, `Observation`, `LoopObservation`, `Observer`) with no exporter, and the outbound `tg.Gate` implementation with its player lookup and positive-only cache; migration `00004_ingest.sql` creating `ingest_offset` (guarded singleton, seeded) and `ingest_dead_update`; `store.Queryer` and `store.PlayerExists`, the package's first owner read; `config.Ingest` and the `LAB_GAME_INGEST_*` tuning keys; and `internal/backoff`, into which `internal/tg`'s and `internal/scheduler`'s duplicate ramps were folded and then deleted. Nothing routes an update: each mechanic registers its own handler, in its own PR, and `cmd/bot` stays a scaffold.

- **Decisions worth keeping:**
  - **The gate asks *who* the destination is, never *what kind of chat* it is.** `ALLOWED_CHAT_IDS` governs group and channel traffic; a DM is permitted because the id resolves to an `owner` row of `kind = 'player'`. The kind belongs in the predicate, not just the id: `owner`'s unique index is on the pair `(kind, telegram_id)` and a chat's own id lives in the same column, so a `telegram_id`-only lookup would match every chat the bot was ever added to and void the allowlist entirely. The obvious alternative — read the sign of the `chat_id` token — is refused outright and recorded as refused: `Chat.Type` is inbound-only and `Chat.ID`'s documentation states no relation between a chat's kind and its id's sign, so the convention is uncitable.
  - **A handler must not issue an outbound call permitted only by a row its own uncommitted transaction created.** The gate reads on a pool connection, so under READ COMMITTED it cannot see the loop's open transaction — and §1's onboarding (button → Start → owner row → DM) is exactly one update that creates the row and addresses the reply to a chat outside the allowlist. The rule holds even if the gate were made transaction-aware, because a Telegram send is not rollback-able: a message justified by a row that later rolls back has already reached a real person. #43's notification queue is the post-commit route.
  - **`ingest_offset` stores `next_update_id`, not the last settled `update_id`.** `GetUpdatesParams.Offset` is defined as one greater than the highest identifier received, so the `+ 1` lives in the advance statement and the stored value is transmitted verbatim. The other reading produces a permanent live-lock — the same update re-fetched every cycle, settled as a duplicate, the guarded-monotone advance never moving — whose only symptom is §13.2's idempotency-hit counter, which is documented as ordinary traffic.
  - **A poll failure is observed and the loop continues; `Run` returns non-nil only on cancellation.** Transposed from `internal/scheduler`'s worker without variation. No consecutive-failure ramp: the transport layer has already retried and backed off before `PollOnce` sees anything, so the poll interval alone bounds the rate.
  - **Idempotency stays the basis document's unique constraint, caught at the handler's `store.Post`.** The loop derives the key and classifies `store.ErrAlreadyPosted` by sentinel; a duplicate consumes no retry attempt. The consequence, stated rather than left to discovery: an update that moves no balance writes no document, so its non-ledger effects replay in full.

- **Traps found:**
  - **The shipped scheduler suite is *invariant* to a missing one-based→zero-based translation at `settle.go`, not blind to it.** Both assertions over a persisted retry `run_at` compute their expected value through the very function the call site calls, so they move together: a byte-identical-assertion rule and a green `make verify` are both compatible with every retry delay silently doubling. Blindness would be cured by adding any test; invariance is cured only by an expected value computed *outside* the function under change. The fix was a literal one-based ramp landed and confirmed green first, then the wrong delay written at the call sites over a `cp` backup and required to go **RED** before the re-point — a green probe was defined as a STOP.
  - **A mutation probe that does not compile is the same failure as one that cannot go red.** The first form of the probe called `Exponential` while `func backoff` still stood; no file of `internal/scheduler` can import `internal/backoff` in that state, because the name collision is package-wide rather than per-file. Rewritten in the shipped ramp's own units as `backoff(k+1, …)`.
  - **`encoding/json` erases an *empty* slice under `omitempty`, not only a nil one.** `allowed_updates` absent means "reuse the server's previous setting" — hidden state outside this repository — so the loop transmits a one-element sentinel (`shipping_query`, an id space this bot cannot receive) when no route is registered. The same tag sits on `GetUpdatesParams.Offset`, so a stored offset of `0` is legitimately absent from the request body and must not be asserted present.
  - **`CallbackQuery` carries no `date` field**, so §13.2's star metric is undefined for that update kind. The observation states the absence rather than reporting a zero duration, which would be indistinguishable from a healthy poll.
  - **The scheduler suite assumes exclusive database access, and says so nowhere.** Point every package at ONE shared Postgres — which `LAB_GAME_TEST_DSN`, the documented escape hatch, is exactly how you do — and `go test -race ./...` fails roughly half the time, in four different tests (`reconcile_test.go:365`, `worker_test.go:194`, `deadline_test.go:168` with a `statement_timeout`, `observe_test.go:121` with an off-by-one failure count). Under testcontainers' per-package servers the same command is green run after run, and CI has no `services:` block, so CI never sees it. The failure looks like a defect in whatever changed last; it is contention. Check which provisioning path the run used before believing it.
  - **A RAID scrub starves container `initdb` past testcontainers' 60s wait.** Every database-backed package then fails with `"database system is ready to accept connections" matched 0 times` — four FAILs that describe the host, not the tree. `LAB_GAME_TEST_DSN` against a hand-started server is the documented way through, and it is worth checking `/proc/mdstat` before believing a sudden whole-suite red.

So neither reading the node's line nor offsetting from it is correct; the extractor searches for the comment text in the direction each field fixes, and escalates an unreconciled comment to an instrument failure rather than guessing a line. Nothing mechanical covers them; the convention records that they are review-judged, and review is what found them.

Restored on the owner's ruling. The distinction is not pedantry: the criterion that the sweep moves no statement is what makes the diff reviewable at all.

## Shared PostgreSQL test server — one server for the whole run, containers as the fallback (PR #72, 2026-09-08)

- **What landed:** `internal/testdb/server.go` — the provisioning that was buried in `Main`, now an exported API (`ServerOptions`, `StartServer`, `Server` with `DSN` / `Stop`, the capacity `Probe`, `DSNEnv`, `SharedContainerName`) plus the `Ceiling` formula and the `Binaries` manifest constant, with `Main`'s container branch re-expressed over it. `cmd/testpg` — the wrapper every gate now runs its test invocation through: it passes a caller-supplied DSN straight down, otherwise reuses a long-lived server named by a locator file under the scratch directory, otherwise starts an anonymous container sized by the ceiling and removes it on every exit path. `--up` / `--down` create and remove that long-lived server; `--clients` and `--parallel` feed the ceiling. `make test` and `make test-race` route through it, and so does the coverage ratchet's own measurement, placed after the ratchet's skip decision so a commit that stages nothing coverage-moving still starts nothing. `make test-fallback` keeps the per-binary container path executed and CI runs it in a job of its own, Test fallback; `make test-db-up` / `test-db-down` hold a server across commits; `make test-contention` is the probe that induces cross-package load. The scheduler suite's wall-clock constants were classified and retimed. KD-20 carries the arithmetic and a corrected consequence clause; the provisioning story is in `go-test-conventions.md` and `AGENTS.md`.

- **Decisions worth keeping:**
  - **The connection ceiling is computed, not a literal.** Every term but one scales with the host's core count, because `go test` defaults both its package-level and its subtest parallelism to `GOMAXPROCS` — so a number that is right on a sixteen-core machine is wrong on a sixty-four-core one. The formula multiplies clients by the database-backed binaries by that parallelism by the per-schema pool cap, plus slack for reserved and pool-oversized connections, floors at the image's own default and **refuses** above a measured maximum rather than clamping silently. A manifest test derives the binaries term from the tree, so adding a database-backed package cannot silently under-size the server.
  - **A shortfall gets a different answer on each path, because the wrapper's authority differs.** On a caller's own DSN it reports and runs — the contract is that the gates execute against the server the caller named, and exhaustion was always loud; what was missing was the diagnosis. On a discovered long-lived server it falls through to its own container, because the locator is this change's convention and there is an alternative. On a server it started itself the case cannot arise.
  - **`--down` removes only a server this project started.** The reaper is disabled for the long-lived container precisely so it survives the process that created it, which means the reaper will not remove it either; the locator file is the record of ownership, and a server found rather than started is never touched.
  - **A fixed host port was rejected on the library, not on taste.** The container runtime binding is parsed as a port range with no host-side form, so a fixed binding would need a lower-level modifier hook and promote an indirect module to a direct requirement. The locator makes an ephemeral port cost nothing.
  - **Every wall-clock constant in a database-backed suite is either an instrument or the subject, and they are treated oppositely.** An instrument is a patience budget — made generous, or replaced by polling the condition. The subject stays exact, with its reference instants read from the database clock around the operation. One value is both, in different tests, which is why the widening is per test and never an edit to a shared configuration helper.

- **Traps found:**
  - **A gate whose command can be served from the test cache is a report, not a gate.** `make test-fallback` was written without `-count=1`. Measured: a second invocation returned green having started no container at all, every database-backed package answered `(cached)`. The path itself was fine; the instrument that exists to keep it fine could not fail. The same reasoning was already written down for the contention probe's load loop and was simply not carried to its sibling.
  - **A `TestMain` that reads configuration before `m.Run()` is invisible to the test cache, and this one does.** `testing.M.Run` opens the log `cmd/go` reads to decide whether a cached result still applies; `testdb.Main` reads the DSN variable and *then* returns `m.Run()`, so the read is never recorded and the variable is in no cache key. Measured with the cache cleared: a package re-run under a different DSN, and again with the variable cleared entirely, answers `(cached)` both times. So the shared and fallback regimes share cache entries — the reason the fallback gate needs its flag — and no reasoning may treat a changing DSN as forcing a fresh run. Three live documents and one design decision asserted the opposite before self-review measured it.
  - **The shared regime moves the coverage number systematically, and the ratchet's band is thin.** Under one shared server the container-provisioning branch of `internal/testdb` is executed by no test, so the recorded mark has to be re-centred inside whichever commit moves it. Assume it blocks rather than planning around a measurement taken on a tree that does not yet contain the change.
  - **`go test` swallows a passing package's output, so "no container was created" can be a property of the observation.** Checking the fallback path by grepping a non-verbose log finds nothing whether or not containers were started; the runtime's own container list, or `-v`, is what actually answers.
  - **`go run` flattens the child's exit status.** A program exiting with a specific code under `go run` surfaces as exit 1 with the real code on stderr; built and run directly it surfaces exactly. Non-zero is preserved either way, so no gate mis-reports green — but any recipe that branches must branch on zero versus non-zero, never on the value.
  - **The recorded exclusive-access trap did not reproduce at its original settings on this machine.** Only an artificially tight budget produced the red that demonstrates the probe can detect contention. That is evidence about this host and about the intervening tmpfs and backoff changes, not a retraction — and it is why the demonstration reverts an instrument deliberately rather than waiting for a failure to appear.

- **Invariants this now relies on:**
  - The wrapper is the only thing that provisions; `testdb.Main` still prefers an already-set DSN and returns before it reaches the container path, so no test knows which regime it is running under.
  - A green contention run counts as evidence only after the probe has been shown able to go red, and only when neither captured log carries the connection-exhaustion condition. A run that carries it is an instrument failure and is thrown away; a run with no failure at all is inconclusive, never a pass.
  - The ordinary gates keep replaying from the test cache exactly as they did before, on every provisioning path. `-count=1` belongs to a gate whose claim the cache key cannot see: one that exercises a particular provisioning path, or one that asserts a property of the run's *conditions* rather than of the code. Both kinds are here — the fallback gate is the first, and both of the contention probe's children are the second, the foreground race gate included, since its exit status is the probe's whole verdict.

- **What landed:** `internal/health` — the health surface. An explicitly constructed `prometheus.Registry` handed to every registration, with no use of the client library's global default registerer and no `promauto`; one adapter per consumer-declared observation seam (`tg.Observer`, `scheduler.Observer`, `ingest.Observer`), each mapping its own label values in exhaustive switches rather than delegating to a source package's rendering; a pgx pool collector over a `func() *pgxpool.Stat` accessor read during `Collect` rather than from a cached snapshot; the Go runtime and process collectors; a `promhttp` handler on its own `http.Server` at `/metrics` with an exported start and shutdown the caller owns; and the two-leg `getMe` canary — own instance and cloud reference — driven by an in-process ticker that touches neither Postgres nor the scheduler. `internal/config` gained the `LAB_GAME_HEALTH_` class (metrics address, canary interval, the cloud leg's own token as a `Secret`, the cloud base URL), every key optional-with-default. `internal/repotest` — the module's one repository-root resolver for tests, into which every per-package copy was folded. `ai-docs/alert-contract.md` fixes the alert names, expressions, condition shapes and severities the infrastructure pass wires against, and fixes no threshold.   - **The cloud canary leg carries its own cloud-side bot token, never the production one.** §13.2 asks for a cloud reference probe and §12.2's runbook keeps the production bot logged out of the cloud; §12.5 already places a separate bot there.   - **A scoping measurement that searches a proxy is not a measurement of the class.** The repository-root consolidation was scoped three times: first by identifier, then by `runtime.Caller`, each time asserted complete and each time missing members. The durable form is to define the class by mechanism — a helper that ascends from its own source file's location is in, one that asks git is out — and the acceptance criterion now says so, which is what makes the guard's "and no other file" clause provable.

Every discriminating proof runs over a temporary copy, because a proof that mutates the working tree leaves it dirty and the coverage ratchet blocks on that before any assertion is reached.

Without it a swap inside the prober would have passed every test in the package.

## `cmd/bot` composition root — wiring, the migration policy, graceful shutdown (PR #75, 2026-09-10)

- **What landed:** `cmd/bot` stopped being a scaffold. `assemble` builds every subsystem in one place from the validated configuration and appends an ordered closer as each step takes something that has to be given back; `serve` waits on the registered signal channel or the first runner return and hands off to `drain`; a `migrate` subcommand applies pending migrations under the production lock and constructs nothing else. `internal/store` gained the liveness migration, `MigrateOption`/`WithAdvisoryLock`, `ProcessLockID` and `HasPendingMigrations`; `internal/scheduler` gained `Liveness` (the restart-hygiene shift) and `(*Worker).Stop`; `internal/ingest` gained `(*Loop).Stop` and the two-context `PollOnce` split; `internal/health` gained `ReadyFunc`, `ServerOptions`, the readiness path beside the metrics path, and the process-identity collector; `internal/srcguard` holds the source-walk guard support the hand-rolled copies folded into; `internal/testdb` gained `SchemaDSN`. `cmd/importguard` plus its gate turns the container-runtime import invariant from prose into something that fails. `ai-docs/process-lifecycle.md` carries the start-up order with a failure mode per step, and the migration policy in full.

- **Decisions worth keeping:**
  - **Migrations apply at start-up by default, with an opt-out key, and both paths take the same database-held advisory lock.** The instance that loses the race waits and then finds nothing pending — it does not fail. With auto-apply off and a migration still pending the process refuses to start rather than serving against a schema it was not built for, which is also what lets one readiness definition hold in both modes.
  - **The lock is opt-in with a caller-supplied id.** It is database-wide while this module's test isolation is schema-wide, so a lock in the default apply path would serialise every fixture in every binary behind one id on the shared test server.
  - **Signal registration is start-up step 1**, ahead of the listener bind, so no observable readiness can precede it. Assembly itself is deliberately not interruptible: the rollback already gives what a cancel would, and a hung start-up is the supervisor's to bound.
  - **Stopping is a second lever, never a context cancel.** Cancelling the context stops the cycle *and* aborts the work inside it, which is the opposite of a drain. The ingest stop cancels the long-poll call alone; the offset read and every update already fetched keep the parent context and run to completion.
  - **A stop-discarded poll reports an observation with no error field set**, because the health adapter counts poll errors on exactly that field — the naive shape mints a spurious poll error on every clean shutdown.
  - **One ordered closer list is walked backwards by both the start-up unwind and the drain**, so the two orders cannot drift apart; the start-up table's unwind column is a consequence of the list rather than a second copy of it.
  - **The heartbeat tolerates a failed refresh, but not forever** — it returns once the stored instant would have aged past the downtime threshold, counted over its own ticker so no Go clock enters the path. A heartbeat that died silently would make the *next* start read a stale instant and shift every overdue row by the whole gap.
  - **Both instants in the downtime measurement come from the database**, and the shift's transaction takes the singleton liveness row `FOR NO KEY UPDATE` first, so two concurrent starts move the rows once rather than twice. That is the weakest mode which still serialises them — it is what the transaction's own non-key `UPDATE` takes anyway, and it conflicts with itself — and the block-and-re-read it buys is asserted by a test that drives two transactions statement by statement, because the manual's Read Committed sentence about re-reading names only the stronger modes.

- **Traps found:**
  - **`-ldflags -X` sets a string *variable*, never a constant.** The scaffold declared `version` as a constant with a comment claiming the release pipeline overrode it; the claim could not hold as written.
  - **The migration library applies no lock unless one is configured**, and its session locker holds a single connection for the whole apply — which is what makes a session-level advisory lock work over a pool-backed handle.

## Goroutine-leak detection — every test binary ends with a goleak check, and a guard enforces it (PR #86, 2026-09-11)

- **What landed:** `internal/leaktest` — `Main(m, run, ignore...)` and the `Ignore{Function, Anywhere, Reason}` entry, over `go.uber.org/goleak` (a direct requirement since #24).   - **The check wraps whatever owned the entry point, and runs after it.** `testdb.Main` provisions and tears down; the check runs once it has returned, so on the fallback route it looks at the process after the test container has stopped. It adds no window of its own on top of goleak's short retry: a longer wait would pass a goroutine that outlives its test by seconds.
  - **An ignore entry is kept honest by the check, not by review alone.** Refused before tests run: a blank reason, a blank function, a function naming this module's own code. The per-entry pass is skipped on a filtered run (`-run`, `-skip`, `-list`, `-short`), and no gate filters.
  - **The guard walks the tree inside the test process and asks `go/build` which files compile.** A guard that shells out to `go list` stays cached when a package appears; an in-process walk is recorded by the test cache and re-runs. It checks two configurations because `-race` satisfies the `race` constraint: a `TestMain` in a `//go:build !race` file compiles under `make test` and not under `make test-race`.
  - **The fake server's base context is its own, never the test's `Context()`.** The test's context is cancelled before every cleanup, including the teardown consumers register after `New`; the server's own cleanup, registered first, runs last, so the server keeps answering until those cleanups finish.

A cleanup test driven by a body-less GET passes against a half-fix that cancels nothing.
  - **A leak detection has no `--- FAIL:` line.** The binary prints `PASS`, then the report, then `FAIL <package>`. Reproduce it as the whole package with `-count=1` on the route that failed — never with `-run`, which also switches the per-entry pass off.
  - **A log written into the repository's `tmp/` makes the guard miss the test cache.** The guard reads the root's directory listing, and `go test` hashes the stat of every entry of a directory a test opened, so a changed `tmp/` mtime is a changed input. Harmless — an extra run, never a stale pass — but a cache probe must write its logs outside the tree.
  - **Verifying this change surfaced two defects already on `main`:** wall-clock-sensitive tests on the race route failing under machine load (#84), and `make test-contention` red with `cmd/bot`'s migrations losing the advisory-lock connection (#85). Neither comes from the check. A failure is pre-existing when a run of the base commit reproduces it; a green rerun of the branch proves nothing either way.

- **Invariants this now relies on:**
  - Every package with tests has exactly one `TestMain` of the leak-check form under each build configuration the gates compile; a gate that ever sets a build tag of its own needs another configuration in the guard.
  - A goroutine this module's code starts is ended by its owner — a cleanup, a context, a close — before the package's tests finish; an ignore entry is only for a dependency's process-lifetime goroutine.
  - `internal/leaktest`'s non-test code imports only goleak and the standard library, so any test binary can use it without an import cycle.

## Canary limiter refusal label — a refusal decided past an expired deadline reports `timeout`, not `network` (PR #93, 2026-09-12)

- **What landed:** `internal/tg`'s caller now reads `now` into a variable once per retry-loop pass, beside the `ctx.Deadline()` read, and passes that same instant both to the limiter and to a new pure helper that answers which cause the refusal carries. When the deadline had already passed at the moment of the decision, the refusal wraps `context.DeadlineExceeded` and says so in its message; every other refusal keeps the unchanged wait-does-not-fit cause, carrying neither context sentinel. `internal/health` takes no production edit — its failure classifier already maps a `context.DeadlineExceeded` chain to `timeout` — so the canary's label follows from the transport's cause, and a test in `internal/health` is what pins it.

- **Decisions worth keeping:**
  - **The predicate is strict.** At an instant equal to the deadline the limiter still grants a zero wait, so a refusal decided exactly there is necessarily a real-wait refusal and the deadline has not passed. This deliberately disagrees with `context.WithDeadline`, which treats a non-positive duration as already expired: the predicate explains the *limiter's* decision, so it tracks the limiter's boundary, and matching the context's would label a genuine-wait refusal a deadline breach.
  - **The cause wraps `context.DeadlineExceeded` directly, never `ctx.Err()`.** A context cancelled while its deadline is still ahead would yield `context.Canceled`, which the real-wait half forbids; and a deadline context publishes its error from a timer callback, so `ctx.Err()` lags the wall clock under load — the caller would refuse for one reason and label for another.
  - **The message is named in the design, not left to the implementor.** Both `timeout` sources now render the same label, so the log line is the operator's only discriminator; reusing the wait form's wording would have voided that silently, and the end-to-end test asserts the rendered cause, not only the chain.
  - **The retry-wait pre-refusal is left as it is.** That site has a real attempt behind it, so its status and cause are the right classifier there; the asymmetry is intended, not an oversight.

- **Traps found:**
  - **Hoisting the instant above the retry loop would be wrong, not merely stale.** The limiter consultation is a per-pass step: an instant read once would mis-start the fixed-point search, hand the eviction pass a past instant, and mislabel a second-pass refusal against a deadline it no longer describes.
  - **An attempt count of zero identifies the pre-attempt refusal only on the first pass.** A limiter refusal on a later pass carries the attempts already made, so the count is evidence about the first-pass case alone.
  - **A green test is a claim about the test.** The real-wait test is green both before and after the change, so its discriminating power was established against a mutant that drops the already-passed condition rather than against the pre-change tree; the boundary row needed its own mutant (the non-strict predicate), and the reverted call site is what turns the two deadline assertions red.

- **Invariants this now relies on:** the limiter's refusal predicate and the cause helper read one and the same instant, so the decision and its explanation can never disagree; a limiter refusal decided with the deadline still ahead carries neither `context.DeadlineExceeded` nor `context.Canceled`, which is what keeps the canary's `network` label meaning what it says; and the canary's failure classifier stays the single place a transport cause becomes a `reason` value — the label set itself is unchanged, so no alert expression moves.

## Scheduler handler panics and deadline reclaim — a panicking handler is a counted attempt, and a breached row is claimable at once (PR #106, 2026-09-12)

- **What landed:** a new `internal/panicguard` carries the one recovered-panic primitive both handler boundaries call — the recovered value together with the stack captured at the recovery point, a constructor from a `recover()` result, and an `error` rendering, standard library only. `internal/scheduler` recovers around the `Handler.Execute` call alone, on the goroutine that runs it, and settles the panic the way a returned error settles: one counted attempt under the same failure policy, classified by a new `FailurePanic` member that outranks the rolled-back classification, with the rendered panic reaching the existing `last_error` column and no migration. A post-panic transaction pgx will not reuse is routed into the pending-settlement set the deadline breach already uses, carrying the panic kind and the rendered panic as its reason, so the attempt cap engages on the nastiest panic shape too. After a deadline breach the worker terminates the breached task's own backend from a pooled connection, reading that backend's PID before the handler goroutine is launched and carrying it on the breach path; the shipped negative-case test that asserted the row stays locked is reversed, renamed and re-documented. `internal/ingest`'s recovery returns the shared primitive instead of a bare flag, so the stack reaches the give-up row and a log record. Both packages gained an `Options.Logger` the composition root threads in, with a discard handler substituted for nil. The failure-label mapper, the closed-set label guard, the goroutine-ownership allow list and four documentation sites followed.

- **Decisions worth keeping:**
  - **The waiting `pg_terminate_backend(pid, timeout)` form was taken and then reversed out, on a measurement.** It frees the row no sooner than the one-argument form — both send the same signal and the victim dies on the same schedule — while blocking `executeOne` on a structural floor of about a tenth of a second. Its only purchase was a synchronisation point for one test assertion, bought with a real delay in a sequentially-executed cycle.
  - **The waiting form also destroys the failure split.** Under the one-argument form an already-gone pid returns `false` with a nil Go error (expected traffic, debug level) while a permission failure returns `SQLSTATE 42501` (a fault, error level); the waiting form collapses *already gone* and *did not die in time* into one bare `false`.
  - **A handler blocked outside the database stays a contract breach** — the terminate reclaims the goroutine only for a handler blocked *in* the database. The row's lock, though, leaves the exception in both cases: a lock is held by a backend and cannot outlive one.
  - **The stack goes to the log in every case and to the row wherever the attempt leaves the row an outcome** — the owner's amendment, after the design showed the unconditional reading unsatisfiable on three paths: a panic after the breach has already enqueued a deadline settlement, an ingest panic a later attempt supersedes, and an ingest panic on any attempt before the last, since the give-up row carries the last attempt's error.
  - **The terminate's bound is a decided operational constant in Go**, matching the watchdog close bound already there — not a balance value in configuration.

- **Traps found:**
  - **`pg_terminate_backend`'s one-argument form is the two-argument function with `timeout = 0`**; there is no separate one-argument function. With a zero timeout it returns `true` whether the process actually terminated or not, and any positive bound at or below the server's wait step returns `false` on a backend that is already dead.
  - **A claimability figure measured by a Go claimer is the claimer's own detection latency, not the row's residue** — poll cadence, wake and round-trip all sit inside it. An in-server poll puts the release two orders of magnitude sooner. Conservative in the safe direction, but the subject was wrong.
  - **A probe whose claimer connects *after* the terminate hides the race entirely.** Pre-established claimer versus freshly-connected flipped a reproduction from dozens of first-probe misses to none, on one machine — about a millisecond of connect slack is the whole difference.
  - **A shipped test asserted the exact opposite of the new criterion.** The ctx-ignoring negative case required the row to stay locked while its handler ran, and its fixture blocks in the database, so the terminate reverses it. Its doc comment, its name, a `//nolint` reason claiming the connection close is what *finally* releases the lock, and a helper's enumeration of the two pre-existing release mechanisms were all falsified with it.
  - **The terminate races the server's own `idle_in_transaction_session_timeout`**, both armed against the same task timeout, so a log assertion counting entries exactly is nondeterministic where one asserting on the panic's own record by message is not.

- **Invariants this now relies on:**
  - A terminate's success is the boolean, never `err == nil`.
  - The backend PID is read while the pooled connection is still idle — before the handler goroutine is launched — and carried on the breach path.
  - A handler panic is classified before the rolled-back classification in the settlement switch, so the two never collide.
  - The scheduler's `failure` label set stays closed and guarded; a panic is a value of it, never a new metric family.
  - Update ingestion's reported outcome for a recovered panic is unchanged; only the stack was added.
## Item machine — `item`, `item_movement`, and the shared holder address space (PR #107, 2026-09-12)

- **What landed:** the second accounting machine. `00006_capacity_kinds.sql` adds the `slots` and `weight` members of `ledger_kind` and nothing else, because the migration hygiene gate forbids an `ADD VALUE` file doing anything besides. `00007_item_machine.sql` adds the `capacity_role` enum (`free` / `used`), the `account_definition` column carrying it with a partial unique index over `(scope_definition_id, kind, capacity_role)`, the `backpack` scope definition and its capacity account definitions, a backfill of `scope` / `account` / `account_balance` for owners that already exist, `item`, `item_movement`, and the views `item_holder`, `item_chain_break` and `item_capacity_divergence`. `internal/store` gains `Movement`, `Move`, the identity types `ItemID` / `HolderID` with the `NewItem` and `WorldHolder` constants, and a sentinel per refusal condition; `post` gains a `beforeBalances` hook and `Post` becomes the thin wrapper that passes `nil`, its exported signature untouched. The propagation sweep corrected every live surface that named the machine's tables in the plural or called `store.Post` the only mover of a balance.

- **Decisions worth keeping:**
  - **A holder is a `scope` row, not an `owner` row.** The design lists a player's backpack and a player's chest as distinct addresses of the same owner, so the shared address space cannot be the owner. Instancing — a corpse belonging to a particular death — rides on `owner`, whose ids are generated and whose telegram-id uniqueness is partial, so a corpse holder arrives later without relaxing `scope_singleton_key`.
  - **Capacity is a `free` / `used` account pair per holder per kind, and the pair is what makes two criteria true at once.** `CHECK (balance >= 0)` bounds a holder from above only if the balance counts *free* capacity, while "instance count equals the capacity balance" holds only if it counts *occupied*. A move posts `from.free +1 / from.used −1 / to.free −1 / to.used +1`, self-balancing per holder, so the group is zero-sum by construction. This diverges from the design corpus's single "slot remainder", and the divergence is what buys both properties.
  - **Chain continuity is a database invariant, not a code convention.** A self-referential composite foreign key on `(prev_movement_id, item_id, from_holder_id)` forces a movement's `from` to be its predecessor's `to`; a genesis `CHECK` pins the first movement's source to the World scope; and one unique index on `(item_id, prev_movement_id, from_holder_id)` with `NULLS NOT DISTINCT` refuses a fork, refuses a second genesis, wins the concurrency race, and covers the composite key for the index-coverage gate — which a two-column form cannot.
  - **The blanket "no composite foreign keys" of the ledger-core decision is scoped, and the owner ruled so explicitly.** Its stated reason was that such moves are not planned and that the declarative guard would be illusory; neither half transfers here, where a disagreeing `from` is the invariant the machine exists to protect and the constraint demonstrably refuses the row.
  - **`Move` composes `post`; it never bypasses it.** One basis document and one journal entry carry the movements, the derived capacity legs and the mechanic's own postings, so "one document, postings in both machines" is structural rather than checked.
  - **The chain insert runs ahead of the balance updates**, through the hook rather than by reordering `post`. That ordering is what keeps a lost race reporting its own sentinel; see the trap below for what it cost and what it fixed.
  - **An instance carries identity and nothing else.** `item` is a single generated-always id column. Durability is not designed and item statistics belong to their own issue, so the first mechanic that needs a mutable property brings it by forward migration.
  - **The player's storage scope is not created here.** Its binding to a group chat is undecided and waits on the issue that closes that question; shipping the backpack scope alone forecloses neither answer.

- **Traps found:**
  - **Ordering the capacity legs before the chain insert makes a lost race indistinguishable from a full backpack.** Two transactions moving one instance off a holder whose `slots_used` equals the number of racers both reach the same decrement; under read committed the second resumes against the committed value and goes negative, so it returns the overdraft sentinel and never reaches the index that would have named the conflict. Measured on every round of the first test shape. The first fix attempted was to seed a second instance at the holder so the case could not arise — a fixture that removes the case it was written to catch. The real fix is the ordering.
  - **A row lock cannot protect head-ness.** The obvious mechanism — lock the head movement before posting — fails because head-ness is the *absence* of a successor, which no row lock covers: the blocked read returns the stale head after the winner commits, and only a fresh statement sees the new one. The successor index is the serialisation point precisely because it is an index on a shape rather than a lock on a row.
  - **A reconciliation driven from the current-holder view cannot see a holder that currently holds nothing.** A drifted `slots_used` at an empty holder produces no row to report on. The divergence view is a full outer join between the per-holder count and every capacity account for that reason, one shape along from the null-blind comparison the chain-break view was already written to avoid.
  - **Adding enum members breaks existing switches through the linter, not the compiler.** `exhaustive` is enabled and test files are not excluded from it, so two switches in the ledger's own tests failed on the new capacity kinds.
  - **A per-round log is not a test assertion.** A race test that reports which sentinel each round produced tells nobody anything: the gates run the suite without verbose output, so the log is discarded on a pass and a run that quietly stopped reaching the conflict path stays green. The mitigation is a cross-round assertion, not a message.

- **Invariants this now relies on:**
  - Every balance still moves through `post`'s body, which is the single site of the balance update; `Move` reaches it rather than writing beside it.
  - An instance has exactly one holder at every moment, and every movement's source is its predecessor's destination — both refused by the database, not by a caller's discipline.
  - A lost race for an instance reports the conflict sentinel; an overdraft naming a destination's free account is a full holder, and one naming a source's used account is pre-existing divergence that the reconciliation view quantifies.
  - Nothing in the machine branches on a holder's kind. A holder kind the current scope does not use costs a scope definition and its capacity account pair — both halves, since a move refuses a holder missing either — and no code.
  - The append-only source scan covers `item_movement`. `item` is deliberately outside it, because it is an identity table whose definition column a later issue will legitimately backfill.
## World generation core — hex topology and the deterministic chunk generator (PR #115, 2026-09-13)

- **What landed:** new packages, no wiring and no call site. `internal/hexgrid` carries the topology vocabulary — the axial coordinate with its six directions and `Opposite`, the canonical face two neighbours share with `FaceOf` computing it from either side, the chunk with its floor-division `ChunkOf`/`Origin`/`Contains`, and the chunk-grid distance the design chooses over a hex traversal. `internal/maze` carries generation: fixed-width big-endian preimages behind a versioned domain tag, SHA-256 keys domain-separated by a purpose byte, a ChaCha8 stream reached through an unexported one-method interface whose sole constructor is the package's only reference to `math/rand/v2`, reductions implemented in-package so no standard-library mapping change can move a face, `Params` with an enum-indexed weight array, the chunk cell graph, connectivity-guarded island selection, the five spanning-structure algorithms, the extra-passage pass, border-portal selection, and `Cell` as the per-coordinate entry point. `internal/detguard` carries the determinism predicates both packages apply to their own directories — no clock, no `math/rand` v1 or `hash/maphash` or `crypto/rand`, no `math/rand/v2` identifier other than the ChaCha8 constructor, no floating-point type, no `math` import, no float-valued `decimal` member, and no map range the scan can name — map-ness is decided from an identifier's declarations, which approximates a type question, so the guard is a pre-check and the goldens carry the proof — composing `internal/srcguard`'s walker and adding no walk of its own, each predicate paired with a scratch red case. Goldens for the preimage table and for the cell table with a single-weight section per algorithm, a property suite, per-package structural guards, and benchmarks over one cell and over each algorithm. `~/lab-private/DESIGN.md` §16 item 2 records the intra-chunk-algorithm question as closed and §2.2.2 records the decision; `ai-docs/key-decisions.md` gained the world-generation section.

- **Decisions worth keeping:**
  - **The algorithm is drawn per chunk, not chosen once for the game** — the owner's own counter-proposal to the question as first put. The chunk seed settles the draw over weights that arrive as generation inputs, and the drawn algorithm takes its own further parameters from the same inputs, so corridor character is authored per biome. Determinism survives because the weights are inputs like the chunk dimensions already were, not because anything on the path was made to behave.
  - **A cell with any face on a chunk border is never an island.** Islands are drawn from interior cells only, which is what lets a border's portals be a function of the ordered chunk pair alone — and that is what makes the locality bound and the portal guarantee close together instead of each pulling in the other's neighbours.
  - **The prefab boundary splits along the design corpus's own line.** A claimed coordinate's interior faces are the prefab layer's and read as a distinct deferred state — the zero value, so the report is honest rather than a wall the authored interior may contradict — while its border faces stay the portal rule's, identical to what the unclaimed cell across the border reads. The consequence is that the config-and-prefab layer needs no accessor added here: the portals it must stitch to are already what `Cell` returns on a claimed chunk's border ring.
  - **The weight set is an array indexed by the algorithm enum, not a map.** Unknown-key validation then disappears rather than being reconciled with the ban on ranging a map, and an unknown algorithm *name* lands where names are known — the config layer's decoder.
  - **Cross-architecture stability was struck mid-flight by the owner**, on the ground that the game targets one platform for now. The gate that watched it went with it; the mechanisms it watched stayed, because they are what makes the output a function of its inputs at all rather than architecture-specific insurance.
  - **`Algorithm.String()` is production surface, not a test convenience.** It satisfies `fmt.Stringer`, so it governs how the enum renders in every formatted message, and it carries the canonical spelling the golden's algorithm column and the config layer's keys are both written in — which makes a rendering drift visible in the golden.

- **Traps found:**
  - **`go doc` cannot see a test file, and the answer was in one.** The stability of the chosen stream *is* gated upstream — `math/rand/v2`'s own suite carries a golden commented to make sure the algorithm never changes — and an early draft recorded the opposite, pinned to `go doc`. A local golden is a detector; the toolchain axis needed a mechanism, and establishing that the upstream gate exists is what supplied one.
  - **A second architecture is a build-time choice, not a hosted-runner question.** The inference that no run anywhere could exercise one was drawn from the runner catalogue; a `GOARCH=386` build of this module's own tests runs natively, at a different word size, against the generic rather than the assembly implementation of both primitives in the chain. The conclusion was wrong even though the requirement it served was later struck.
  - **Kruskal and Prim draw the same maze when Prim is formulated as a minimum spanning tree.** Minimum spanning trees are unique for distinct weights and both algorithms compute one, so on a shared weight draw they agree edge for edge — measured identical over repeated trials, with a control confirming the comparison could report a difference. Only the frontier-based Prim is a distinct traversal, which is why the set names that variant.
  - **Growing tree at one end of its bias range is the recursive backtracker.** Measured indistinguishable at the noise floor against an independently implemented backtracker, while the other end does *not* collapse onto frontier Prim. The owner ruled edge-condition similarity acceptable and struck the requirement that had been derived from a question rather than from a decision.
  - **A test can be blind to the very class it is named for.** The order-independence scenario shared one generator across both passes, so any state outliving a single `Cell` call — the memo the scenario exists to catch — answered both passes identically. A cross-call memo mutant compiled, vetted, and passed. Giving each pass its own generator makes the mutant fail.
  - **A word search cannot verify a removal.** The commit that added the architecture gate also bumped counts and cross-references that name the job cluster without naming the target, and a pattern built from the target and class names matches none of them. The acceptance is the commit delta, which compares against the tree as it stood rather than against a guess about how the thing is spelled.
  - **`git diff` between two commits reads neither the index nor the working tree**, so an instruction to stage first is inert for it; `git ls-files` is blind only to a file not in the index at all, not to an unstaged edit of a tracked one. Both were asserted the other way before being run.
  - **An empty input set reports the clean answer for any tree.** The first sweep for a live document still framing the algorithm choice as open returned a clean verdict over an empty file list, because the pattern carried only the Latin spelling against a Russian corpus.
  - **A golden's mint is self-consistent when it is wrong**, since the code under test produced it. The mint is read against the island rule and the per-chunk algorithm column, not against the diff's shape.

- **Invariants this now relies on:**
  - Every value generation yields for a coordinate is a pure function of the world seed, the generation inputs, and the coordinate — no clock, no unseeded source, no floating-point arithmetic anywhere on the path.
  - Faces are derived on demand and stored nowhere.
  - Islands are interior cells only, so every border face has two non-island endpoints.
  - A border's key is derived from the canonically ordered chunk pair, so both sides compute it from their own call site without consulting each other.
  - The island-selection connectivity guard reads the chunk-induced subgraph; over the whole lattice a neighbour always reconnects the set and the guard would accept every candidate.
  - The bounded draw is total — a bound of one or zero returns zero and consumes nothing — so the standard library's panicking form is never reached and the index stays empty.
  - Connectivity is built, never repaired: no stage anywhere on the path depends on the order cells were visited.

## World generation rework — hexagonal chunks on a super-lattice, generated a whole chunk at a time (PR #123, 2026-09-14)

- **What landed:** `internal/hexgrid` swaps the rhombic chunk grid (`Dims`, `ChunkOf`, `Origin`, `Contains`) for `Lattice`, the hexagon-of-hexagons super-lattice of radius-R chunks — `Center`, `Locate` and `At` between a cell and its (chunk, local coordinate), `LocalCells` in one canonical order, `Offset`, and `Border`, a border's `2R+1` faces in path order — plus `Chunk.Neighbor` and the cell `Distance` gameplay reads. `internal/maze` stops answering per coordinate: `Generate(ch, typ, neighbors ...Map)` builds one chunk into a `Map` that names its `Version`, `Chunk`, `Type` and `Radius` and answers `Faces` in its own local frame; `NewMap` rebuilds a `Map` from what a stored map holds; `ChunkType` is fabric or gate with a zero value that is refused. The prefab hook, `Cell` and the per-coordinate path are gone. A border draws its portal count between the two portal shares of its `2R+1` faces, rounded up, and places the portals so that none touch. The balance key `world.chunk.radius` replaces `world.chunk.cols` / `rows`, bound below by `maze.MinRadius`. `chunks.golden` replaces `cells.golden`; `derive.golden` did not move. KD-37…KD-40 carry `Amended by #119` clauses.

- **Decisions worth keeping:**
  - **The stored form of a chunk map is #29's, not this task's.** The owner first chose to define it here and then rolled that back as a widening of scope. `NewMap` is an in-memory constructor — chunk, type, version and per-cell faces in `LocalCells` order — with no byte layout; it exists because without it #29 could reach a neighbour's `Map` only by regenerating the neighbour, which is exactly what taking a stored border rules out.
  - **No design and no tests for unreachable extremes.** The owner ruled that the radius is a value they set deliberately and that the `int32` coordinate seam will never be reached by an MVP Telegram game, so there is a lower radius bound and no upper one, and nothing is built for the seam.
  - **The generation version is its own integer, not the hash-chain domain tag.** Bumping `Version` for a generation change leaves `cellSeed` and every already-stored map's content key where they were; tying the two would re-roll stored chunks' content on every bump.
  - **A stored neighbour's border is taken as stored, whatever its version.** `Generate` refuses a neighbour map for the chunk itself, one that is not adjacent, one at another radius and two for the same neighbour — never one at another `Version`, because an old stored border is exactly what a new chunk must agree with.
  - **The prefab hook was removed rather than reshaped.** A later prefab layer brings its own entry point; a guard fails the package if an exported interface, or an exported function taking an interface- or function-typed parameter, reappears.
  - **The super-lattice mapping is a hand-roll, argued.** The packages inspected offer hex coordinates and float pixel conversions but no hexagon-of-hexagons mapping and no enumeration of the faces between two large hexagons, which is the whole requirement; `Lattice` is the one seam a package that gained it would replace.
  - **`internal/config` imports `internal/maze` for `MinRadius`**, which brings `maze` and `hexgrid` into `cmd/bot`'s dependency graph — accepted, and recorded against KD-38.

- **Traps found:**
  - **A chunk's border with one neighbour is a zigzag of faces in two directions.** The neighbour a border cell's face leads into is not always `ch.Neighbor(d)` for that face's `d`, so `Generate` locates the actual neighbouring cell's chunk instead of stepping by direction.
  - **A mutant that trips a parent test's setup `t.Fatal` never reaches the subtests after it.** The first mutant against the stored-neighbour test went RED on the setup check, which proved nothing about the two new subtests; each was seen RED only after a mutant that passed the setup or a probe that let the subtests run.
  - **A `go test -run` pattern that matches no test is green.** A per-AC run passed with one expected name absent because the test was named differently; only checking each name's own `--- PASS` line exposed it.
  - **A test with the design's subject is not the design's test.** The radius refusal and the gate-centre exclusion were tested at `Params.validate` and island-selection level, green and named plausibly, while the design's tests drove them through `New` and `Generate`; a sweep of every test the design names is what found the gap, not the suite.
  - **A decision record written while code is mid-change can go false when the change lands.** KD-40 was worded to hold whether or not the zero-capacity island refusal survived, and still described the refusal as present after it was removed.
  - **An empty extraction reads as a clean sweep.** A range over KD headings returned nothing because key decisions are bold paragraphs, not headings, and the stale-vocabulary check over that empty text reported no hits.

- **Invariants this now relies on:**
  - A chunk's map is a pure function of the world seed, the generation inputs, the chunk coordinate, the chunk type and the neighbour maps it is generated against; generating a region with no neighbour maps and generating it chunk by chunk against neighbours rebuilt through `NewMap` yield identical maps.
  - A border depends on its two chunks alone — never on either chunk's type and never on a third chunk — and both chunks enumerate its `2R+1` faces in the same order, where consecutive faces are exactly the faces that share a vertex.
  - A border's portal count lies between the lower and upper portal share of its faces, each rounded up; the lower bound is at least one portal and the upper at most `R + 1`, and no two portals of one border share a vertex.
  - Islands are never border cells and never a gate chunk's centre; island capacity is checked once, against the gate chunk's smaller capacity, so one valid input holds for every chunk type.
  - `maze` imports only an allowlist, so no database or store package can enter generation.

## Spiral gate placement and nearest-gate depth — `internal/gate`: the spiral order, the next gate, and an exact ring-search depth (PR #124, 2026-09-14)

- **What landed:** a new package, `internal/gate`, over `internal/hexgrid` and the standard library. `Spiral` is the infinite gate-placement order from the centre chunk, and `SpiralIndex` its closed-form inverse, recovered from a chunk's own coordinates. `Next` returns the first chunk in that order that is not created and keeps at least `k+1` chunks from every gate, and refuses a negative `k` with `ErrNegativeK`. `NewSet` builds a gate `Set` (refusing a negative radius with `ErrNegativeRadius`), and `Set.Depth` returns the hex-formula cell distance from a cell to the nearest gate chunk's centre, or `(0, false)` for a set with no gate, the zero `Set` included. Property, table and internal tests, and reporting-only benchmarks. KD-41 records the package and its decisions; KD-38's consumer sentence and `context.md` now name `internal/gate`.

- **Decisions worth keeping:**
  - **`k` is the gap between gate chunks, the gate chunks themselves not counted.** Two gates lie at super-lattice distance of at least `k+1`, so `k = 0` lets neighbouring chunks both hold gates and fills concentric rings. The owner confirmed this reading in the interview.
  - **Each ring starts mid-side, rounding down — the owner's decision, not a packing argument.** Ring `n` starts `⌊n/2⌋` steps from its corner `(n, 0)`, at `(n, −⌊n/2⌋)`. The design fixed the start direction as `DirE` and the turn as the canonical `Direction` order. Once #29 stores gate indices, this orientation is a data contract: changing it re-places later gates and renumbers stored indices, which is a migration, never a refactor.
  - **`Next` scans a bounded prefix and falls back to a chunk that is valid by construction.** With `M` the outermost ring of any created or gate chunk, it scans rings `0..M+k` and otherwise returns ring `M+k+1`'s first chunk, which lies beyond every created chunk and, by the triangle inequality, at least `k+1` from every gate. So it is total with no unbounded loop.
  - **Depth is an exact ring search with a lower-bound stop rule — no BFS, no scan over all gates.** Around the cell's chunk it widens ring by ring and stops once the best distance found is at most `L(s) = ⌈s·C/(2R+1)⌉ − R`, with `C = 3R²+3R+1`. The rings it visits are bounded by the returned depth and the radius, never by the number of gates. That bound rests on the proof and on its tests, not on `detguard`, whose map-range check sees only what a name-based pass can see.
  - **The gate set is built once per gate snapshot.** Where that snapshot lives, and whether depth is stored or computed on read, is #29's.

- **Traps found:**
  - **A residue class is not a regularity test.** Judging simulated gate layouts by `(q−r) mod 3` reported seams in corner-start layouts that are perfectly regular lattices, because that class is invariant only on the index-3 lattice. The instrument that answers the question is a coset test — the gate set equals one translate of the lattice its nearest-neighbour vectors span — with both of its failing branches seen red on constructed layouts.
  - **The rounding of a mid-side start is part of the layout.** In simulation, ceil and floor rounding place gates differently at `k = 2`, and floor keeps a regular lattice at every `k` tested.
  - **Scratch Go under `tmp/` is walked by `./...`.** A design probe there failed the module-wide lint gate while `git status` stayed clean. Scratch Go goes under a `_`-prefixed directory.
  - **`detguard` treats a map-typed struct field's name as map-typed across its whole file.** A `Set` field named `gates` beside a `range gates` over the constructor's slice would fail the determinism guard over code that ranges no map; the field is `members`.
  - **A doc comment can overstate the proof it paraphrases, and every gate stays green.** `Set.Depth`'s comment first claimed the search never passes the nearest gate's ring, and `Next`'s that its fallback is unreachable, while a table row returns it. Both were found only by checking a decision record's claims against the code.
  - **A mutant must build before its red counts.** The first "stop at the first hit" mutant did not compile, which tested the compiler and not the suite.

- **Invariants this now relies on:**
  - `Spiral` lists every chunk exactly once, ring by ring, and `SpiralIndex` inverts it exactly.
  - `Next` never returns a created chunk or a chunk nearer than `k+1` to a gate, and it returns for every finite input and every `k ≥ 0`.
  - `Set.Depth` equals the least hex distance from the cell to any gate chunk's centre however far that gate lies, and gates beyond its search bound add no work.

  - **The generator's constructor is the single source of every cross-field refusal.** Its validation is unexported and reachable only through it, so restating those predicates in the schema would be two copies of one rule drifting past a green build.
  - **The agreement between the authored profile and the ledger enum is a test, not a start-up check** — the world set is tracked in this repository, so it is a repository fact a gate holds, and the production package keeps its database-free import graph.
  - **A resource kind is permanent after merge.** The owner approved the token triple knowing a rename later is a new member plus a dead one, never an edit.
  - **The configuration's `id` is the canonical world identifier** — maze persistence inherits it rather than minting its own, which makes it a shared data contract rather than a local name.

- **Traps found:**
  - **A doc-comment sweep that names a phrase cannot reach a site that spells the key.** The rule asserting the chunk radius ships in the balance file sat in an instruction file, where left standing it would have told future work to put the radius back; the sweep only reached it once the pattern spelled `world.chunk.radius`.
  - **`errors.Join` results must not be re-wrapped in a single `%w`.** The helper that walks for a keyed error descends through a joined list, not through a further single-unwrap layer, so one outer wrap makes a real refusal invisible to the test that looks for it.
  - **Stale gate logs in `tmp/` collide with a later run's names.** Files dated days earlier were within one careless glob of being counted as this run's evidence; mtimes are what separated them.
  - **A per-schema error string shared by two schemas names the wrong schema.** The walker hard-coded "not a recognised balance key" for both sides until it became a noun the caller supplies.

- **Invariants this now relies on:**
  - No world key has a compiled-in fallback: every one is required, and an authored zero is distinguishable from an absent key.
  - A world that loads is a world a generator can be built from — stronger than "the file parses".
  - The balance configuration carries no world value, and no world's generation input or `k` is read from it.
  - A later content layer (prefabs, the entrance prefab, boss areas, ruins, NPC outposts) adds its own section and redefines nothing this format already states.

## Maze persistence — the world becomes rows: lazy whole-chunk creation, gates, discoveries, and a depth computed on read (#140, 2026-09-19)

- **What landed:**
  - `internal/world`, the persisted world over `internal/hexgrid`, `internal/maze` and `internal/gate`: `Open` with its seed refusal, `EnsureChunkAt` reading unlocked and creating whole, `ActivateChat` allocating a chat's gate, `Depth`, `RecordDiscovery` on the caller's own transaction, and the stored-map byte codec with its golden. Nothing imports it yet — the activation, `move` and look edges that call it are #36's.
  - One forward migration creating `maze`, `chunk` and `node_discovery`, with the chunk type and the creation cause as enums of this package's own, a `CHECK` pairing the gate type with a non-null gate chat, the partial unique index that gives a chat one gate per maze, and a **separate** partial index covering the gate-chat foreign key.
  - The `chunk_created` event, registered by the migration in the type table and mirrored in the ledger package's catalog in the same change: the chunk type and the creation cause in separate fields, the generation version, the dictionary's dimensions, and for a gate chunk its spiral index and its ring.
  - The chunk map is stored rather than regenerated — one byte per cell in the lattice's own local-cell order, one bit per face, with the generation version on the row.
  - `ai-docs/domain-invariants.md` gains the world's section: the lock-ordering rule, its *explicit*-lock carve-out, the pinned isolation level, the never-updated-chunk invariant an unlocked read rests on, and the two-connection cost with its mitigations.
  - Per-cell state and the union-by-chat knowledge view were deferred on the owner's ruling, each with its reason; the personal discovery record they build on ships here.

- **Decisions worth keeping:**
  - **Depth is computed on read, never stored.** A later gate lowering an earlier cell's depth then holds by construction rather than resting on an invalidation sweep, and "a crafted door can never reach the metric" becomes a property of the input *type*: the metric takes gate chunks, and a door is bound to a cell and can never be one. There is no filter for anyone to forget.
  - **A row lock on the maze row, in its own short transaction, at an explicitly pinned READ COMMITTED.** The ordering against a raid session's own row lock is settled by a rule instead of an order: a chunk-creating transaction takes the maze row lock and no other *explicit* lock, and a session transaction never takes the maze row lock — one lock on one side, none on the other, so there is no cycle to order. The isolation level is pinned because the border argument rests on READ COMMITTED's per-command snapshot; under REPEATABLE READ the same wait ends in a serialization error instead.
  - **The create budget covers the whole call, not only the locked transaction.** The unlocked fast-path read takes a connection of its own, so a caller already holding one is blocked before the creation transaction is ever reached — a transaction-scoped budget would let exactly the stall it exists to prevent happen, with a bare context error and no named one to read.
  - **The season is a parameter whoever creates the maze supplies**, with no configuration key, on the owner's ruling: a season key lands with whatever task ships rotation, which is out of the MVP.
  - **The event log's maze dimension keeps no foreign key.** It stays an open question rather than becoming a design: no acceptance criterion asked for it, and tightening an already-shipped table was not this task's scope.

- **Traps found:**
  - **An exact-set schema assertion is extended, never loosened.** The base-table test compares against a literal list; relaxing it to a subset check turns the gate green while quietly deleting the guard it exists to be.
  - **A foreign key is not covered by an index that merely contains its column.** The cover test compares the key's columns against the index's *leading* columns, so the partial unique index leading with the maze does not cover the gate-chat key — that needs a partial index of its own.
  - **`go test -run` with a pattern that matches nothing exits 0.** A per-criterion sweep reading only exit codes reports every criterion green whether or not a single test ran. The discriminator is the `[no tests to run]` suffix on the `ok` line, and the control is a deliberately non-existent test name.
  - **A test that mutates stored bytes from inside the test cannot verify "production never updates this row".** It stays green the day production starts issuing that update, so the invariant is carried by a measurement over source and by review — not by a gate, and the design says so rather than implying coverage.
  - **A conditional test case can reach green by skipping.** The border-agreement case on the gate path was written to skip when the spiral did not put the gate adjacent — and its fixture forces adjacency, so that branch was unreachable and would have fired only once a later edit stopped forcing it, silently. It asserts adjacency instead and fails naming the fixture. The world seed holds nothing honest here either: gate placement reads the created set, the existing gates and the spacing parameter, and takes no seed at all.
  - **The lattice's border helper returns a non-canonical direction's cells in the neighbour's frame.** It is documented, and it still produced a border walk that read correctly and was not.

- **Invariants this now relies on:**
  - A `chunk` row is never updated after insert. Nothing in the tree enforces it; the unlocked fast path is safe only while it holds, and the package owes it.
  - An owner's kind never changes — no production code updates it — which is what makes the activation's unlocked kind check safe to act on.
  - The stored map's byte layout is live data: a golden that involves no seed and no generator pins it, and a diff there means every stored chunk is now misread, not that a test needs updating.
  - A new chunk's shared border comes from its neighbour's **stored** map, never from a fresh generation of that neighbour.

## Chat location, deep-link onboarding, and player-to-chat membership — the game's front door: a chat becomes a settlement, a player arrives through its link (#TBD-at-Step-12, 2026-09-19)

- **What landed:**
  - One forward migration: the `home` `scope_definition` row (owner kind `chat`, **no** `account_definition` row) with its scope backfill, `chat_presence`, `chat_membership` with its player index, and the `chat_knowledge` view — plus every hard-coded schema manifest it moves (the Go catalog mirror, the exact view set, the view column contract, the base-table set, the applied-migration count).
  - `internal/chat` — presence (the current answer, with `changed_at` written explicitly on a flip and left alone on a repeat), membership (accruing only, idempotent on a repeat), and the pool-backed `DestinationLookup` the outbound gate reads.
  - `internal/onboard` — the namespaced `start` payload codec with its three refusals (empty payload, unknown prefix, malformed remainder), the deep-link builder that takes the bot's username as an argument and refuses an empty one, the `my_chat_member` handler and the private-`/start` handler. These are the first production `ingest.Handler` implementations in the tree, and `cmd/bot` registers both routes, so the assembled process's router is no longer empty.
  - `store.EnsureOwner` — find-or-create keyed on `(kind, telegram_id)`, lifted into the ledger package because both handlers create an owner and #36 will be the third site.
  - The outbound gate's chat branch now requires **allowlisted AND present**; `ingest.PlayerLookup` became `ingest.DestinationLookup` and `ingest.NewPoolGate` was deleted with no shim, the composition root injecting `internal/chat`'s implementation through the already-exported `ingest.NewGate`.
  - The peaceful-home instrument: a schema scan over the Postgres catalogs, in two halves, each with a constructed positive control plus a width control for the surrogate-key and no-foreign-key shapes.
  - `ai-docs/domain-invariants.md` gains § 10 (the home as an address space, membership's single observation, the gate's presence condition and the pre-existing-chat bootstrap), and § 6's gate bullets carry the new predicate and branch order.

- **Decisions worth keeping:**
  - **The peaceful rule is the address space, not a flag.** A home is a `scope` row with no maze or cell key, and no maze-touching relation carries a `scope` reference — so a mechanic that fights or loots *without asking* cannot reach a home, because there is no home for its position argument to name. A `peaceful boolean` column would only have helped a mechanic that asks, and a mechanic that asks was never the risk.
  - **The guard's subject is deliberately wider than either narrow reading.** Any ordinary base table that declares a `maze (id)` reference **or** a column named `maze_id`, whatever its primary key. A primary-key-shaped definition would miss the surrogate-key shape a PvP or corpse table takes; an FK-only definition would miss `event`, which is the in-tree precedent a later relation is most likely to copy.
  - **What a chat knows is a view, and that is what makes the joiner case free.** A membership recorded today brings every discovery that player already had into the chat's knowledge, with nothing to back-fill. The projection is minimal on purpose so a later `first_discovered_at` is an append; the discoverer is left out because adding it would *multiply* the row set, which `CREATE OR REPLACE VIEW` cannot express.
  - **`player_started` fires on the player's creation OR on a new membership.** The funnel attributes by the earliest **chat-bearing** event, so emitting only on player creation would leave a player who starts bare and later takes a chat's link attributable to no chat forever. The cost — more than one event per player — is already absorbed by both shipped views.
  - **The presence row is written on every handled update; only the event is conditional.** That separation is what keeps the funnel's promotion-first gap from also being an outbound-traffic gap.
  - **The Start handler looks the link's chat up and never creates it.** The payload is guessable, so find-or-create there would let a guessed id conjure a chat and its home scope.
  - **A link naming a chat the bot was removed from still records the membership.** Presence governs what the bot may *send*; the player's own arrival is real either way, and a re-add then finds the membership already there.

- **Traps found:**
  - **Seeding a scope for a kind that has none reverses a shipped test's own name.** `TestCreateOwner_chat_has_no_scope_or_accounts` encodes the invariant this task inverts; it is renamed and re-pointed in the same commit, keeping the zero-accounts half, because dropping that half would silently widen what the migration is allowed to do. A now-false comment in the move suite moved with it — `make comment-refs` is lexical and cannot see that class.
  - **An unfiltered `information_schema` scan picks up views.** `chat_knowledge` projects `maze_id`, so the peaceful-home guard would be red on output its own dependency produces. Scoping to `relkind = 'r'` is the same decision the base-table assertion made when the first views landed.
  - **A deleted constructor with an out-of-package caller cannot be split across subtasks.** `cmd/bot` built the gate through `ingest.NewPoolGate`, so the rename and the rewire are one subtask — otherwise `go build ./...` is red across every intervening one, and the coverage ratchet refuses a commit whose suite is not green.
  - **The Bot API's own username accessor reports the empty string on failure.** Resolving it inside the link builder would turn an outage into silently dead links, so the username is a parameter and the sender supplies it.
  - **An allowlisted id that is not a present chat must FALL THROUGH, not refuse.** An operator may legitimately allowlist a player's DM, and that id lives in the same `telegram_id` column as a chat's. Refusing at the presence branch would break DMs the gate allows today.
  - **A new database-backed test binary is a term of the connection ceiling.** `testdb.Binaries` rises once per such binary, in the same commit as the binary, and it lowers the `clients × parallel` product at which the suite refuses to provision.

- **Invariants this now relies on:**
  - No relation that touches a maze carries a `scope` reference, and `scope` carries no maze or cell column. A new maze-touching relation with an `owner` reference turns the guard red until its allow-list row states which owner kind the column holds.
  - `chat_knowledge`'s column names, order and types are a permanent contract from merge — `CREATE OR REPLACE VIEW` can only append.
  - A membership is never removed, and nothing in this module ends one.
  - Presence is read, never cached, on every outbound chat call; a chat with no presence row is refused, which is why a pre-existing chat must be removed and re-added once.
  - `event` is append-only, so `bot_kicked`'s `chat_id` is set rather than null, and a chat missing from the activation funnel because its first update was a promotion is missing permanently.
