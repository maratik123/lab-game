## Mechanical code-style gates from claude-alduna — one `make verify` every runner shares (PR #6, 2026-08-30)

- **What landed:** `asciicheck` + `gofumpt` in `.golangci.yml`; a tracked `Makefile` whose `.PHONY` sub-targets carry every gate, under a `verify` aggregate; CI rewired so every Go job invokes a `make` sub-target, with the job matrix and `paths-filter` otherwise unchanged; a two-tier file-size gate (1000 non-test / 1500 `_test.go`) as one POSIX `awk` step; the `PostToolUse` formatting hook and the `PreToolUse` piped-gate guard both updated; a committed guard regression suite run by CI; and the two rule changes propagated to every site the sweep found.

- **Decisions worth keeping:**
  - **The format gate is `golangci-lint fmt -d`**, not `gofmt -l .`. It exits 1 when any enabled formatter would rewrite a file, so it works as a check without post-processing its output. `gofumpt` needs no separate binary — it is a golangci-lint v2 built-in formatter.
  - **`make` matches as a CLASS in the piped-gate guard**, not by target enumeration. Enumeration leaks on six shapes that all run gates: five carry a flag between `make` and the target (`-s`, `-B`, `-C .`, `-j4`, `-f Makefile`), which breaks the `make[[:space:]]+<target>` anchor; the sixth is bare `make`, which leaks because it names no target for the anchor to bind to at all. The class form's only false positive is a dry run, which executes nothing — loud over-blocking beats silent under-blocking.
  - **No dry-run carve-out in that guard.** `tail -n 5` is the canonical spelling of `tail -5`, so exempting that flag would switch the guard off through the exact idiom it exists to catch. The carve-outs are whole-command greps, so any such exemption is a bypass, not a narrowing.
  - **The `gofmt` branch stays in the guard regex** even though `gofmt -l .` is no longer this project's gate — agents still reach for it by habit, so it remains must-block regression cover.
  - **File-size bands: 500 and 800 are prose, 1000 and 1500 are gated.** The source contradicts itself — alduna's `projectlint` flags mechanically at 500 (`internal/projectlint/projectlint.go`, `MaxLines = 500`) while alduna's prose (`docs/code-style.md`) calls 1000 the hard threshold. Resolved in favour of the prose by owner decision.
  - **Neither of alduna's `errcheck` loosenings crossed over.** Both would have weakened this repo's existing "never discard an error" rule (`code-style.md`). `asciicheck` was the whole linter delta; alduna's other linters are already active here via `linters.default: standard`.
  - **Every Makefile target is a gate**, which is what makes class-matching `make` semantically exact. An eleventh non-gate target was refused as drift bait — `go` stays enumerated in the guard precisely because `go list` and `go doc` are legitimately piped.

- **Traps found:**
  - **A pure-`revive` two-tier limit is impossible.** Two `file-length-limit` entries in one config silently collapse to the last one, and `exclusions` can disable a linter per path but not re-parameterise it. Hence one `awk` step owning both tiers.
  - **A fixture proving the file-limit gate must itself be gofmt-clean, or it proves nothing.** `verify` runs `fmt-check` first, so a dirty fixture reds at target 1 of 10 instead of at the gate under test. The naive fix — inserting a blank line — shifts the boundary fixtures by one, flipping 1000 to 1001 at exactly the boundary being proven. Reduce the filler by one to compensate.
  - **Proving a gate is load-bearing needs both halves:** red *at that gate* with the fixture present, and green with it removed. A red alone is satisfied by any red.
  - **`golangci-lint fmt` confines itself to path arguments**, despite a usage line that suggests otherwise. That is what makes the formatting-hook swap a one-call delta rather than a whole-module reformat.
  - **`golangci-lint-action@v9` needs `install-only: true`** when a job's `run:` is a `make` target — the action otherwise runs the linter itself. Its `core.addPath` precedes the early return, so the pinned binary is still on PATH.
  - **A guard regression suite must execute the hook body, not a copy of its regex.** Extracting the body with `jq` removes the drift class instead of documenting it. The suite was also run against the *pre-edit* body, where it fails on exactly 11 rows — proving it discriminates rather than passing anything put in front of it.
  - **The piped-gate guard matches command TEXT, not shell semantics.** It fires on any command merely quoting a gate piped into `tail`/`head`, including documentation of its own fixtures. Use the Write tool for such content.

- **Invariants this now relies on:**
  - `AGENTS.md` sits at **34 984 bytes** against its own 34 986 ceiling. Any edit to lines 47, 48, 77, 102 or 108 needs its byte arithmetic re-run *before* the edit lands — the five-line set balances only as a set, and two of the five grow while three pay for them.
  - `.claude/skills/task/SKILL.md` is **39 539 bytes** against a 40 000 hard cap.
  - `harness` is the only CI job whose `paths-filter` matches `.claude/**`, so a guard added there has nowhere else to live.
  - `Makefile` is present in the `go` paths-filter; without that entry a Makefile-only change silently skips every Go job.
  - The file-limit gate has no per-file escape hatch. The exemption channel is a reviewed path prune in the `file-limits` recipe, recorded in `code-style.md` — an inline escape on a hard limit is what turns a hard limit soft.

## Ledger core — `store.Post`, the owner/scope/account model and container-backed tests (PR #14, 2026-09-02)

- **What landed:** `internal/store` (`Migrate`, `NewPool` with the shopspring codec, `CreateOwner`, `Post`, enum and catalog mirrors, the `Err…` sentinels) and `internal/testdb` (testcontainers provisioning, `LAB_GAME_TEST_DSN` override, schema per test, never a skip). One forward-only goose migration creating the enums and tables — `owner`, `scope_definition`, `account_definition`, `scope`, `account`, `account_balance`, `player_operation`, `manual_correction`, `journal_entry`, `posting` — with World and the player `attributes` catalog seeded. The whole suite runs against a real `postgres:18` container: the rapid property for the zero invariant, the `QueryTracer` phase/capture-order test, the `-race` anti-deadlock stress, FK-coverage and balance-row invariant checks, the catalog-mirror equality test. CI's `go` filter now matches `**/*.sql`.
- **Decisions worth keeping:** `kind` and `controlled` are catalog data (`account_definition`), never caller input — a posting is `(account, amount)` and "wrong kind on wrong account" is unrepresentable; accounts and zero balance rows are created with their owner, so every overdraft is refused by `CHECK (balance >= 0)` and `Post` needs one plain `UPDATE` per controlled account in ascending `account_id` (no upsert, no sign split); the exclusive arc and `ts` live on `journal_entry`, 1:1 with its basis document; singular table names; identity columns (`BY DEFAULT` where seeded, `ALWAYS` where only `Post` writes); every FK is index-covered, partial `IS NOT NULL` allowed, enforced by a migration test with a planted positive control; enums are add-only, one `ALTER TYPE` per migration file; images pinned to the major tag (`postgres:18`); `pgregory.net/rapid` for properties.
- **Traps found:** `INSERT … ON CONFLICT DO UPDATE` evaluates the `CHECK` on the *proposed* row, so an upsert refuses a covered debit with `23514` — the round-1 design had "measured" it on credits only; `pg_index.indkey` is zero-based (take the prefix `WITH ORDINALITY`); rootless podman's healthcheck never leaves `starting` (gate on `pg_isready`); the shell's `grep` is ugrep and `\|` inside `-E` is a literal pipe under GNU grep too — a grep-shaped AC needs a positive control, and its command cannot live in a markdown table cell (the cell escaping recreates the defect); `go mod tidy` prunes a `require` no package imports, so a dependencies-only subtask cannot commit on its own; a `.gitignore` pattern with an inner slash is root-anchored (`**/testdata/rapid/`); `decimal.New` takes an `int64` coefficient — 25-digit amounts are built from `New(r, 18)` plus a scale-5 fraction; `pgxdecimal.Register` prepends on every call (register once, in `AfterConnect`).
- **Invariants this now relies on:** every controlled account has exactly one `account_balance` row from creation (owner-creation code + the AC18 test) — `Post` treats zero rows affected as a broken invariant, never as overdraft; the Go mirrors of the three enums and two catalogs equal the database rows (test); no non-test statement in `store` targets `posting`/`journal_entry` with `UPDATE`/`DELETE` (grep with a planted control); `cmd/bot` never links testcontainers (`go list -deps` count 0); the test suite fails rather than skips when no database is reachable.

## Configuration layer — typed access, fail-loud start-up validation, and the tracked balance file (PR #50, 2026-09-04)

- **What landed:** `internal/config` — the `Balance` schema with a node walker that reports every failure by dotted key path, the environment layer (`Lookup`, `EnvKeys`, the `LAB_GAME_` name constants), the world-set path probe, and `Load` joining all three into one error; the tracked `config/balance.yaml` and `config/world/`; `.env.example`; `cmd/bot` rewired so `main` delegates to a testable `run` that loads and validates before any other work; the `go` paths-filter in `ci.yml` extended to the tracked config artefacts. Riding in the same PR by the owner's decision: the `AGENTS.md` axiom making established packages the default over hand-rolling, the `.claude/settings.json` deny narrowing that made `.env.example` authorable, and the `claude-tools-hierarchy.md` propagation of that narrowing.

- **Decisions worth keeping:**
  - **The parser is `go.yaml.in/yaml/v3`, not `gopkg.in/yaml.v3`.** The incumbent's upstream (`go-yaml/yaml`) is archived and has no release past `v3.0.1`; the YAML org's fork is maintained and has zero non-stdlib requires. `gopkg.in/yaml.v3` stays as a test-only indirect via testify — do not tidy it away. The fork's `retract [v3.0.0, v3.0.1]` directive is **not** an argument for the move: it retracts those version strings under the new module path and says nothing about the incumbent release.
  - **The three sources are disjoint by domain, so there is no override chain to resolve.** The environment owns secrets, runtime settings and file paths; the balance file owns balance values; the world set owns world content and is not decoded here. This is excluded by decision, not merely unimplemented — no key-path override machinery and no env-vs-file merge step exist, and none should be added without revisiting the decision.
  - **Reload is start-up only.** Moving balance without a deploy is deferred out of MVP with the seasons work; the closing clause of `domain-invariants.md` § 8 binds nothing here, while the rest of § 8 — balance is configuration, never a Go literal — is why the layer exists.
  - **`.env.example` is the loader's manifest, and the equality is enforced.** Its keys equal the set the loader consults, checked in both directions by name. Test-suite variables such as `LAB_GAME_TEST_DSN` are documented elsewhere; adding one here breaks the suite, which is why the file opens with a header comment saying so.

- **Traps found:**
  - **A YAML `null` decodes into `int`, `time.Duration` and `decimal.Decimal` with no error and a zero value** — the silently-defaulted balance number this layer exists to prevent. So does `!!float` into `int` (`3.25` → `3`). Both are why the walker inspects node tags rather than binding straight into a struct.
  - **Duplicate keys are reported when decoding into a map but not into a `yaml.Node`**, at any depth — hence the separate duplicate-key pre-pass.
  - **`reflect.DeepEqual` on `decimal.Decimal` is true for two parses of the same text** and false only for a respelling (`1.50` vs `1.5`). It passes today and breaks the day someone reformats a placeholder; compare field-wise with `decimal.Decimal.Equal`.
  - **In ripgrep, a later `--glob` overrides an earlier one**, so `--glob '!*_test.go' --glob '*.go'` silently includes the very files the negation dropped. The AC11 gate now takes its file set from `go list` instead, which has no ordering footgun.
  - **The permission deny rules reach `Bash` by command text, not only the file tools.** A command naming both `.env` and `.env.example` is refused outright while either alone runs — and a refusal reads nothing like a failed criterion.
  - **`revive`'s `package-comments` fires per package, so the package comment must land in the first subtask**, or every earlier per-subtask commit red-gates on it. A second package comment is gated by nothing: two of them pass lint and vet and simply concatenate, so `doc-convention.md` DOC-2's "exactly one" is honour-system here.

- **Invariants this now relies on:** no balance value has a compiled-in fallback, so an empty-but-valid balance file fails rather than yielding a usable configuration; every failure names its dotted key path or variable; `main` may exit non-zero but nothing on the loader path panics; and a textual gate's hit is evidence to inspect, never a reason to reword the matched text.

## Bot API transport over telego — retries, exact `retry_after`, a window-schedule rate limiter, the base-URL axis (PR #53, 2026-09-04)

- **What landed:** `internal/tg` — the client over `telego`'s low-level generated API with `net/http` and `encoding/json` substituted for its `fasthttp`/`go-json` defaults, the method classifier, the `Gate` seam #22 installs its allowlist into, the window-schedule rate limiter, the caller with its retry loop and typed error, and the `Observation` the §13.2 health surface reads; `internal/tgtest`, an in-process fake Bot API server over `net.Pipe` with scripted 429/5xx/delay/dial-failure behaviours; the optional-with-default `LAB_GAME_TG_*` key class in `internal/config` with `.env.example` extended; `github.com/mymmrac/telego` pinned as a direct requirement; and `key-decisions.md` rewritten for KD-2 plus KD-25/KD-26/KD-27. `cmd/bot` is deliberately untouched — constructing a client nothing feeds would be dead code and an untested wiring path at once.

- **Decisions worth keeping:**
  - **The seam is `telegoapi.Caller`, not a wrapper around the generated methods.** telego's stock caller discards the HTTP status code and reports any 5xx as an untyped error, so the per-method status and 429 counts §13.2 asks for cannot be observed from above it. Replacing the caller is the only layer where those facts exist, and it makes the generated API safe to hand out unwrapped.
  - **One schedule per key holding a *set* of `(count, per)` windows — not composed limiter legs.** "At most one per second" and "at most twenty per minute" are the same kind of constraint. Acquire computes `t = max(now, global.earliest(), chat.earliest())` under one mutex, refuses on deadline **before any mutation**, then commits to every window at that same `t`. Three review rounds of composed legs produced four defects of one shape, each individually defensible per leg; the composition was what broke.
  - **A chat key is ordered, the class-global key is unordered.** A per-chat key owes arrival order (AC30); a ceiling owes none, and imposing one let a backlogged chat hold every other chat behind it.
  - **Never retry on doubt.** A Bot API call has no idempotency key, so a request that went out with no response back is ambiguous and is *not* re-sent; the typed error carries the ambiguity flag for #43 to branch on.
  - **The limiters are charged per attempt and are unconditional across all three base-URL values.** A self-hosted instance does not relax message rate limits (KD-9), so there is no relaxed mode and no branch on base URL in the limiter path.
  - **Tuning values are environment keys carrying compiled-in defaults** — a new class for `internal/config`, bounded to operational tuning only: secrets, the base URL, the allowlist and the two file paths stay required with no default, and no balance number gains a fallback.

- **Traps found:**
  - **`url.Error.Error()` prints the full URL, and the Bot API URL contains the bot token.** `stripPassword` redacts only userinfo. Store `url.Error.Unwrap()` rather than the wrapper — `Unwrap` returns exactly the cause, so `errors.Is` still reaches `context.DeadlineExceeded` — and run rendered strings through a token replacer.
  - **`net/http` retries a POST internally only when an `Idempotency-Key` header is present.** Never set one, or "never retry on doubt" is silently defeated inside the transport.
  - **`MultipartRequest` returns `BodyStream` (an `io.Pipe`) with `BodyRaw` nil**, so a file upload's `chat_id` is unreachable at the caller seam. Hence the three-state target: `ChatNone` (no destination — `getMe`) and `ChatUnknown` (destination unreadable) need *opposite* answers from #22's allowlist gate, and one boolean cannot carry both.
  - **A token bucket sized `burst = count` admits `count + rate·W` per window** — double the configured figure at the shipped default. A bucket is a rate, never a window bound.
  - **`rate.Reservation.Cancel` reclaims nothing whenever a later reservation exists**, so a cancelled call leaves a permanent hole rather than releasing its slot.
  - **Count-based retention is unsound once inserts are no longer appends** — a sorted-insert schedule that keeps "the newest `max(c)`" silently forgets live grants and over-emits. Retention is time-based.
  - **Eviction must be relative to real `now`, never to the instant just granted**, or a far-future grant makes the schedule forget an early member of a simultaneous burst.
  - **The transport keys must not join the unexported `envKeys()`** — two existing suites iterate it and assert every member is required. Append in `EnvKeys()` only, mirroring the file-path keys. `.env.example` must land in the *same* commit as the loader, because the disjointness test asserts the two key sets are equal.
  - **A red-first variant that cannot go red is worse than none.** One shipped here: a truncated pacing interval could never admit an extra emission, because the quota window already forbade it. A variant is only evidence when it has been seen to fail.

- **Invariants this now relies on:** no chat is exempt from the per-chat limiter by construction, including private chats and calls whose body cannot be decoded; every submitted call ends in an emission or a returned typed error, never in silence, and nothing is discarded to relieve pressure; the bot token appears in no rendered error, observation or fixture; limiter state is in-process only — no database, no disk, no migration, with #43 owning anything that must survive a restart; and each rate-limit default traces to a figure with a published source, with classes whose figure has none left unbounded rather than throttled against an invented number.

## Postgres task scheduler — `scheduled_task`, the `SKIP LOCKED` worker, one-shot and recurrent tasks (PR #54, 2026-09-05)

- **What landed:** migration `00002_scheduler.sql` — `scheduled_task` with its live-scoped identity index, the `deferred_task` / `recurrent_task` basis tables, and `journal_entry`'s arc widened to four columns; `store.DeferredTask` / `store.RecurrentTask`, which make `PostingBasis` a four-implementation sum type; `internal/scheduler` — the handler registry with its one-shot and recurrent declarations, `Schedule`, the worker's discovery / per-id re-claim / execute / settle cycle, the failure policy, the per-task execution deadline with its deferred settlement, `Reconcile`, and the observation seam #23 reads; the second optional-with-default environment class, `LAB_GAME_SCHEDULER_*`. No production handler ships — the raid timer edges (#36), corpse evaporation (#40) and the day close (#45) each bring their own. `cmd/bot` is untouched: #24 owns the composition root.

- **Decisions worth keeping:**
  - **Discovery is one statement; each task then gets its own transaction.** A batch transaction with a savepoint per task was designed, reviewed, and **withdrawn** — under it a late task's deadline breach discarded an early task's already-committed effects, which is exactly the durability `docs/DESIGN.md` §11 buys with "одна транзакция со своими эффектами". The derived documents that spell that cardinality out were the signal, not the target: the shape changed rather than their wording.
  - **Savepoints are raw SQL on the worker's own `pgx.Tx`.** `pgx.Tx.Begin`'s pseudo-nested transaction sets `sp.closed = true` unconditionally after its `release savepoint`, so a failed release leaves `sp.Rollback` returning `ErrTxClosed` without ever issuing `ROLLBACK TO SAVEPOINT` — the recovery the design prescribed was unreachable through the API it named.
  - **`FOR NO KEY UPDATE`, and it is not a throughput decision.** It is the weakest lock that expresses what a claim does; a one-shot's `DELETE` takes `FOR UPDATE` strength at the moment it needs it. The equivalence of the two modes rests on *no foreign key anywhere referencing `scheduled_task`* — a condition wider than AC27 enforces, which covers basis-document tables only. An FK from any other table would pass every criterion here and silently start minting multixacts.
  - **Every future `run_at` comes from a settlement instant, never the claim instant.** The execution instant keeps one job: the lag the health dashboard reads.
  - **A deadline breach settles.** It counts an attempt through a guarded, non-blocking deferred settlement drained before the next discovery — the alternative left the row due with no attempt counted, which retries for ever with neither backoff nor cap.
  - **No liveness protocol.** No `picked` column, no heartbeat, no revival: a worker that dies mid-execution aborts its transaction and the row is simply still due. The residual case a transaction cannot heal is a handler that *hangs*, and that is answered by a bounded deadline, not a lease.

- **Traps found:**
  - **`docs/DESIGN.md` carries `FOR UPDATE` twice.** Line 310 is the scheduler's claim query; **line 147 is §3.5's `SELECT session FOR UPDATE`, the raid-session FSM guard.** A document-wide substitution silently changes the documented lock mode of a different machine. Line 311's bare `SKIP LOCKED` is a third sweep hit that names no table.
  - **CI's relative-link gate is a raw regex over markdown text and does not honour code spans** — a correctly backticked example of a link still fails it. Its own escape is a target containing `<`.
  - **`internal/store/migrate_test.go` goes red on the table list and the migration count, but not on the index list or the CHECK map** — the first is a presence loop, the second matches `num_nonnulls` by substring. Both must be extended by hand, and no gate will remind you.
  - **A resolution table is read more carefully than the section it points into.** Two descriptions of mechanisms that a later round had replaced survived four review rounds and a full implementation pass, because the tables truthfully said the change had happened.
  - **`pgx` does carry a `time.Duration` → `interval` codec** — `now() + $1` works. What genuinely fails is `SET LOCAL statement_timeout = $1`; use `set_config(name, $1, true)`.

- **Invariants this now relies on:** a stale task dying on its guard is a third outcome class, distinguished from failure everywhere it is observed; a recurrence is one row moved forward in place and never reaches a terminal state, while a one-shot is deleted on completion and does reach give-up; scheduling twice is refused by the database rather than by a code path that checks first; the scheduler moves no balance and writes no posting of its own — it ships the basis documents that mechanics post under; and `AC30`'s guarantee is conditional on handlers propagating the context they are handed, which is stated in `Handler`'s doc comment and driven as a negative test case.

## Event log — the `event` table, the §13.4 dictionary, and the MVP SQL views (PR #60, 2026-09-06)

- **What landed:** migration `00003_event_log.sql` — the `event_volume_class` enum, the seeded `event_type_definition` registry carrying §13.4's dictionary in declaration order, the append-only `event` table whose four §13.4 dimensions are columns over a JSONB payload, `journal_entry`'s arc widened to five columns, and the five MVP §13.3 views (`metric_activation_funnel`, `metric_retention_daily`, `metric_death_by_depth`, `metric_faucet_sink`, `metric_notification_per_chat_day`); `store.Event` as a fifth `PostingBasis` implementation plus `store.AppendEvent` for the no-posting majority, and `ErrUnknownEventType`; the Go registry mirrors and their ordered element-for-element database comparison; `docs/DESIGN.md` reconciled with its own §11 — the log table named `event` and the game event registered as a basis type. Nothing emits an event: each mechanic brings its own, in its own PR.

- **Decisions worth keeping:**
  - **The activation funnel attributes a player through their own `player_started`, not through the raid's chat.** The owner's call, and it removes an obligation rather than recording one: no future PR owes `chat_id` on `raid_started` for §13.3's headline number to work. The earlier construction read the raid's chat, which would have returned a zero funnel with every gate green if #36 shipped without that column — and this task's own fixture would have passed regardless. Validated on a fixture where every `raid_started` carries a null chat, so the raid's chat is provably unread. Accepted cost: a player active in several chats is credited to the chat they started from; §16.7 and #30 own membership.
  - **The registry is a seeded catalog table, not a Postgres enum — and the volume class is an enum.** The asymmetry is the point: `TestMigrate_hygiene` forbids an `ADD VALUE` file from doing anything else, so an enum registry would cost every future mechanic two migrations with a window where its type has no class. A new type is routine; a third volume class is a rare policy change that wants its own migration anyway.
  - **`event.type` is a `text` foreign key to `event_type_definition (code)`, not a smallint id.** The stated consumer is a Grafana Postgres datasource writing ad-hoc SQL: `WHERE type = 'death'` beats a join. `event_type_definition.id` exists solely to carry §13.4's declaration order so the mirror comparison is ordered rather than set-wise, and is referenced by nothing.
  - **A view's column set is as durable as a table's.** `CREATE OR REPLACE VIEW` can only append; dropping, renaming, reordering and retyping each fail with `42P16`. The design therefore fixes every view's column names, order, types **and row set** — the row set being precisely the half Postgres does not police.
  - **The event basis carries no idempotency key.** Unlike `player_operation`'s `ON CONFLICT (source, operation_id)` → `ErrAlreadyPosted`, two `Post` calls under the "same" event write two event rows and two journal entries. Stated for mechanic authors rather than left to discovery, alongside the 1:1 arc: one event backs at most one `journal_entry`, so a mechanic moving balances twice needs two events.

- **Traps found:**
  - **`information_schema.tables` reports views alongside base tables**, so the existing exact-table-set assertion breaks on the first `CREATE VIEW` in a way that reads like a spurious failure. It needs a base-table filter, and the views need their own exact-set assertion.
  - **`count(…) / count(…)` is integer division**, so an uncast ratio renders `0` for every value below 1 — a plausible wrong answer rather than an error, which is worse than the division-by-zero and empty-`FILTER` traps beside it. Found by probing, not by review.
  - **A wrong-but-existing issue number clears the citation guard**, which checks that `#N` resolves and not that it is the right `N`. An emitter attribution naming the wrong issue passed every gate; the repair was to attribute emitters only where an issue title actually names one.
  - **Most of the store suite stays green on the new schema.** Only the table list and the `goose_db_version` count go red; the enum map is a hard-coded literal ranged over, the index list is a membership loop, and `journal_entry_exactly_one_basis` is matched on the substring `num_nonnulls`, which the four-column form already contains. "Suite green" is not "requirement discharged".
  - **`TestFailurePolicy_oneShotAttemptsGrowAndGiveUp` in `internal/scheduler` is a pre-existing flake** that fails roughly one full `-race` run in three, and **isolation is not a valid probe for it** — 25 of 25 isolated runs were green while the same assertion fails under parallel load. Reproduced on the base commit in a clean worktree; filed as #59.

## Update ingestion — long polling, dispatch, operation idempotency, the chat allowlist (PR #66, 2026-09-07)

- **What landed:** `internal/ingest` — the poll/dispatch/retry loop (`Options`/`New`, `PollOnce`, `Run`), the `Kind` table over `telego.Update`'s payload fields with its date and chat extractors, `IDSpace` and the unexported `operation_id` builder, `Handler`/`Update`/`Route`/`Router`, the guarded-monotone offset and the payload-free give-up store, the observation seam (`Outcome`, `Observation`, `LoopObservation`, `Observer`) with no exporter, and the outbound `tg.Gate` implementation with its player lookup and positive-only cache; migration `00004_ingest.sql` creating `ingest_offset` (guarded singleton, seeded) and `ingest_dead_update`; `store.Queryer` and `store.PlayerExists`, the package's first owner read; `config.Ingest` and the `LAB_GAME_INGEST_*` tuning keys; and `internal/backoff`, into which `internal/tg`'s and `internal/scheduler`'s duplicate ramps were folded and then deleted. Nothing routes an update: each mechanic registers its own handler, in its own PR, and `cmd/bot` stays a scaffold.

- **Decisions worth keeping:**
  - **The gate asks *who* the destination is, never *what kind of chat* it is.** `ALLOWED_CHAT_IDS` governs group and channel traffic; a DM is permitted because the id resolves to an `owner` row of `kind = 'player'`. The kind belongs in the predicate, not just the id: `owner`'s unique index is on the pair `(kind, telegram_id)` and a chat's own id lives in the same column, so a `telegram_id`-only lookup would match every chat the bot was ever added to and void the allowlist entirely. The obvious alternative — read the sign of the `chat_id` token — is refused outright and recorded as refused: `Chat.Type` is inbound-only and `Chat.ID`'s documentation states no relation between a chat's kind and its id's sign, so the convention is uncitable.
  - **A handler must not issue an outbound call permitted only by a row its own uncommitted transaction created.** The gate reads on a pool connection, so under READ COMMITTED it cannot see the loop's open transaction — and §1's onboarding (button → Start → owner row → DM) is exactly one update that creates the row and addresses the reply to a chat outside the allowlist. The rule holds even if the gate were made transaction-aware, because a Telegram send is not rollback-able: a message justified by a row that later rolls back has already reached a real person. #43's notification queue is the post-commit route.
  - **`ingest_offset` stores `next_update_id`, not the last settled `update_id`.** `GetUpdatesParams.Offset` is defined as one greater than the highest identifier received, so the `+ 1` lives in the advance statement and the stored value is transmitted verbatim. The other reading produces a permanent live-lock — the same update re-fetched every cycle, settled as a duplicate, the guarded-monotone advance never moving — whose only symptom is §13.2's idempotency-hit counter, which is documented as ordinary traffic.
  - **A poll failure is observed and the loop continues; `Run` returns non-nil only on cancellation.** Transposed from `internal/scheduler`'s worker without variation. No consecutive-failure ramp: the transport layer has already retried and backed off before `PollOnce` sees anything, so the poll interval alone bounds the rate.
  - **Idempotency stays the basis document's unique constraint, caught at the handler's `store.Post`.** The loop derives the key and classifies `store.ErrAlreadyPosted` by sentinel; a duplicate consumes no retry attempt. The consequence, stated rather than left to discovery: an update that moves no balance writes no document, so its non-ledger effects replay in full.

- **Traps found:**
  - **The shipped scheduler suite is *invariant* to a missing one-based→zero-based translation at `settle.go`, not blind to it.** Both assertions over a persisted retry `run_at` compute their expected value through the very function the call site calls, so they move together: a byte-identical-assertion rule and a green `make verify` are both compatible with every retry delay silently doubling. Blindness would be cured by adding any test; invariance is cured only by an expected value computed *outside* the function under change. The fix was a literal one-based ramp landed and confirmed green first, then the wrong delay written at the call sites over a `cp` backup and required to go **RED** before the re-point — a green probe was defined as a STOP.
  - **A mutation probe that does not compile is the same failure as one that cannot go red.** The first form of the probe called `Exponential` while `func backoff` still stood; no file of `internal/scheduler` can import `internal/backoff` in that state, because the name collision is package-wide rather than per-file. Rewritten in the shipped ramp's own units as `backoff(k+1, …)`.
  - **`encoding/json` erases an *empty* slice under `omitempty`, not only a nil one.** `allowed_updates` absent means "reuse the server's previous setting" — hidden state outside this repository — so the loop transmits a one-element sentinel (`shipping_query`, an id space this bot cannot receive) when no route is registered. The same tag sits on `GetUpdatesParams.Offset`, so a stored offset of `0` is legitimately absent from the request body and must not be asserted present.
  - **`CallbackQuery` carries no `date` field**, so §13.2's star metric is undefined for that update kind. The observation states the absence rather than reporting a zero duration, which would be indistinguishable from a healthy poll.
  - **The scheduler suite assumes exclusive database access, and says so nowhere.** Point every package at ONE shared Postgres — which `LAB_GAME_TEST_DSN`, the documented escape hatch, is exactly how you do — and `go test -race ./...` fails roughly half the time, in four different tests (`reconcile_test.go:365`, `worker_test.go:194`, `deadline_test.go:168` with a `statement_timeout`, `observe_test.go:121` with an off-by-one failure count). Under testcontainers' per-package servers the same command is green run after run, and CI has no `services:` block, so CI never sees it. The failure looks like a defect in whatever changed last; it is contention. Check which provisioning path the run used before believing it.
  - **A RAID scrub starves container `initdb` past testcontainers' 60s wait.** Every database-backed package then fails with `"database system is ready to accept connections" matched 0 times` — four FAILs that describe the host, not the tree. `LAB_GAME_TEST_DSN` against a hand-started server is the documented way through, and it is worth checking `/proc/mdstat` before believing a sudden whole-suite red.

So neither reading the node's line nor offsetting from it is correct; the extractor searches for the comment text in the direction each field fixes, and escalates an unreconciled comment to an instrument failure rather than guessing a line. Nothing mechanical covers them; the convention records that they are review-judged, and review is what found them.

Restored on the owner's ruling. The distinction is not pedantry: the criterion that the sweep moves no statement is what makes the diff reviewable at all.

## Shared PostgreSQL test server — one server for the whole run, containers as the fallback (PR #72, 2026-09-08)

- **What landed:** `internal/testdb/server.go` — the provisioning that was buried in `Main`, now an exported API (`ServerOptions`, `StartServer`, `Server` with `DSN` / `Stop`, the capacity `Probe`, `DSNEnv`, `SharedContainerName`) plus the `Ceiling` formula and the `Binaries` manifest constant, with `Main`'s container branch re-expressed over it. `cmd/testpg` — the wrapper every gate now runs its test invocation through: it passes a caller-supplied DSN straight down, otherwise reuses a long-lived server named by a locator file under the scratch directory, otherwise starts an anonymous container sized by the ceiling and removes it on every exit path. `--up` / `--down` create and remove that long-lived server; `--clients` and `--parallel` feed the ceiling. `make test` and `make test-race` route through it, and so does the coverage ratchet's own measurement, placed after the ratchet's skip decision so a commit that stages nothing coverage-moving still starts nothing. `make test-fallback` keeps the per-binary container path executed and CI's Test job runs it as a step; `make test-db-up` / `test-db-down` hold a server across commits; `make test-contention` is the probe that induces cross-package load. The scheduler suite's wall-clock constants were classified and retimed. KD-20 carries the arithmetic and a corrected consequence clause; the provisioning story is in `go-test-conventions.md` and `AGENTS.md`.

- **Decisions worth keeping:**
  - **The connection ceiling is computed, not a literal.** Every term but one scales with the host's core count, because `go test` defaults both its package-level and its subtest parallelism to `GOMAXPROCS` — so a number that is right on a sixteen-core machine is wrong on a sixty-four-core one. The formula multiplies clients by the database-backed binaries by that parallelism by the per-schema pool cap, plus slack for reserved and pool-oversized connections, floors at the image's own default and **refuses** above a measured maximum rather than clamping silently. A manifest test derives the binaries term from the tree, so adding a database-backed package cannot silently under-size the server.
  - **A shortfall gets a different answer on each path, because the wrapper's authority differs.** On a caller's own DSN it reports and runs — the contract is that the gates execute against the server the caller named, and exhaustion was always loud; what was missing was the diagnosis. On a discovered long-lived server it falls through to its own container, because the locator is this change's convention and there is an alternative. On a server it started itself the case cannot arise.
  - **`--down` removes only a server this project started.** The reaper is disabled for the long-lived container precisely so it survives the process that created it, which means the reaper will not remove it either; the locator file is the record of ownership, and a server found rather than started is never touched.
  - **A fixed host port was rejected on the library, not on taste.** The container runtime binding is parsed as a port range with no host-side form, so a fixed binding would need a lower-level modifier hook and promote an indirect module to a direct requirement. The locator makes an ephemeral port cost nothing.
  - **Every wall-clock constant in a database-backed suite is either an instrument or the subject, and they are treated oppositely.** An instrument is a patience budget — made generous, or replaced by polling the condition. The subject stays exact, with its reference instants read from the database clock around the operation. One value is both, in different tests, which is why the widening is per test and never an edit to a shared configuration helper.

- **Traps found:**
  - **A gate whose command can be served from the test cache is a report, not a gate.** `make test-fallback` was written without `-count=1`. Measured: a second invocation returned green having started no container at all, every database-backed package answered `(cached)`. The path itself was fine; the instrument that exists to keep it fine could not fail. The same reasoning was already written down for the contention probe's load loop and was simply not carried to its sibling.
  - **A `TestMain` that reads configuration before `m.Run()` is invisible to the test cache, and this one does.** `testing.M.Run` opens the log `cmd/go` reads to decide whether a cached result still applies; `testdb.Main` reads the DSN variable and *then* returns `m.Run()`, so the read is never recorded and the variable is in no cache key. Measured with the cache cleared: a package re-run under a different DSN, and again with the variable cleared entirely, answers `(cached)` both times. So the shared and fallback regimes share cache entries — the reason the fallback gate needs its flag — and no reasoning may treat a changing DSN as forcing a fresh run. Three live documents and one design decision asserted the opposite before self-review measured it.
  - **The shared regime moves the coverage number systematically, and the ratchet's band is thin.** Under one shared server the container-provisioning branch of `internal/testdb` is executed by no test, so the recorded mark has to be re-centred inside whichever commit moves it. Assume it blocks rather than planning around a measurement taken on a tree that does not yet contain the change.
  - **`go test` swallows a passing package's output, so "no container was created" can be a property of the observation.** Checking the fallback path by grepping a non-verbose log finds nothing whether or not containers were started; the runtime's own container list, or `-v`, is what actually answers.
  - **`go run` flattens the child's exit status.** A program exiting with a specific code under `go run` surfaces as exit 1 with the real code on stderr; built and run directly it surfaces exactly. Non-zero is preserved either way, so no gate mis-reports green — but any recipe that branches must branch on zero versus non-zero, never on the value.
  - **The recorded exclusive-access trap did not reproduce at its original settings on this machine.** Only an artificially tight budget produced the red that demonstrates the probe can detect contention. That is evidence about this host and about the intervening tmpfs and backoff changes, not a retraction — and it is why the demonstration reverts an instrument deliberately rather than waiting for a failure to appear.

- **Invariants this now relies on:**
  - The wrapper is the only thing that provisions; `testdb.Main` still prefers an already-set DSN and returns before it reaches the container path, so no test knows which regime it is running under.
  - A green contention run counts as evidence only after the probe has been shown able to go red, and only when neither captured log carries the connection-exhaustion condition. A run that carries it is an instrument failure and is thrown away; a run with no failure at all is inconclusive, never a pass.
  - The ordinary gates keep replaying from the test cache exactly as they did before, on every provisioning path. `-count=1` belongs to a gate whose claim the cache key cannot see: one that exercises a particular provisioning path, or one that asserts a property of the run's *conditions* rather than of the code. Both kinds are here — the fallback gate is the first, and both of the contention probe's children are the second, the foreground race gate included, since its exit status is the probe's whole verdict.

- **What landed:** `internal/health` — the health surface. An explicitly constructed `prometheus.Registry` handed to every registration, with no use of the client library's global default registerer and no `promauto`; one adapter per consumer-declared observation seam (`tg.Observer`, `scheduler.Observer`, `ingest.Observer`), each mapping its own label values in exhaustive switches rather than delegating to a source package's rendering; a pgx pool collector over a `func() *pgxpool.Stat` accessor read during `Collect` rather than from a cached snapshot; the Go runtime and process collectors; a `promhttp` handler on its own `http.Server` at `/metrics` with an exported start and shutdown the caller owns; and the two-leg `getMe` canary — own instance and cloud reference — driven by an in-process ticker that touches neither Postgres nor the scheduler. `internal/config` gained the `LAB_GAME_HEALTH_` class (metrics address, canary interval, the cloud leg's own token as a `Secret`, the cloud base URL), every key optional-with-default. `internal/repotest` — the module's one repository-root resolver for tests, into which every per-package copy was folded. `ai-docs/alert-contract.md` fixes the alert names, expressions, condition shapes and severities the infrastructure pass wires against, and fixes no threshold.   - **The cloud canary leg carries its own cloud-side bot token, never the production one.** §13.2 asks for a cloud reference probe and §12.2's runbook keeps the production bot logged out of the cloud; §12.5 already places a separate bot there. The separate credential satisfies all three, and an absent key disables the leg rather than degrading it.

  - **The canary runs on its own ticker, not as a scheduler task.** A probe that stops when Postgres stops goes silent exactly during an incident, which is the ambiguity the dual-leg design exists to remove.
  - **Each leg gets its own client, its own limiter and one attempt.** A retrying canary measures the retry loop rather than the network, and a shared client would let a probe draw on the production budget and mix into the transport series.

  - **A scoping measurement that searches a proxy is not a measurement of the class.** The repository-root consolidation was scoped three times: first by identifier, then by `runtime.Caller`, each time asserted complete and each time missing members. The durable form is to define the class by mechanism — a helper that ascends from its own source file's location is in, one that asks git is out — and the acceptance criterion now says so, which is what makes the guard's "and no other file" clause provable.

Every discriminating proof runs over a temporary copy, because a proof that mutates the working tree leaves it dirty and the coverage ratchet blocks on that before any assertion is reached.

Without it a swap inside the prober would have passed every test in the package.

## `cmd/bot` composition root — wiring, the migration policy, graceful shutdown (PR #75, 2026-09-10)

- **What landed:** `cmd/bot` stopped being a scaffold. `assemble` builds every subsystem in one place from the validated configuration and appends an ordered closer as each step takes something that has to be given back; `serve` waits on the registered signal channel or the first runner return and hands off to `drain`; a `migrate` subcommand applies pending migrations under the production lock and constructs nothing else. `internal/store` gained the liveness migration, `MigrateOption`/`WithAdvisoryLock`, `ProcessLockID` and `HasPendingMigrations`; `internal/scheduler` gained `Liveness` (the restart-hygiene shift) and `(*Worker).Stop`; `internal/ingest` gained `(*Loop).Stop` and the two-context `PollOnce` split; `internal/health` gained `ReadyFunc`, `ServerOptions`, the readiness path beside the metrics path, and the process-identity collector; `internal/srcguard` holds the source-walk guard support the hand-rolled copies folded into; `internal/testdb` gained `SchemaDSN`. `cmd/importguard` plus its gate turns the container-runtime import invariant from prose into something that fails. `ai-docs/process-lifecycle.md` carries the start-up order with a failure mode per step, and the migration policy in full.

- **Decisions worth keeping:**
  - **Migrations apply at start-up by default, with an opt-out key, and both paths take the same database-held advisory lock.** The instance that loses the race waits and then finds nothing pending — it does not fail. With auto-apply off and a migration still pending the process refuses to start rather than serving against a schema it was not built for, which is also what lets one readiness definition hold in both modes.
  - **The lock is opt-in with a caller-supplied id.** It is database-wide while this module's test isolation is schema-wide, so a lock in the default apply path would serialise every fixture in every binary behind one id on the shared test server.
  - **Signal registration is start-up step 1**, ahead of the listener bind, so no observable readiness can precede it. Assembly itself is deliberately not interruptible: the rollback already gives what a cancel would, and a hung start-up is the supervisor's to bound.
  - **Stopping is a second lever, never a context cancel.** Cancelling the context stops the cycle *and* aborts the work inside it, which is the opposite of a drain. The ingest stop cancels the long-poll call alone; the offset read and every update already fetched keep the parent context and run to completion.
  - **A stop-discarded poll reports an observation with no error field set**, because the health adapter counts poll errors on exactly that field — the naive shape mints a spurious poll error on every clean shutdown.
  - **One ordered closer list is walked backwards by both the start-up unwind and the drain**, so the two orders cannot drift apart; the start-up table's unwind column is a consequence of the list rather than a second copy of it.
  - **The heartbeat tolerates a failed refresh, but not forever** — it returns once the stored instant would have aged past the downtime threshold, counted over its own ticker so no Go clock enters the path. A heartbeat that died silently would make the *next* start read a stale instant and shift every overdue row by the whole gap.
  - **Both instants in the downtime measurement come from the database**, and the shift's transaction takes the singleton liveness row `FOR UPDATE` first, so two concurrent starts move the rows once rather than twice.

- **Traps found:**
  - **`-ldflags -X` sets a string *variable*, never a constant.** The scaffold declared `version` as a constant with a comment claiming the release pipeline overrode it; the claim could not hold as written.
  - **The migration library applies no lock unless one is configured**, and its session locker holds a single connection for the whole apply — which is what makes a session-level advisory lock work over a pool-backed handle.
  - **The shipped example's placeholder credential fails at the bot token, before the canary ever matters.** Under the all-fatal rule that means exporting the example's variables does not run the bot, which a documented gate line had claimed for as long as the line existed.
  - **An HTTP poll for a transient shutdown state races its own listener's teardown.** The drain closes the health listener, and a clean drain with nothing in flight finishes in tens of milliseconds, so the poll cannot reliably land inside the window.
